# Compile Web —《译世界》网页版

《译世界》(Compile) 是 Jeux Synapses Games 出的桌游。我照着官方规则和卡牌文本，用 TypeScript 写了一个网页版：纯前端、没有后端，可以装到桌面离线玩。

> 个人学习、自用项目。官方规则和卡牌文本版权归 Jeux Synapses Games Inc.（©2024/2025），请勿公开分发或商用。

## 现在能玩到什么

- **热座双人**：完整流程都能跑完。掷硬币定先手，然后按 1-2-2-1 选协议（可以开禁用模式，也可以随机抽 12 套当池子），之后是六步回合：Start / Check Control / Check Compile / Action / Check Cache / End。编译的判定是线值 ≥10 且严格高于对手就必须编译。
- **单视角预览**：用远程对战页的布局（三条横带，上面是对手、下面是自己）本地玩一局。这一页本来是为联机准备的，现在不开联机也能看效果。
- **单人（打 AI）、三人模式**：页面上有入口，点了会提示开发中，还没做。

内容方面：45 套协议、每套 6 张，一共 270 张卡，来自 6 个补充包（MN01 / AX01 / MN02 / AX02 / MN03 / AX03，也就是常说的 1、2、3 代）。卡面中文和官方 Codex 的勘误逐句对过。每套协议都配了特效。

## 档案可以导出，也可以重放

每局都能导出一份档案，里面是这局的种子、开局配置和每一步操作。把档案拿到另一台设备导入，就能把整局一步步重放出来——可以暂停、单步，也可以 1× / 2× / 4× 快放。

导出的是 json，用文本编辑器打开能看到每一步的 kind 和参数。同一份格式后面还要用来做断线重连（重连就是把档案重放一遍）。

入口在「本地数据与隐私」屏：导入成功后会出现「重放这一局」按钮。这次会话还没打过对局时，导出会被拒绝并说明原因，不会给你导一份空档案。

## 关于数据

**没有后端、也没有任何服务器**：这个项目不上传你的对局、没有账号、没有数据库。G5 起联机走的是
**浏览器之间的 WebRTC 直连**（`RTCPeerConnection`，代码在 `src/ui/net-browser.ts`）——两端把连接描述
编码成"邀请码 / 回示码"，**由你自己复制粘贴**给对方（默认没有信令服务器；6 位房间码那条路需要一台，
不配就用邀请码）。

唯一会出网的是 **ICE 候选收集**：默认内置两家公共 STUN（Google、Cloudflare）用来问自己的公网地址；
没有中继（TURN），除非你自己在「连接设置」里填。收集不到时程序会照实说"只收到本机候选"，
不会假装能跨网连。

昵称、设置、卡组这些偏好，只有在首次进入的授权弹窗里点了「允许」之后，才会写进浏览器存储。点「不用」就是游客模式：这些数据只在内存里，刷新或关掉页面就没了。想清掉本机数据，「本地数据与隐私」屏可以一键清。

游客模式下导出和重放照常可用，因为它们只用到内存和你自己选的文件。

## PWA

手写的 Service Worker 加 manifest：可以装到桌面或主屏，断网也能打开，发新版本会在页面上提示并支持一键更新。

预缓存只收程序外壳，实测 11 个文件、1.23 MiB；卡图之类的资源等你用到时才进运行期缓存。

发布要用 `npm run build`。它会在构建后生成 SW 清单和版本戳；`npx vite build` 不会，那样发出去更新提示不会触发。

## 怎么跑

```bash
npm install
npm run dev         # 开发服务器
npm run build       # 类型检查 + 构建 + 生成 SW 清单与版本戳
npm run preview     # 预览构建产物
npm run test        # Vitest，184 个文件 / 2487 项
npm run texts:check # 卡牌文本与官方文本的差异，应为 0 处
```

## 实现上的一些选择

分层是单向的：`core` 是纯引擎，不碰 DOM；`app` 是纯逻辑（档案格式、本地存储、会话层驱动），也不碰浏览器 API；`ui` 负责 DOM 和特效；`main.ts` 只做装配。测试里有守卫钉住这几条。

出牌只有一个入口，就是 `driver.submit`。热座用 `LocalDriver`；重放用 `ReplayDriver`，它只放行档案里的下一条操作，玩家点别的会被拒；以后联机只要再写一个 `NetDriver`。重放没有另写一条捷径，而是把档案里的每一步喂进和现场完全一样的动作编排，所以特效、错误处理和动画时序都是复用的。

引擎是确定性的：随机数由种子驱动并写进状态，任何一步之后都有稳定的状态指纹。同种子加同操作必然同结果，所以录一局再重放能对得上。测试里包含随机对局的模糊测试和录制-重放的往返。

判断「谁盖住谁、能不能点到」这类问题时，测试用 `elementFromPoint` 问真实浏览器，而不是读 `getComputedStyle`——对 `position: static` 的元素，内联 `z-index` 会被浏览器忽略，但 `getComputedStyle` 照样把它读回来。这类判据只能问浏览器。

## 目录

```
src/
  core/     纯引擎：模型、牌库、回合状态机、规则、效果结算、事件总线、状态指纹
  app/      纯逻辑：对局档案、卡牌指纹、本地存储、会话层驱动
  ui/       DOM 渲染与特效（热座页、远程对局页、重放控制条等）
  data/     卡牌与协议数据
  main.ts   装配
tests/      单元测试、确定性测试、行为腿与守卫
tools/      卡牌文本同步、真实浏览器真值自查
docs/       设计稿、各阶段实现计划与收口文档
public/     manifest、手写 Service Worker、图标
```

## 进度

- G0 确定性内核：种子随机进状态、状态指纹、录制-重放
- G1 特效 DOM 契约
- G2 远程对战页
- G3 本地优先：授权弹窗、本地存储、档案格式、PWA
- G4 会话层与档案重放：`MatchDriver` / `LocalDriver` / `ReplayDriver`
- G5 联机：邀请码握手、掷硬币定先后手、草稿选协议两端同步、对局锁步、5 分钟内掉线重连（已落地，见下）
- G6 回合计时、G7 观战、G8 桌面端打包、G9 单人 AI 与三人模式（都还没做；
  **下一步做什么已经有候选菜单**：`docs/2026-09-24-G6-规划草案.md` 按"价值 ÷ 成本"列了 8 条，
  每条都写了现状证据与需要裁决的问题 —— 那只是草案，没点的条目不会开工）

联机（G5）今天能走通的一条路（**只在同一台机器上、用两个浏览器窗口验过**）：
联机对战（两台设备）→ 建房生成邀请码 → 对方粘贴邀请码（整条链接也行）→ 出示回示码 → 房主粘回 →
掷硬币（三段：告知 → 抛硬币 → 结果）→ 草稿选协议（两端真的同步，池子与热座一样是全部 45 套）→
打牌 → 掉线 <4 秒能自动接回、超过就回大厅重新贴码追平。

还有的（**如实说**）：

- 6 位房间码那条路需要一台信令服务器（默认不配，屏上会提示改用邀请码）；
- **联机的"效果选择"已经有真浏览器证据了（2026-09-24）**：同侧应答（打出一张带选择效果的牌 →
  提示只落在操作方那一屏 → 选卡 + 确认 → 两端状态逐字相同）**两个方向都验过**
  （两端指纹 `4b9129bf/4b9129bf`，10059 字符）；"换人应答"（对手来选那一段）走通过一次，
  并且两段卡 `plague-2` 被独立评审用变异副本走通了完整两段（手牌 8→6 / 对手 5→3、
  两端 `applied 12 / pending 0`、指纹 `d1bd7480/d1bd7480`，10098 字符）；
  **整屏重排窗口**（动量4 / 新星2）也验过：窗口只出现在操作方那一屏（对手屏连选择条都没有）、
  交换 + 「完成重排」后两端逐字一致、新星2 的条件窗口带「跳过」、条件不满足时不开窗。
  **还没做到的**：那条一次性夹具自身还有 7 条判据缺陷（正在修，见下一条），
  所以"同一跑里两个场景同时全绿"还没跑出来；它**暂时不能当门禁用**；
- 跨机网络（NAT 打洞、mDNS、丢包、手机切后台）**未验**；没有中继时**不敢说跨网能连**
  （TURN 可在高级设置里自配，但没在真服务器上验过）；
- 触摸与键盘可达性、窄到 600px 以下的视口、图鉴卡图的懒加载**都没验**（交互只验过鼠标）；
- 草稿与对局都没有计时/超时（属 G6）；观战、投降未做。

图鉴（协议与卡牌）可以按**效果分类筛选**（30 类，默认全勾），数据由 `tools/card-effect-index.mjs`
从效果代码生成到 `src/data/cardEffectTags.ts`；分类口径与已知偏差见 `docs/2026-09-21-卡牌效果分类与关键词.md`。
图鉴页在 **≤1100px 的窄窗口下**已经是**单列**（2026-09-24 修，之前这一档列表会被压成 131px、筛选面板一行一个字；
三档真浏览器读数：1280 逐字不变、1100 单列 869px、900 单列 669px）。

各阶段的实现计划和收口文档在 `docs/` 里。最新的收口是 `docs/2026-09-17-G4-进度与上下文.md`，跨阶段的交接摘要在 `docs/3代特效-进度与上下文.md`。
