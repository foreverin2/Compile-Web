### 跳转是怎么配的（避免"certbot 搬走 listen 80"那个坑的正确形态）

主块仍然一个块服务 80 + 443，但 `server_name` 改成 `_`（默认块），另加一个 4 行小块按域名跳转：

```nginx
server {                                   # ← 主块：服务站点，80 与 443 都在这里
    listen 80 default_server;
    listen [::]:80 default_server;
    server_name _;                         # ⚠️ 必须写 `_`，见下
    …站点规则…
    listen 443 ssl http2;                  # ← 443 上加 http2（certbot 那两行）
}

server {                                   # ← 新增：域名走 http 时跳 https
    listen 80;
    listen [::]:80;
    server_name kompile.xyz www.kompile.xyz;
    return 301 https://$host$request_uri;
}
```

为什么主块必须写 `server_name _;`：80 上"默认块服务站点 + 按名字跳转"两块靠**名字匹配**分流；
主块若也写域名，它会先把域名的 80 请求抢走（实测过一次：域名 301、直连 IP 变 404）。

## 1. 缓存头：改了什么、为什么

原来的规则（`/etc/nginx/sites-available/compile`）只有两条：

```nginx
location /        { expires -1; try_files $uri $uri/ /index.html; }   # HTML 每次回源校验
location /assets/ { expires 30d; add_header Cache-Control "public, max-age=2592000, immutable"; }
```

问题在第二条：它对 **整个 `/assets/`** 都加了 `immutable`，可那里**大部分文件的文件名不带哈希**
（卡图 `card-0.png`、字体、界面图、二维码…）。`immutable` 的语义是"**在 max-age 内不要回来问**"
⇒ 哪天我们换了某张图，已经缓存过的玩家在 30 天里**永远不会**看到新图。

改成"按文件名有没有哈希"分开：

| 规则 | 匹配 | Cache-Control（实测） |
| --- | --- | --- |
| HTML / `sw.js` / `sw-manifest.json` / `manifest.webmanifest` | `location /`、`location = /sw.js` | `no-cache`（每次回源校验；配合 ETag/Last-Modified） |
| **哈希产物** | `~ ^/assets/index-[A-Za-z0-9_-]+\.(js\|css)$` | `public, max-age=31536000, immutable`（1 年，名字变内容才变） |
| **其余素材** | `location /assets/` | `public, max-age=2592000`（30 天，**不带 immutable** ⇒ 到期会回来校验） |

另外补了 `gzip_vary on;`（`nginx.conf` 里那条一直是注释状态）：gzip 开着却不发 `Vary: Accept-Encoding`，
一旦前面挂了 **CDN 或公司代理**这种共享缓存，就可能把 gzip 版发给不支持 gzip 的客户端。

**实测（2026-10-09，`curl -D -`）：**

```
http://kompile.xyz/                        → 200  Cache-Control: no-cache
/assets/index-BHp4fF9e.js                  → 200  Cache-Control: public, max-age=31536000, immutable
                                                  Content-Encoding: gzip   Vary: Accept-Encoding
/assets/protocols/water/card-0.png         → 200  Cache-Control: public, max-age=2592000
/sw.js                                     → 200  Cache-Control: no-cache
```

顺带一处**同类清理**：`expires 30d` 与 `add_header Cache-Control` 同时写会让响应里出现**两条**
`Cache-Control`（`expires` 自己也发一条）。现在这两条 `/assets` 规则只用 `add_header`，
所以每个响应只有一条 `Cache-Control`。

| **外部访问 443** | ❌ **被腾讯云安全组挡着** |

### 2.1 "被安全组挡着"是怎么测出来的（不是猜）

- 在服务器上临时起了个监听 443 的进程：`ss -ltn` 能看到 `0.0.0.0:443 LISTEN`；
- 从本机连 `kompile.xyz:80` → **秒连**（对照组，说明测法有效）；
- 从本机连 `kompile.xyz:443` → **超时**（不是"拒绝"）；
- 服务器自身的防火墙**不是**原因：`ufw status` = inactive，`iptables -S` 里默认策略全是 `ACCEPT`
  且没有 80/443 的拦截规则。

⇒ 结论：**腾讯云控制台 → 该实例 → 安全组 → 入站规则 → 放行 TCP:443**（源 `0.0.0.0/0`）。
放行后立刻可用，不需要再改服务器。

### 2.2 一个必须记住的坑：certbot 会把 `listen 80` 搬走

`certbot --nginx` 在生成"80 → 443 跳转块"时，会把原来那一块的 `listen 80 default_server;`
**搬进它新建的跳转块**。于是：

1. 跳转块生效后，`http://kompile.xyz/` 变成 **301 → https://…**，而 443 又被安全组挡着
   ⇒ **站点对所有人打不开**（实测踩到：域名 301、直接访问 IP 变 404）；
2. 我们把那个跳转块删掉（安全组还没放行，不能跳），结果 **80 端口整个消失**（`ss -ltn` 里
   只剩 443）—— 因为 `listen 80` 被搬走之后没搬回来。

修法：把这两行**放回主 server 块**，80 与 443 由同一块服务、**先不强制跳转**：

```nginx
listen 80 default_server;
listen [::]:80 default_server;
```

⇒ **安全组放行 443、并且从外部确认 `https://kompile.xyz/` 真的 200 之后**，再谈跳转。

## 3. 放行 443 之后要做的事（照这个顺序）

1. 你的操作：控制台放行入站 **TCP:443**；
2. 我复验：`curl -I https://kompile.xyz/` 与 `https://www.kompile.xyz/` 都要 200、
   证书链正常、`http` 仍然 200；
3. 然后（**只有此时**）再把 80 跳 443 打开。正确形态是**两块**：
   ```nginx
   server { listen 443 ssl; server_name kompile.xyz www.kompile.xyz; …站点… }
   server { listen 80 default_server; server_name _; …站点… }          # 直连 IP 仍走 http
   server { listen 80; server_name kompile.xyz www.kompile.xyz;
            return 301 https://$host$request_uri; }                      # 域名跳 https
   ```
   （注意第一块**不能**再带 `default_server`，否则它会把 80 的域名请求抢走、跳转不生效。）
4. 顺手可做：`probe.html` 的读数确认 `secureContext=true`、`serviceWorker=true`、`crypto.subtle=true`
   —— 现在 http 下这三项都是 false，**PWA/离线/加密在 http 下根本不生效**（见
   `docs/2026-10-07-HTTPS升级后的缓存与加载优化.md`）。

**证书续期**：certbot 的定时器已就位（`systemctl list-timers | grep certbot`）。
续期走 ACME（出网 443），实测出网正常：`https://acme-v02.api.letsencrypt.org/directory` → 200，
用时 4.4s。如果哪天续期失败，先跑 `sudo certbot renew --dry-run` 看日志。
（这次签发用了 `--register-unsafely-without-email`，所以**不会**收到到期提醒邮件；
想收的话补一条：`sudo certbot update_account --email 你的邮箱`。）

## 4. CDN 是什么（用户问的）

CDN = 内容分发网络。你现在的形态是"**一台服务器直接面对全世界**"：每个玩家的请求都跑到
湖南那台机器上。CDN 的做法是：把站点里的静态文件（JS/CSS/图片）**预先复制到分布各地的缓存节点**，
玩家就近从节点取，只有节点上没有（或已过期）时，才回到你的服务器（"回源"）。

- **好处**：跨地区/跨国的首屏快很多（尤其中东、欧洲、南美访问大陆机器）；抗流量峰值；
  顺手能把 gzip/brotli、HTTP/2/3 交给 CDN 做。
- **代价**：多一层要配（缓存规则、回源、证书）；国内 CDN **要求域名备案**（已有）；
  免费额度之外要花钱；改了文件要让 CDN 刷新缓存，否则玩家还看旧版。
- **对本项目的现实判断**：卡图 270 张、每张 ~0.9MB，是最值得上 CDN 的部分；但**先别急着上**：
  ① 域名刚备案、HTTPS 还没对外跑通；② 先看 Discord 上的实际反馈——如果海外玩家抱怨慢，
  再上（顺序建议：先 443 → 再看真实访问数据 → 再决定 CDN 或加一台境外小机器）。
- **一条注意**：上了 CDN 之后，本文件第 1 节那套 `Cache-Control` 会被 CDN 按自己的规则处理，
  届时"改了图玩家看不到"的风险会回来 —— 要么给图片路径带内容哈希，要么配 CDN 刷新。

## 6. 当前完整配置（实测版，2026-10-09）

`/etc/nginx/sites-available/compile`（`server_name` 之后的站点规则与反馈/中继反代都保持原样）：

```nginx
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    server_name kompile.xyz www.kompile.xyz;
    root /var/www/compile; index index.html; charset utf-8;

    location / { expires -1; try_files $uri $uri/ /index.html; }
    location ~ ^/assets/index-[A-Za-z0-9_-]+\.(?:js|css)$ {
        add_header Cache-Control "public, max-age=31536000, immutable";
        try_files $uri =404;
    }
    location /assets/ {
        add_header Cache-Control "public, max-age=2592000";
        try_files $uri =404;
    }
    location = /sw.js { add_header Cache-Control "no-cache"; }

    # … /feedback/、/turn-cred、/healthz-* 三条反代与 error_page 一字未动 …

    gzip on; gzip_comp_level 5; gzip_min_length 1024;
    gzip_types text/plain text/css application/javascript application/json application/manifest+json image/svg+xml;
    gzip_vary on;
    add_header X-Compile-Deploy "2026-10-09-cache-headers" always;

    listen [::]:443 ssl http2 ipv6only=on;   # ← 以下 6 行由 certbot 写入（http2 是当天补的）
    listen 443 ssl http2;
    ssl_certificate     /etc/letsencrypt/live/kompile.xyz/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/kompile.xyz/privkey.pem;
    include /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;
}

# ★ 域名走 http 时跳 https（直连 IP 仍走上面那个默认块）。见 §0.5 的说明。
server {
    listen 80;
    listen [::]:80;
    server_name kompile.xyz www.kompile.xyz;
    return 301 https://$host$request_uri;
}
```

⚠️ 主块的 `server_name` 已由 `kompile.xyz www.kompile.xyz;` 改成 `_;`（理由见 §0.5）。

备份：改动前的那一份在服务器 `/root/compile.nginx.bak-20261009`（以及
`bak-before-unredirect`、`bak-before-http2-redirect`）；本地留了快照
（`.superpowers/2026-10-09-cache-tls/`，该目录被 gitignore）。
