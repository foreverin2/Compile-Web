# 新手引导与教学模式 · 方案（2026-10-01）

用户要求的目标流程：

```
选择语言 ──►（提示：之后可在「首页 → 设置」改，只出现一次）
   │
同意保存数据到本地 + 给自己取个名字 ──►（提示：之后可在「首页 → 本地数据与隐私」改，只出现一次）
   │
选择是否开始教学模式（只出现一次）
   ├─ 开始教学 ──► 进入教学模式：从零学基础操作 / 基础规则 / 常见卡牌效果
   └─ 我玩过，直接跳过 ──► 提示「之后还可以在首页再次进入教学模式」
```

## 0. 现状（先摸清，避免与既有实现打架）

| 事实 | 出处 | 对方案的影响 |
|---|---|---|
| **没有任何 i18n**：界面与卡牌文本全是中文；卡牌文本被 `npm run texts:check` 与权威 txt 逐字钉住 | `src/data/cards.ts:11`、`tools/sync-card-texts.mjs`；全仓 `i18n/locale` 只出现在"排序不许依赖 locale"的注释里 | 「选择语言」是**从零加**；**卡牌文本不参与翻译**（翻了两道门禁立刻红）。语言只覆盖 UI 文案 |

## 1. 总体架构：一个"首启向导" + 一个"教学模式"，两者只共享存储与文案

- **首启向导**（`src/ui/onboarding.ts`，新增）：三步的状态机，**只在"本机还没走过"时**在启动后接管屏幕，走完写一个"已完成"标记。
- **教学模式**（`src/tutorial/`，新增）：可反复进入的**关卡式教学**，入口 = 首页「新手教程」按钮；进度单独存，可中断可续。
- 两者都不碰 `src/ui/render.ts` / `render-net.ts` / `styles.css`（红线）。

---

## 2. 第 1 步：选择语言（要做的事与代价）

### 2.1 必须先定的口径（这是本方案最大的一个岔路）

仓库现在**没有** i18n 基建，所以有三种做法，代价差一个数量级：

| 方案 | 内容 | 代价 | 风险 |
|---|---|---|---|
| **A. 只做"语言"这一步 + 只翻译首启与首页周边**（推荐先走这条） | 新增 `src/i18n/`（`lang` 设置 + 文案表），**先覆盖：首启向导、首页菜单、设置小窗、本地数据屏**；其余界面暂时保留中文，文案表按屏逐步补 | 小～中 | 会出现"首页英文、牌桌中文"的混搭期，需要明确告知 |
| B. UI 全量双语 | 把 `src/ui/**` 所有玩家可见文案抽表 | 大（几千条、且按钮文案被大量测试逐字钉住，会牵动几十个测试文件） | 与卡面/提示/日志的既有测试大面积冲突 |
| C. 语言只有中文一项（占位） | 步骤照做、选项里只有「中文」，另列「English（即将支持）」但不可选 | 最小 | 用户会觉得"这步没意义" |

**卡牌文本一律不进文案表**（`texts:check` 与联机卡文哈希都依赖它逐字不变）。若将来真要英文卡面，那是**另一条**产品线（需要官方英文卡文来源 + 哈希口径讨论），不在本方案内。

### 2.2 落点
- 新增设置项 `lang`（存 L1，与现有昵称/设置同一份存储与同一套授权门控）。
- 首页「设置」小窗里加一项**语言**（与"金属6 频闪"并列）。
- 首启选完后弹一句只出现一次的提示：**「之后可以在首页的『设置』里更改语言。」**

## 3. 第 2 步：同意保存 + 取名（合并，只出现一次）

- 复用现有授权弹窗，**扩成一张卡**：
  - 主体：既有的一句"是否允许把数据保存在本机"（文案现成，别改口径 —— `privacy.ts` 那套文案被隐私门禁逐字钉住）；
  - 新增一条输入框：**昵称**（可留空，留空就用缺省显示名）；
  - 两个按钮：**允许并保存** / **不允许，本次会话有效**（口径与现状一致）。
- 选完（无论允许与否）弹一句只出现一次的提示：**「之后可以在首页的『本地数据与隐私』里修改昵称，也能清除本机数据。」**
- 「不允许」时昵称只进内存（既有行为，`local-store` 已支持），如实提示"刷新即丢"。
- **不做**在向导里加"卡组"相关的东西（用户没提，且卡组导入是进阶功能）。

---

## 4. 第 3 步：是否开始教学（只出现一次）

- 一张两选一的卡：
  - **开始教学** → 进教学模式（下面第 5 节）
  - **我玩过，直接跳过** → 弹一句：**「随时可以在首页点『新手教程』再次进入教学模式。」** 然后进首页。
- 无论选哪个都写"向导已完成"标记，**首启向导不再出现**（只出现一次）。
- 想重看向导？给一个隐藏/次级入口（建议：设置小窗里一行「重新观看新手指引」），否则"只出现一次"就是永久不可逆。

## 5. 教学模式的设计（本方案的主体）

### 5.1 形态选择（推荐：**真实引擎 + 脚本化关卡 + 教练浮层**）

- 用**真引擎**（`createGame` + 固定 seed + 注入教学用协议/牌堆）跑一局**受控**对局；
- 教学层做三件事：**限制**（只放行本关要教的动作）、**提示**（讲这一关在教什么、该点哪里）、**验收**（用状态断言判断"做对了没有"）。
- 为什么不播动画/截图：这游戏的规则耦合度高（阈值/覆盖/编译/控制权），假演示会让玩家学到错的东西；而且引擎已经有 `getLegalActions` 可以精确"只放行一个动作"。

**教练浮层的实现方式**（避免红线）：照 `src/ui/hotseat-exit.ts` / `log-toggle.ts` / `feedback-screen.ts` 的既有做法 —— `document.body` 级浮层 + 行内样式 + `MutationObserver` 跟随重画；样式新类名进 `styles-local.css`。**不改 `render.ts` / `render-net.ts` / `styles.css`**。

### 5.2 关卡编排（从零到能玩）

| 关 | 教什么 | 玩家必须做的动作 | 通过判据（状态断言） |
|---|---|---|---|
| T0 | 界面扫盲：链路 / 协议 / 阈值 / 控制权分别在哪 | 依次点高亮的三个区域 | 三个区域都被点过 |
| T1 | 打出第一张牌：拖手牌到链路 | 打出 1 张正面卡 | `stacks[线].length === 1` |
| T2 | 朝向：正面 / 反面各是什么 | 各打出 1 张正、1 张反 | 两张 `faceUp` 分别 true/false |
| T3 | 五个基础动作：翻转 / 偏转 / 抽牌 / 弃牌 / 回手 | 用教学卡各做一次 | 五条状态断言全满足 |
| T4 | 覆盖与揭开：盖住别人的牌会发生什么 | 把牌盖到对手顶卡上 | 被盖卡 `isUncovered === false` |
| T5 | 编译与阈值：为什么这条线算得出 | 完成一次编译 | `protocols[线].compiled === true` |
| T6 | 控制权：怎么拿到、拿到有什么用 | 按提示把控制权拿到手 | `s.control === 自己` |
| T7 | 常见卡牌效果（一）：触发时机（打出后 / 被盖住前 / 结束） | 各触发一次 | 三条触发日志出现 |
| T8 | 常见卡牌效果（二）：删除 / 免疫 / 加成 | 各触发一次 | 对应状态断言 |
| T9 | 完整小局：用 3 条线打一局迷你对局（对手用脚本走固定好棋） | 打到终局 | `s.winner !== null` |

- 每关 = 一个数据对象：`{ id, 标题, 讲解文案（数组，逐句显示）, 允许的动作白名单, 高亮目标, 完成判据, 失败/走偏提示 }`。
- **进度**：`localStore` 里存 `tutorial.progress = { 已完成关卡: [...], 当前关 }`；从首页再进教学时**从上次那一关继续**，并给一个"从头开始"按钮。
- **退出**：任意时刻可退出（教练浮层右上角），退出即保存进度。

### 5.3 内容量估算（要老实说）

- 10 关，每关平均 4~6 句讲解 + 1 条判据 + 2~3 条走偏提示 ⇒ 文案约 120~180 句、判据 10 条、协议/牌堆注入 2~3 套。
- 这是**本方案里最大的一块工作量**，建议**先做 T0~T3 四关**（够"从零到能打出第一张牌"），你验收后再补 T4~T9。

## 6. 存储与隐私（必须一起做，否则隐私门禁会红）

新增的存储键：`lang`、向导各步已读标记（`onboarding.*`）、`tutorial.progress`。
- **每一个都要出现在「本地数据与隐私」屏**（可见 + 可清除），否则 `tests/ui/local-data-screen.test.ts` / `privacy-consumers.test.ts` 会挡。
- 清除本机数据后：语言回默认、向导**重新出现一次**、教学进度清空（这正是想要的）。

## 6.5 用户 2026-10-01 拍板（据此调整下面的顺序与范围）

- **语言：走方案 B（UI 全量双语）** ⇒ i18n 基建必须排在**首启向导之前**（向导第一步就是选语言，它自己得能双语）。
- **教学：先做 T0~T3**（界面扫盲 / 打出第一张牌 / 正反面朝向 / 五个基础动作），验收后再补 T4~T9。
- **不留"重新观看新手指引"入口**：提示过一次就够，之后用户自己去设置里改（语言→设置；昵称→本地数据与隐私）。

### B 档的两条关键设计（否则会撞门禁）

1. **默认语言 = 中文，且中文文案与现状逐字一致** ⇒ 既有那几十个"逐字钉住中文按钮"的测试**零改动**；英文是并行的第二张表。
2. **卡牌文本不进 i18n 文案表**：`cards.ts` 的中文文本是**数据**，被 `npm run texts:check` 与联机卡文哈希钉住。
   ★ **用户 2026-10-01 补充：卡牌图片上的原文本来就是英文**，所以英文模式**不需要任何卡文翻译** ——
   只要**不显示那层中文翻译文本框**即可（卡面照旧显示原图英文）。
   ⇒ P4 从"整副卡文翻译"降级为"英文模式隐藏中文翻译框"：**不需要翻译表、不需要英文来源、不需要动数据**；
   实现上是一处很小的渲染层改动（`src/ui/render.ts` 里那层翻译文本按语言隐藏 ⇒ **红线文件改动，需要用户单独授权**）。
3. **完整性可验证**：文案表要有一条"**每个 zh 键都有 en 对应且非空**"的腿；逐屏抽取过程中维护一份"**尚未抽取的屏**"清单（放在本文档里），每抽完一屏就把该屏从清单划掉 —— 清单只能变短，不能变长（抽完的屏若又出现裸中文字面量，用生成式腿报红）。

## 7. 落地顺序（每阶段结束都跑四条门禁 + 部署 + 真机走一遍）

| 阶段 | 内容 | 可交付 |
|---|---|---|
| **P0** | **i18n 基建**：`src/i18n/`（`zh`/`en` 两张表 + `t()` + 语言设置走既有 L1 存储与授权门控）、设置小窗加语言项、切换后重画当前屏、新存储进隐私屏、表完整性腿 + "尚未抽取的屏"清单 | 能切语言；中文行为与今天逐字一致（既有测试零改动） |
| **P1** | 首启向导三步（全部用 `t()` 写，中英都有）：选择语言 →（提示"之后可在设置改"）→ 同意保存+取名 →（提示"之后可在本地数据与隐私改"）→ 是否教学 →（跳过则提示"首页『新手教程』可再进"）；三步各写"已读"标记；清除本机数据后重新出现一次 | **已完成**（2026-10-01，见 §7.6）：新玩家进来有完整双语引导；教学那步先指向"待开发" |
| **P2** | 教学骨架：教练浮层 + 关卡数据结构 + 进度存取 + 首页「新手教程」入口接上 + **T0~T3 四关** | 从零到能打出第一张牌，可中断续玩 |
| **P3** | 逐屏抽取 UI 文案（首页周边 → 大厅/联机 → 牌桌/选择条/草稿 → 卡牌制作器/反馈/规则/本地数据…），每屏都补 en | UI 全量双语的推进主体 |
| **P4** | 英文模式**隐藏卡牌的中文翻译文本框**（卡面原图本来就是英文，不需要翻译表）—— 一处渲染层小改，动 `src/ui/render.ts`（**红线，需用户授权**） | 英文玩家看到的是卡面原文英文，没有多余的中文框 |
| **P5** | 教学 T4~T9（覆盖 / 编译阈值 / 控制权 / 触发时机 / 删除免疫加成 / 迷你对局） | 完整教学 |

### 7.1 P0 的范围**到底**抽了哪一屏（★ 2026-10-01 真浏览器验收 D4 的更正）

**P0 只抽了「设置小窗」这一屏**（`src/ui/home.ts` 的 `settingsOverlayElement`）。

- 这**不是**"设置小窗 + 本地数据与隐私屏"两屏：`src/ui/local-data.ts` 在 P0 里**一个
  `t(...)` 都没有**，`lang=en` 下那屏的标题、按钮、隐私说明**全是中文**。那个说法不成立，
  已按 D4 更正。
- 该屏在 P0 里唯一的例外是**语言那一行**（`[data-role=lang]` / `lang-state`）：它是**语言功能
  自己的读数**，双语是它自己的需求，所以那一行走 `t()`；其余文案当时仍是裸中文。
- ⇒ 逐屏抽取（P3）时**这一屏仍然要抽**；**它在 2026-10-01 的 C 轮已经抽完了**（见 §7.5，
  清单里那一行已按规矩删掉）。
- 混搭期的如实交代：P0 交付时 `lang=en` 下**只有设置小窗与本地数据屏的语言那一行**是英文，
  其余屏（首页菜单、牌桌、大厅…）全是中文 —— 这是 P0 的既定范围，清单里逐条列着。
  **C 轮之后首页周边也变英文了**（见 §7.5）。

### 7.2 P0 的四条真浏览器验收与修法（★ 2026-10-01）

| 编号 | 现象（真浏览器实测） | 修法 |
|---|---|---|
| **D1** | 「本地数据与隐私」屏：**全新访客**与**刚点完清除**的人都看到「（本机存的不是一个有效值，按默认语言显示）」 | 根因：`readLang()` 把"键不存在"与"值是坏值"都回成 `undefined`，屏上用 `isLang(raw) ? '' : tail` 判 ⇒ 缺键也挂警告。新增 `readLangPresence()`（**四态**），只有"`lang` 字段在、值不是 zh/en（含坏 JSON / 非对象）"才挂那句 |
| **D2** | 切语言时首页背景整片跳：608 张 `.bg-plane` 的顺序哈希 `2714029209→1340731705`、band 的 CSS `currentTime 2850→350`（动画从头） | 选**"让背景节点跨重画保持同一个 DOM 节点与动画连续性"**（**不是**固定种子）。实现：`renderHome` 复用上一帧那一份 `.home-bg`（`takeReusableBg` / `buildHomeBg`），`clearRoot` 不再置空 `liveBgHost`、并把状态记成"已摘下来"。取舍理由写在 `src/ui/home.ts` 那两处注释里。用户 2026-10-01 裁决：接受这个选法，真机读数另派复核 |
| **D3** | `lang=en` 时写盘失败提示夹中文 `（本机存储拒绝写入（隐私模式或配额已满））`；对"值超上限"那句是**错的**（真因被丢）；`settings.lang.save-failed` 是**不可达的死键** | `writeLang` 回**结构化** `WriteResult` 而不是布尔：`too-large` 给 `{ bytes, limit }` **两个数**，`write-failed` 给系统原样消息。**纯层不再拼任何玩家可见句子** —— 整句由 `saveFailedText()`（`src/i18n/index.ts`）按语言拼，`70,023 字节 > 上限 65,536 字节` / `70,023 bytes > the 65,536-byte limit`。"结果 → 回话"的映射收成 `applyWriteResult()` + `langChangeThrew()`（住在 `src/ui/home.ts`，**能在 node 下真跑**；内联在 `main.ts` 里那一面零覆盖，变异实测过）。那条死键删掉。用户 2026-10-01 追加裁决：**英文界面里不许出现汉字**（含技术细节），所以诊断也走结构化 |
| **D4** | 7.1 那条范围更正 | 语言那一行走 `t()`（中英都有）；方案与清单都写明"P0 只抽了设置小窗" |

### 7.3 「本地数据与隐私」屏语言那一行的**四态**（★ 2026-10-01 用户裁决的最终口径）

| 存储里的样子 | 屏上 |
|---|---|
| 键不存在（全新访客 / 刚点完清除） | `界面语言：中文` |
| 键在、但**没有 `lang` 字段**（只存过昵称 `{"nick":"甲"}`） | `界面语言：中文`（**不许**说"不是一个有效值" —— 本机从来没存过语言） |
| 键在、`lang` 是 `zh` / `en` | `界面语言：中文` / `界面语言：English` |
| 键在、`lang` 不是 `zh`/`en`，**或**整份 JSON 坏了 / 不是对象 | 默认语言 + `（本机存的不是一个有效值，按默认语言显示）` |
