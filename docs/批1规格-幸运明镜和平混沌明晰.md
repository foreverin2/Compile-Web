### 0.2 槽位与触发注册对照（《手册》§1.4/§5）

- 分值卡每张三槽 top/middle/bottom，`cards2.ts` 中未写字段 = 空（无该指令）。
- **中部指令 middle**：卡正面打出落地（或未覆盖翻正/揭开）时 pushMiddle 入栈结算；源卡被覆盖后中指令不再触发。
- **顶部指令 top**：常驻生效（正面即 active，含被盖——FAQ 行 98-99「只要卡牌处于正面朝上状态,顶部指令文本就处于场上」）。回合开始/结束类 → `triggers.start/end` 注册 `top:true`；数值类 → `valueModifier`。
- **底部指令 bottom**：仅当本卡为所在堆叠**未覆盖顶卡**且正面时生效（规则 79 行；1代 先例 psychic-1 底/psychic-4 底/fire-3 底在 `collectTriggers` 中被盖跳过）。
- end/start 只收集**回合玩家**场地侧（triggers.ts:70）；即时连锁 after-* 只 push 不 runStack（triggers.ts:8-9）。

### 0.4 FAQ「主规则 2」本批相关裁定（FAQ 文本行 174-199；DeepL 机翻）

- **混沌0**（行 176-179）：中间指令勘误 =「翻开每行中的一张盖牌」；持有者需标记需执行的每一行，**依次**选择要处理的行；每行选一张面朝下的卡牌翻开，处理其后果后再处理下一行；**面朝下的卡牌在翻开时绝不会激活其中间指令**（注：引擎对被盖卡翻正本就不连锁中指令——resolve.ts:224，FAQ 行 127）。
- **混沌1**（行 181-182）：**你必须对双方玩家的协议进行修改**（自己与对手都要重排）。
- **运气0**（行 188-189）：打出的卡牌**必须是**你通过运气0抽到的那张；可正面朝上或背面朝下打出。
- **运气1**（行 190-193）：勘误 =「将牌库顶部的卡牌面朝下打出。翻开该卡牌，**忽略其中间指令**。」说明：中间指令**仅在翻牌时被忽略**（其它时机正常）。
- **运气3**（行 195-197）：勘误 =「宣布一项协议。弃掉对手牌库顶的一张牌。若弃掉的牌符合所宣布的协议，则移除…」——**原文在「则移除」处截断**（txt 文件即截断），见 [Q4]。

## 1. 幸运 luck（关键词：随机、删除、打出；txt 行 6-13）

幸运5 模板（5 分卡惯例「你弃置1张牌」，全 15 套 2代 共用同一模式，与 1代 弃1 完全同构）：
`registerCardEffects('luck-5', { middle })`：select 自己手牌 1 张（空→fizzle）→ discard。参照 fire-5（fire.ts:61-66）。

### luck-0（分值 0 · 中指令）

- **卡文**（cards2.ts:82 / txt 行 8）：`宣告1个数字。抽取3张牌。从中揭示1张阈值与你宣告数字相同的牌，你可以打出它。`
- **槽位**：middle。
- **逐句拆解**：
  1. 宣告1个数字 → 公开声明（多张命中时的揭示取舍见 [Q1]）。数字域建议 0–6（全池印刷值域；[默认]）。
  2. 抽取3张牌 → `draw 3`（一次性，FAQ 行 94；触发对手侧 after-draw 连锁）。
  3. 从中揭示1张阈值==宣告数字的牌 → 「从中」限定为**本效果抽到的 3 张**；候选 = 抽入手中且 `getCardDef(defId).value === 宣告数字` 的卡（手牌=公开给持有者，引擎可过滤）；无匹配 → 该句 fizzle（空候选自动跳过，FAQ 行 39 不碍及后句——本句即末句）。
  4. 你可以打出它 → 打出**被揭示的那张**（FAQ 运气0：必须是你抽到的那张，可正/反面；落线规则与朝向 → [Q2]）。

- **1代参照**：speed-0 效果内打出（speed.ts:12-42，select-action 正反 + isPlayableFaceUp 选线）；love-4 reveal 手牌句（love.ts:59-69）；fire-5 弃1。
- **实现方案**：
  ```
  middle luck0:
    declare = yield select-action actions ['action:num:0'..'action:num:6']（宣告 UI）
    n = 解析数字
    before = Set(自己手牌 uid 快照)
    yield draw 3
    matching = 当前手牌中 uid ∉ before 且 getCardDef().value===n 的卡
              // 注：抽牌连锁可能同时改动手牌构成（罕见），以结算后实际手牌 ∩ 原手牌差集为近似；如需严格「仅本效果抽的3张」需引擎把 draw 结果回传给生成器（非本批阻塞）
    pick = yield select candidates=matching（min1 max1 optional false；空→引擎自动 fizzle）
    uid = pick.selected[0]
    yield reveal(uid)                       // 公开：对手获得幽灵副本（Case A）
    act = yield select-action ['action:face-up','action:face-down']（可选：'action:skip' 亦需提供 → optional:true）
    if face-up: 行 = select-line lines=isPlayableFaceUp 过滤;  else 行 = select-line lines=[0,1,2]
    yield playFromHand(uid, 行, faceUp)
  ```
- **引擎新能力**：无（宣告用 select-action 编码即可，见《手册》§12 ✅；若后续要「骰子/宣告动画」可再加 ChoiceRequest kind，批1 不阻塞）。
- **交互/呈现**：宣告数字按钮面板（0–6）；抽 3 动画（card:drawn 已有）；揭示幽灵（card:revealed，luck 无专属 fx——需在 UI/effects 按 protocol 命名空间加，另排期）；正/反二选一面板；落线高亮。

### luck-1（分值 1 · 中指令）

- **卡文**（cards2.ts:83 / txt 行 9）：`从牌库顶端反面打出1张牌。翻转那张牌，无视中央效果。`
- **槽位**：middle。
- **逐句拆解**：
  1. 从牌库顶端反面打出1张牌 → `playTopDeck faceUp:false`（自己牌库；落地前不可窥视 FAQ 行 100-101；目标线选择？文本未指定 → 需选线（反面任意线）。**注意**：打出到已有顶卡的线会先结算目标顶卡 before-covered（如 1代 顶卡连锁），属正常引擎语义）。
  2. 翻转那张牌，无视中央效果 → 翻开刚打出的卡（翻正后 secret 解禁、公开），**不连锁其中部指令**（FAQ 运气1 勘误：仅在翻牌时忽略；即只豁免这次 flip 的 pushMiddle，翻正后其余文本照常）。→ **引擎缺口 G2**（flip op 目前对未覆盖翻正必 pushMiddle，resolve.ts:224）。
  3. 落线与翻牌的衔接：若落点原无顶卡（空堆叠/单卡堆）直接翻；FAQ 行 47-49 的「已提交卡」保护由引擎 pendingPlay 机制承担。
- **1代参照**：life-0/water-1 playTopDeck（life.ts:10-21/water.ts:16-22）；flip 连锁缺口无 1代 先例（G2）。
- **实现方案**：
  ```
  middle luck1:
    if !deckTopAvailable(自己) return                    // FAQ 行 142/107：牌库空不洗弃牌堆直接 fizzle
    线 = yield select-line [0,1,2]（反面任意线；守卫空应答）
    topUid = 自己 deck 末位 uid（预读）
    yield playTopDeck(线, faceUp:false)
    yield flip(topUid, noMiddle:true)                    // G2
  ```
- **引擎新能力**：**G2 flip 免中指令**——`Op.flip` 增可选 `noMiddle?: boolean`（resolve.ts flip 分支：`if (card.faceUp && isUncovered(s,card)) pushMiddle` 前判 `!op.noMiddle`）；事件/连锁不变。
- **交互/呈现**：playTopDeck 出牌动画（card:deck-played）；随后自动翻开该卡（flip 事件 + 中指令豁免提示）；若该卡为 1代/其它 2代 协议卡，翻开后其顶/底文本即时激活（restrictions/收集自然生效）。

### luck-2（分值 2 · 中指令）

- **卡文**（cards2.ts:84 / txt 行 10）：`弃置你牌库顶端的牌，抽取与其阈值相同的牌。`
- **槽位**：middle。
- **逐句拆解**：
  1. 弃置你牌库顶端的牌 → 自己牌库顶弹出 → 自己弃牌堆（正面公开）。牌库空 → 该句不生效（FAQ 行 107，不洗弃牌堆）。属「弃牌」→ 触发弃牌连锁（FAQ 行 102-103；对手侧 after-discard = plague-1 方向）。→ **G1 discardDeckTop op**。
  2. 抽取与其阈值相同的牌 → N = 被弃卡**印刷值**（弃后公开在弃牌堆；口径同 光0 裁定「在弃牌堆当前值=牌面值」FAQ 行 145）；`draw N`（N=0 → 无效果；抽牌路径可自动洗弃牌堆重组，deck.ts:14-42）。
- **1代参照**：draw（所有文件）；无「弃牌库顶」先例（G1）。
- **实现方案**：
  ```
  middle luck2:
    if !deckTopAvailable(自己) return
    topUid = 预读自己 deck 末位 uid
    yield discardDeckTop(player=自己)          // G1
    card = findCard(topUid)                   // 现在 trash 正面
    yield draw(getCardDef(card.defId).value)
  ```
- **引擎新能力**：**G1 discardDeckTop**（形状与语义见 §7；与 luck-4/clarity-1 top 共用）。
- **交互/呈现**：弃牌库顶动画（card:discarded，triggerProtocol=luck）+ 抽 N 动画。

### luck-3（分值 3 · 中指令）

- **卡文**（cards2.ts:85 / txt 行 11）：`宣告1个协议。从对手牌库顶端弃置1张牌，若此牌与宣告协议相同，删除1张牌。`
- **槽位**：middle。
- **逐句拆解**：
  1. 宣告1个协议 → 公开声明一个协议（可选范围 → [Q3]；建议全 30 套 defId 池）。
  2. 从对手牌库顶端弃置1张牌 → 对手牌库顶 → **对手**弃牌堆（正面公开，谁都能看到匹配与否）。对手牌库空 → 该句不生效（FAQ 行 107）。→ G1（player=对手）。
  3. 若此牌与宣告协议相同，删除1张牌 → 条件成立（`getCardDef(被弃卡).protocol === 宣告协议`）才删；删除对象范围 → [Q4]（FAQ 运气3 勘误原文截断，需要用户补全/确认）。
- **1代参照**：psychic-0 对手弃（chooser=opp 不适用——本卡无选择只固定牌库顶）、hate-0 delete 1（hate.ts:15-20）。
- **实现方案**：
  ```
  middle luck3:
    decl = yield select-action ['action:proto:<defId>' × 30]（宣告 UI；守卫）
    proto = 解析
    oppDeckTop 预读 uid（需 opp deck 非空，否则 return）
    yield discardDeckTop(player=opp)           // G1
    if getCardDef(findCard(topUid)).protocol !== proto: return
    t = yield select candidates=candidates({zone:'field'})  // 双方未覆盖顶卡（[Q4] A 推荐）
    if t.selected: yield delete(t.selected[0])
  ```
- **引擎新能力**：G1（player 参数支持对手）。

## 4. 混乱 chaos（关键词：抽取、重新排列协议、被覆盖；txt 行 33-40；FAQ 作「混沌」）

### chaos-0（分值 0 · 中部 + 底部指令）

- **卡文**（cards2.ts:107 / txt 行 35）：中部 `在每条链路中，各翻转1张被覆盖的牌。`；底部 `回合结束：你从对手的牌库中抽取1张牌。对手从你的牌库中抽取1张牌。`
- **槽位**：middle + `triggers.end`（bottom，不注册 top）。
- **中指令逐句拆解**（FAQ 混沌0 行 176-179：标记每行 → 依次处理 → 每行翻一张面朝下被盖牌，处理后果后再下一行）：
  1. 在每条链路中，各翻转1张被覆盖的牌 → 目标卡 = 被覆盖且**反面**的牌（→ [Q13]；FAQ 勘误「翻开每行中的一张盖牌」+「面朝下的卡牌在翻开时」措辞）；范围 = 全战场 3 条线（每线含双方堆叠，默认规则可及双方——FAQ 行 52）。
  2. 处理流程（FAQ）：触发时**先标记**所有含可翻目标的线（快照行集合）→ 拥有者**依次**选一行 → 该行（此时）选一张被盖反面卡翻正（`flip allowCovered`；被盖翻正不连锁中指令 FAQ 行 127 → 引擎已保证）→ 处理连锁后果 → 下一行。某行目标已被连锁翻走 → 跳过（FAQ 行 179「处理该翻开动作带来的后果」后再处理下一行的精神）。
- **底部指令拆解**：end 触发（bottom）：`你从对手的牌库中抽取1张牌` = `draw fromOpponentDeck`（对手库空先洗其弃牌堆、双空 fizzle——love-1 模式）；`对手从你的牌库中抽取1张牌` = `draw 1 player:对手 fromOpponentDeck`（以对手为 target：从你的牌库抽、洗你的弃牌堆；love-6 的 player:opp 模式 + fromOpponentDeck 组合——**检查引擎**：draw op 的 `fromOpponentDeck` 配合 `player: 对手` 时取「对手的对手」= 自己牌库 → 语义正确，见 resolve.ts:175-196）。两句顺序：先自己后对手（字面顺序）；各自独立（FAQ 行 39）。
- **1代参照**：death-0 选行序（death.ts:9-21）；darkness-2 翻被盖（darkness.ts:37-41）；love-1 fromOpponentDeck（love.ts:8-13）；love-6 对手抽（love.ts:80-83）。
- **实现方案**：
  ```
  middle chaos0:
    // 快照可翻行：含 ≥1 张「被盖且反面」卡的行
    rows = [0,1,2].filter(行 l: 双方 stacks[l] 中 pos<顶 且 !faceUp 的卡数 >0)
    while rows.length:
      l = yield select-line rows（min1 max1）
      if 空应答: break
      移除 l 出 rows
      cand = 该线双方堆叠中被盖且反面卡（当前时点）
      c = yield select cand（min1 max1；空 → 跳过此行继续）   // 行已被连锁清空防御
      if c.selected: yield flip(c.uid, allowCovered:true)
  end chaos0 (bottom):
    if 对手 deck+trash 非空: yield draw(1, fromOpponentDeck:true)
    if 自己 deck+trash 非空: yield draw(1, player:对手, fromOpponentDeck:true)
  ```

### 各套一句话新能力小结（裁决问题清单另见 B 文档）

- **幸运**：弃牌库顶 op（G1）+ flip 免中指令（G2）；宣告用 select-action 编码即可。
- **明镜**：整堆交换 op（G3）+ 复制中央效果 op（G4）+「对手抽牌→你抽」反向反应与底命令覆盖敏感（G5）。
- **和平**：「你弃牌（对手回合）→你抽」自身侧反应与底命令覆盖敏感（G5）；全员弃手牌现成 op。
- **混乱**：chaos-3 无视协议任意线正面打放的按卡放行（G6）；chaos-1 按裁决或需任意重排 op（G7）。
- **明晰**：整副/库顶揭示双方可见呈现（G8a）+ 从牌库任意位抽指定值卡 op（G8b）(+可选洗牌事件 G8c)。
