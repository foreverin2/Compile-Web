> 这样子的方案是否就能解决第二对玩家直接连不上的问题？

**要解决的两件事**：① 中继凭据公开（`turn:` 的用户名密码打在前端 JS 里）⇒ 陌生人能白嫖中继；
② 以后可能要多人模式 / 账号体系（战绩、好友等）。

## 1. 结论：**纯本地身份解决不了**（三条，都是可复核的事实）

1. **coturn 不认本地自建的用户名。** 现在的配置是 `lt-cred-mech` + `user=compile:…`（长期凭据），
   coturn 拿请求里的用户名/密码去**它自己的用户库**核对。要让"每人一个身份"，就得在该服务器上有
   用户库（注册/改密/找回/注销）⇒ 那是后端 + 账号运维，与"零后端"原则直接冲突。
2. **绕开用户库的那条路（TURN REST）会把配额一起废掉。** TURN REST 的语义是
   用户名 = `时间戳:随便什么`、密码 = `HMAC(共享密钥, 用户名)`，coturn 用密钥验签。
   密钥一旦打进前端（我们没有别的下发途径）⇒ **任何人都能签出任意多个不同用户名**，
   `user-quota`（按用户名的配额）当场失效；正常玩家也不会因此被约束。⇒ **没有权威签发方，
   按用户名的配额必然是假的。**
3. **本地身份没有权威可校验。** "首次进入填用户名密码、存本地、以后自动读"这套，
   恶意客户端可以整份伪造（更省事：直接用公开的中继凭据自己发请求）。所以"登录才能联机、
   游客只能单人/热座"**只挡老实人**，还附带隐私与合规负担（存密码、找回、注销）与"换设备就丢"。

**顺带纠正一条口径**：coturn 的配额只有 `user-quota`（**按用户名**）与 `total-quota`（全局），
**没有 per-IP 配额**（`turnserver --help` 实测）。所以"同一个 IP 最多 2 个会话"这个诉求在 coturn 里
无法直接表达；就算能，2 也太小：① 同一个家里的 Wi-Fi 两台设备（我们自己的真机测试就是这种）就要占满；
② 重连时新旧分配会叠加（压测实测：强杀客户端后分配最长残留 1 小时）；③ 一个人多开。真要按 IP 限，
起步值应该是 6。

## 2. 以后真要做，只有两条路（推荐 B）

### A. 服务器上建用户库（重）
- 内容：注册/登录/改密/找回/注销 + 每个用户一组 TURN 凭据（或签发）+ 战绩/好友。
- 代价：一个真正的后端服务、数据库、账号安全与合规（未成年人、隐私政策、注销权）。
- 好处：能承载真正的产品功能（段位、战绩、好友、举报）。

### B. TURN REST + 一个极小的签发服务（推荐先走这条）
- **coturn 侧**：改用 `use-auth-secret` + `static-auth-secret=<随机长串>`（把现在的
  `user=compile:…` 去掉）。之后凭据是"有时效的"：用户名 `{expiryUnix}:{playerId}`，密码
  `base64(HMAC-SHA1(secret, username))`。
- **签发服务**（几行到几十行，跑在同一台 ECS 上，走 HTTPS 子域）：客户端拿它换凭据；
  服务端在签发处做限流（按 IP、按设备指纹、按账号），并可以随时收紧/封禁。
  这一步才是"有身份、可限流、可封禁"的正解。
- **客户端改动**：`src/ui/net-browser.ts` 的 `readIceServers()` 改为"启动时向签发服务取一次凭据、
  过期前续一次"；拿不到凭据时**降级为直连**（不阻塞单人/热座/同网直连）。
- **隐私文案**：`src/app/privacy.ts` 要加一句"联机时会把凭据请求发到我们自己的服务器"（现有文案只谈了中继）。
- **游客策略**（用户提议）：未登录 ⇒ 只允许单人 / 本地热座；远程联机要求登录。
  ⚠️ 这条**只有在 B（或 A）落地后才真正可执行**；纯前端实现等于没拦。

## 3. 现在用什么顶着（2026-09-28 已上线）

三根保险丝（`/etc/turnserver.conf`，改完重启 coturn）：

| 项 | 值 | 作用 |
|---|---|---|
| `total-quota` | 48 | 全局最多 48 条中继分配（与 49 个端口同量级）；超限干净拒绝并留日志 |
| `max-bps` | 65536（**字节**/秒 = 512 kbps） | 单会话带宽上限，挡"拿中继刷流量" |
| `bps-capacity` | 1250000（**字节**/秒 = 10 Mbps） | 全站中继总带宽上限 ⇒ 最坏白嫖成本约 **3.6 元/小时**（按 0.8 元/GB） |

实测容量与失败签名（`.superpowers/g6-T47/T47-REPORT.md`）：**上限 49 条并发中继分配 = 24 场跨网对局**，
端口先耗尽；客户端 `icecandidateerror code=508`、服务端 `no available ports`。
一局成本量级：单条分配约 12-13 KB 出方向 ⇒ **基本是 0**。

## 4. 什么时候该把它从"记录"变成"做"

任一条成立就该动：① 发现中继被陌生人占用（端口被占满 / 流量异常）；② 要上多人模式（>2 人）；
③ 要做战绩/好友/段位这类需要身份的功能；④ 要按人封禁（现在只能整体换密码）。
**触发时优先走 B**：先落"签发服务 + coturn REST"，再谈 A 的账号库。
