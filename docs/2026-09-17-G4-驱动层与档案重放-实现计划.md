## 0. 一页速览

- **本阶段交付四件事**：
  1. `src/app/match-replay.ts`（纯）：**按档案的草稿序列真重放草稿** + 「一条档案操作 → 一次引擎调用」的唯一收口助手；
  2. `src/app/match-driver.ts`（纯）：`MatchDriver` 契约 + `LocalDriver`（执行 + 记录）+ `ReplayDriver`（只读、暂停/单步/倍速、**定时器靠注入**）；
  3. `src/ui/replay-bar.ts` + `src/ui/styles-replay.css`（新屏新样式文件）：重放控制条；
  4. `src/main.ts` 的 **`cb` + `rerender` 收口**（**单独一个提交**，G3 计划 `:3229` 已经把这个范围留给 G4）+ 档案导入导出**变成真的**（导入 → 能重放；导出 → 含真实操作序列）。
- **一句实话**：G3 的"导出"导出的是一份 `actions: []` 的**本机数据快照**，玩家看不到对局重演。G4 之后这两件事都变：导出的是**真对局档案**，导入后可以直接重放。**G4 会改掉若干玩家可见文案**，那些文案的腿必须同轮 retarget（见 Task 5/6）。
- **本阶段最大的技术风险不是 driver，是 `main.ts`**：`cb`（约 `:208-373`）与 `rerender`（约 `:124-147`）被 **至少 5 条既有文本腿**钉着（含两条"证明 G3 没动过它们"的腿），收口必然让它们变红 ⇒ 这些腿的 retarget 属于 Task 4 的"定义完成"，不是收尾杂活。
- **本阶段第二个风险是草稿**：现有"重放"测试（`tests/app/match-recorder.test.ts:241-273`）**没有消费档案里的草稿序列** —— 它用硬编码策略 `getDraftPool(s)[0]` 重新选一遍草稿。它证明的是"同一套选牌策略能算出同一结果"，**不是**"档案能重放"。G4 必须把这个洞补上（Task 1），否则"档案可重放"是一句空话。
- **三个已被侦察推翻/修正的初始设想**（写在这里，免得实现者按直觉走回头路）：
  1. ~~"重放驱动直接调 `executeAction` 最省事"~~ ⇒ **不行**。`cb.onAction` 里的抽牌/揭示累加器（`pendingDraws:77` / `pendingReveals:80`）**只在编排内部排空**（`:336-339`）；绕过编排就调 `executeAction` 会把它们**灌满且永不排空**，泄漏进下一次真实行动。⇒ 重放**必须复用同一条编排**（裁决 D3）。
  2. ~~"倍速就是少播特效"~~ ⇒ **做不到**。全仓**没有任何全局 FX 开关**（`fxEnabled|suppressFx|...` 零命中），加一个要改 `effects/index.ts` 等**红线文件**。⇒ 倍速只缩短**步间隔**，不吞特效（裁决 D10）。
  3. ~~"边打边重放不影响"~~ ⇒ 自动推进（`runAutoAdvance:803-830`，`onRendered:209-213` 起 400ms 后 `advance`）会**替重放多走一步**，而档案里 `advance` 是**显式记录**的（`match-file.ts:178-187`）⇒ 两套时钟打架、重放与档案分叉。⇒ 重放期间必须关掉（裁决 D8）。
- **四道门禁**（每任务收尾）：`npx tsc --noEmit` 0 错 / `npx vitest run` 全绿（**只增不减**，G3 基线 **142 文件 1760 项**）/ `npx vite build` ✓ / `npm run texts:check` 卡牌 0 + 协议 0。
- **第五道门禁**：`node tools/browser-truth-check.mjs`（G4 动了 `rerender` 与页面路由 ⇒ **必跑**）。它现有 3 个场景（热座 / 远程 `viewSeat=0,1`）**不含重放页**；**已核对**：加第 4 场景只需改 `tools/browser-truth-probe.js` 里的一个分支（它不经 `src/`，见 §3.6）⇒ T6 把它补上，让新屏有浏览器级真值。

## 2. Global Constraints

> 每条都是**硬约束**；任一任务违反即视为未完成。与 G3 计划同名条款保持一致，**新增条款以 ⚑ 标出**。

- **零运行时依赖**：不得新增任何 npm 包；`package.json` 的 `dependencies` 必须保持**不存在**。**禁止 `npm install`**（含 `npm i -D`）。devDeps 只允许 `typescript` / `vite` / `vitest`（现状见 `package.json:14-18`）。
- **需要新依赖时必须给零依赖替代方案**：G4 需要的一切（定时器、DOM 节点、档案文件）都能用**注入**解决，替代方案已写死在任务里。
- **无后端、不存储任何数据**：G4 **不写任何网络请求代码**（`fetch`/`XMLHttpRequest`/`WebSocket`/`RTCPeerConnection` 在 `src/app` 内零命中，`tests/app-purity.test.ts:104-106` 有常驻守卫）。
- **只在用户同意的前提下把数据留在本地**：
  - G4 **不新增任何存储写入点**。重放所需的一切都来自**内存**（记录器是内存数组，`match-file.ts:519-521` 的注已明写"游客模式下这就是唯一的档案载体"）。
  - **游客模式（拒绝授权）下重放与导出必须照常可用** —— 它们零写入：档案从内存来、文件由用户自己选。
- **测试环境是 `node`，没有 jsdom**（`vite.config.ts`）：不得引入 jsdom / happy-dom / playwright / puppeteer。UI 行为靠 `tests/ui/net-dom-stub.ts`，纯文本判据靠 `tests/ui/source-text.ts`。
- ⚑ **定时器必须注入**（G4 新约束）：`ReplayDriver` 的"该走下一步了"由注入的 `Ticker` 触发（接口见 Task 2），**不得**在 `src/app` 内直接 `setTimeout`/`setInterval`/`requestAnimationFrame`（`requestAnimationFrame` 已被 `tests/app-purity.test.ts:109` 禁；`setTimeout` 现在没被禁，但**不许**用它绕开注入）。
- ⚑ **档案不落盘**（D13）：G4 **不把 `MatchFile` / 对局记录写进任何浏览器存储**（`localStorage`/`indexedDB`/SW 缓存都不行）。档案只在**内存**与**用户自己选的文件**里。⇒ `src/app/privacy.ts` 与 `local-data.ts` 的现有存储类承诺句**一句都不改**（它们被整句哈希钉死）。

- **守卫哲学**：

  - **每条新守卫都要隔离镜像变异实测**（见下）。
  - **不许为了让门禁变绿而放宽/删除判据**。判据红了就改实现，不改判据。**唯一例外**：判据钉的是"G3 没有动过 X"这类**阶段作用域**的历史事实，G4 正是那个被判为"应该改"的阶段 ⇒ 必须**retarget（改锚点、保留判据目的）**，并在注释里写明"冻结期已结束、本条改为判 Y"。**删除一条腿必须在任务报告里单独列出并说明它的目的被谁接走。**
- ⚑ **变异实测协议（三条硬规矩，G3 §5 的教训）**：
  1. **隔离镜像**：变异只在 `.superpowers/<dir>/mirror/` 下的副本上做（用 `execFileSync('git',['show','HEAD:<path>'])` 取基线，**断言 `\r` 计数为 0**）；**共享工作树只读**，绝不在原文件上改。

  3. **独立探针必须能自己复现缺陷**：①② 都不足以证明"变异真的改了语义"（G3 实测过 `if (false)` 包裹原代码同时满足 ①② 而语义未变）。任何一次"全绿"都要**重跑第二遍**再下结论。

## 4. 已裁决（本计划不再问用户；每条给理由与代价）

> 用户在上一阶段已授权"只要能满足我之前说过的那些要求就可以"⇒ 以下取舍由规划者拍板并留档。**凡与设计稿原文不一致的，都如实标为"有意偏离"。**

**D1 — `settling.ts`（动作序列化门，设计稿 §4.4）不在 G4 实现，推迟到 G5。**
理由：它的**唯一触发条件是"远端操作在本地特效播放中到达"**（设计稿 `:413`），而 G4 没有任何远端操作 ⇒ 写出来只能靠"读源码找字符串"证明它存在，**没有可判的行为腿**（违反"行为腿 > 文本腿"）。
代价：G5 实现 `NetDriver` 时要连它一起做，且那时才第一次能测"两个特效不交叠"。**如实记为对本阶段范围的偏离。**

**D2 — 驱动**不持有** `GameState`：状态仍住 `main.ts`，driver 只做"执行策略 + 记录/重放"，签名是 `submit(state, action)`。**
理由：FX 编排（抽牌幽灵、揭示飞行、`resetEpoch` 世代守卫、`drawAnimBusy` 互斥）**必须包住每一次状态迁移**，而它住 `main.ts`（`:243-372`）。若把状态搬进 driver（设计稿 §4.1 的 `onState(cb)` 形态），就必须把所有迁移都变成"driver 先改、`main.ts` 再订阅后置编排"，语义等价但要把 `main.ts` 里 **~200 处 `state` 引用**全部重写。
代价：与设计稿 §4.1 的签名**有意偏离**（`onState` 暂时没有消费者）。G5 做 `NetDriver` 时若真需要订阅，再按那时的实际需要引入 —— 那时才有第二个消费者，也才有一条真实的行为腿。

**D3 — 重放的**执行路径**与现场**完全同一条**：重放的一步 = `cb.onAction(档案里的下一条)`（见 D12 的闸门语义）；重放页**只读**（`acceptsInput()` 恒 `false`），并有一层**遮罩**让"不可操作"是真的而不是文案。**
理由：侦察确认 `pendingDraws:77` / `pendingReveals:80` 两个累加器**只在 `cb.onAction` 内部排空**（`:336-339`）。绕过编排直呼 `executeAction` 会把它们灌满且永不排空，泄漏进下一次真实行动 —— 这是个**不报错的**缺陷。走同一条路径则"特效、世代守卫、错误守卫、排空"全部免费复用（也用不着 D1 那个被推迟的 `settling.ts`）。
**代价**：① 重放页不能"从这一步接着打"（另一个功能，不在 G4 验收里）；② 因为要复用 `cb.onAction`，重放期间必须让 `state` 指向重放状态（见 D11）。

**D4 — 重放**从草稿开始**：按 `setup.draftPicks` / `bannedProtocols` 两条序列 + `draftNextAction` 的纯派生性重建草稿，再逐步执行 `actions`。**
理由：`nextActionFrom` 只依赖两个计数（`create.ts:144-166`）⇒ 顺序完全可重建；不这么做，"档案可重放"对**任何真实对局**都不成立（现有测试靠硬编码策略掩盖了这个洞）。
**代价**：档案里的草稿序列**不保留撤销历史**（见 D5）。

**D5 — 带撤销（`performDraftUnpick`）的对局，重放后 `log` 会短一截 ⇒ 状态指纹不同；如实登记为已知缺口，并配一条腿把差异**限定在 `log`**。**
理由：`MatchFileSetup` 只存最终序列（`match-file.ts:45-51` 的注释本身就说它是"顺序快照"）；补撤销历史要扩档案格式 ⇒ 触发版本迁移链，超出 G4。
**代价**：这类对局的重放**日志面板与原件不完全一致**（其余字段相同）。**修它属于格式 v2**，写进 G4 收口文档的已知缺口清单。**绝不允许**用"剔除 log 后再比指纹"当作通过判据来掩盖它 —— 那条比较只用来**定位**差异来源，且必须与"无撤销 ⇒ 含 log 也相等"这条腿成对出现。

**D6 — 重放页要有一条**无文件选择器**的到达路径；机器真值走**第五道门禁自己的探针入口**（已核对，见 §3.6），devmode 指令只是**可选的人工入口**。**
理由：① 第五道门禁（真 Chrome 真值）没有它就没法覆盖新屏，而 G4 恰恰动了 `rerender` 与页面路由；② 规划者/评审者自己也要能反复验证新屏落点。
**已核对的机制**：第五道门禁**不经过 `src/`** —— 它是独立入口 `tools/browser-truth-probe.js`（自己 import 渲染器、自己 `createGame` 建状态），场景只是那个文件里的一个 `if`。⇒ 加第 4 场景的成本远低于原设想（不需要 devmode 密码流程，也不需要 `main.ts` 读 query）。
**代价**：探针是**第二份装配**（自己建状态、自己调渲染器）⇒ T6 必须让它在重放路径上**复用生产函数**，否则"机器真值"验的不是产物。

**D7 — 新屏样式放新文件 `src/ui/styles-replay.css`；`styles.css` / `render.ts` / `render-net.ts` 等红线文件一行不改。**
理由：G3 已立下"新屏 = 新 CSS 文件"的规矩（`styles-local.css`），且本仓历史上"改 `styles.css` 的级联影响面"是主要事故源。

**D8 — 重放期间**关闭自动推进**；倍速档 1×/2×/4×，0 = 暂停，单步无视倍速走一步；重放结束停在终局状态并显示"已重放完"。**
理由：自动推进（`:803-830`）与重放时钟是两套独立时钟，同时跑必然互相踩（`runAutoAdvance` 会替玩家 `advance`，让重放步数与档案错位）。**代价**：重放页不会自动跳过非玩家步骤 —— 正是想要的（重放该忠实）。

**D9 — 「导出档案」的含义改变：导出**当前/最近一局的真实对局档案**；本次会话还没有对局记录时**拒绝导出并如实告知**，不再导出 `actions: []` 的"本机数据快照"。**
理由：G3 那份快照档案的唯一目的是"让导出这件事在 G3 有东西可导"（`local-data.ts:366-367` 的文案自陈）。G4 之后留着它只会让玩家以为"我导出的就是对局"。
**代价**：① 玩家可见行为变化（必须改文案与腿）；② 会话内"最近一局"要在返回主界面后**保留**（否则打完一局回主页就导不出来了）⇒ 新增一份内存态 `lastArchive`，在**新对局开始时**清空。**不落盘**。

**D10 — G4 **不新增任何 FX 开关**；倍速（2×/4×）只缩短**步间隔**，不吞特效。**
理由：全仓**没有**全局 FX 开关（`fxEnabled|suppressFx|fastForward|globalFx|reduceMotion` 零命中）。要加一个就得让**每个**订阅点都去咨询它 —— `main.ts:868/882/891` + `effects/index.ts` + `fx-gen2.ts` + `gen3-control.ts` + `fx-gen3-swap.ts`，其中三个是红线文件，而且"漏改一个订阅点"**不会报任何错**（只是少播一个特效）。
**代价**：4× 下长特效（抽牌/揭示/编译环）仍占满真实时间，一局重放快不了 4 倍。**如实写进收口文档**；真正的"瞬时快进"是 G7 观战"快速重放"的独立任务（设计稿 §15）。

**D11 — 重放页**重绑 `state`**，进入/退出两侧各做一次完整复位；退出回主界面。**
理由：`state`（`main.ts:54`）是被 `rerender`(`:125`/`:146`)、`cb`、`runAutoAdvance`(`:803-821`)、`syncPersistentFx`(`:918-949`)、`initDevMode`(`:861`)、`initDiag`(`:850`) 共 **6 处**读的**单一模块变量** ⇒ 要复用 `rerender()` 就必须让 `state` 指向重放状态，否则重放页画的是别的局。
**不需要"存档再还原"**：通往「本地数据与隐私」屏的路径只有主页（`showHome` 的 `openLocalData`，`main.ts:648-656`），**对局进行中到不了那里** ⇒ 进入重放时根本不存在"正在打的一局"可丢。
进入：`resetUiState()`（`render.ts:5568-5662`）+ `setFxViewSeat(null)`（`resetUiState` **不碰** fx-seat —— 侦察 B 实测）+ `renderMode = 'replay'` + `resetEpoch += 1`。退出：并入 `resetToMainInterface` 的同一套复位（**第四份跨页状态**，与 `renderMode`/`netViewSeat`/`fx-seat` 并排），`lastArchive` **保留**（D9）。

**D12 — 重放驱动的语义是「**闸门**」：只有档案里的**下一条**操作能通过；玩家点出来的操作被拒。**
理由（本计划最重要的一条设计决定）：重放必须复用 `cb.onAction` 那条编排（D3），于是重放的每一步就是 **`cb.onAction(档案里的下一条)`** —— 与现场走的是同一条路径（错误守卫、世代守卫、特效编排、累加器排空、重渲染全都免费）。
据此定义 `ReplayDriver.submit(s, a)`：若 `a` 与 `cursor` 处的记录**等价**（`kind` + `args` + `player` 逐项相等）⇒ 应用**记录里的那一条**（不是调用方给的那条 —— 这一条消掉一整类漂移）且 `cursor++`；否则拒绝（`refusal: 'not-the-next-action'`），状态一字不动。
`acceptsInput()` 仍恒 `false`（UI 据此画"重放中不可操作"+ 遮罩）。
**已知无害等价（如实登记）**：玩家恰好点到与档案下一条**完全同形**的操作时会被接受 —— 效果等同按了一次「单步」。这条路由 T3 的**遮罩层**在界面上堵掉。

**D13 — 档案**不落盘**：只在内存 + 用户自己选的文件里 ⇒ 隐私文案**一句不改**、`clearAllLocalData` 语义**不动**。**
理由：侦察 C 实测，只有"把档案写进浏览器存储"才会让 `src/app/privacy.ts:96/99/107/146` 四句变成不完整枚举；而那四句被**整句哈希钉死**（`tests/app/privacy.test.ts:363-381` 的 `COPY_PINS`、`:498-518` 的 `MODULE_PINS`），改动要人工复核后重钉。**G4 不写存储 ⇒ 这个代价不用付。**
**代价**：「最近一局」刷新页面后消失（要留住就得落盘，那正是要避免的）。⇒ 屏上文案必须写清"档案要自己导出保存，本机不替你留"。这条**也是 D9 的诚实前提**。

### T2 — `src/app/match-driver.ts`：`MatchDriver` 契约 + `LocalDriver` + `ReplayDriver`（纯逻辑）

**目标**：把"谁来执行、记不记录、能不能操作、下一步什么时候走"这件事收成一个契约，热座与重放共用同一条执行路径。

**产出**：`src/app/match-driver.ts`、`tests/app/match-driver.test.ts`

**接口（照抄名字）**：
```ts
export type DriverMode = 'local' | 'replay';
export type SubmitRefusal = 'read-only' | 'not-the-next-action' | 'exhausted' | 'engine-error';

export interface SubmitResult { ok: boolean; refusal?: SubmitRefusal; error?: unknown }

export interface MatchDriver {
  readonly mode: DriverMode;
  /** 我是不是这个 driver 的"行动方"（G4 恒 true；G5 的 NetDriver 才有意义）—— 保留字段以固定契约 */
  readonly seat: PlayerId;
  /** 这个 driver 接受玩家（人）提交吗（replay = false） */
  acceptsInput(): boolean;
  /** **收口后 `main.ts` 唯一能触发状态迁移的入口** */
  submit(s: GameState, a: Omit<ActionRecord, 'seq'>): SubmitResult;
  /** 旁路留痕（不执行、不进 actions、只 note） */
  note(a: Omit<ActionRecord, 'seq'>): void;
  /** local: 记录器；replay: null */
  recorder(): MatchFileRecorder | null;
  dispose(): void;
}

export interface Ticker { schedule(fn: () => void, ms: number): number; cancel(h: number): void }

export function createLocalDriver(opts?: { recorder?: MatchFileRecorder }): MatchDriver;

export interface ReplayCursor {
  /** 已执行步数（不含草稿重建） */
  position: number;
  total: number;
  done: boolean;
  paused: boolean;
  /** 0 = 暂停；1/2/4 = 倍速 */
  rate: 0 | 1 | 2 | 4;
  /** 引擎抛错时的人类可读文本（重放页要把它显示出来） */
  error: string | null;
}
export interface ReplayDriver extends MatchDriver {
  readonly file: MatchFile;
  cursor(): ReplayCursor;
  /** 下一档案操作（**深拷贝快照**，与记录器同款语义）；`done` 后返回 `null`。
   *  main.ts 用它驱动：`cb.onAction(next())` —— 见 D12 的闸门语义。 */
  next(): ActionRecord | null;
  play(): void;
  pause(): void;
  setRate(rate: 0 | 1 | 2 | 4): void;
  /** 订阅"该走下一步了"（由注入的 ticker 驱动）。返回退订函数 */
  onTick(cb: () => void): () => void;
  /** **本步特效已播完**的握手：由 main.ts 在编排的**每个终止点**调用（见 T4）。
   *  驱动据此决定是否安排下一步（pause/rate 生效点）。 */
  settle(): void;
}
export function createReplayDriver(f: MatchFile, env: { ticker: Ticker; stepMs?: number; settleWatchdogMs?: number }): ReplayDriver;
```

**验收判据（行为腿）**：
1. **LocalDriver 与"直呼引擎"逐条等价**：同一 `seed` 下跑同一条动作序列，分别走 `createLocalDriver().submit(...)` 与直接 `executeAction(...)`（在**两份**独立 `createGame` 状态上）⇒ 每步之后 `stateFingerprint` 都相等。**这是"热座行为不变"在引擎层面的可机检证据。**
2. **记录语义**：`submit` 恰好往记录器塞一条，且 `seq` 严格递增 `0..n-1`；`note` **不进** `actions()` 但进 `noted()`；`via` 原样保留。
3. ★**闸门语义（只让档案的下一条通过）**：`submit(s, 档案的下一条)` ⇒ `{ok:true}`、`cursor().position` +1，且 `stateFingerprint` 与"直接 `applyRecordedAction(s, 那一条)`"**逐字节等价**；`submit(s, 另一条**合法但不是下一条**的操作)` ⇒ `{ok:false, refusal:'not-the-next-action'}` 且**状态一字未变**；`acceptsInput() === false` 恒成立。
4. ★**应用的是记录里那一条，不是调用方给的那条**：构造一个 `args` 与记录**不同**但 `kind`/`player` 相同的提交（例如 `line` 不同）⇒ 断言状态变化与本条**记录的** args 一致（用"重放后指纹 == 原局"证）。
   **为什么单列**：现场 UI 算出来的 args 与档案里的可能不同（例如 `effect-choice` 的 `player` 由 `prompt.chooser` 推出）；若按调用方给的走，重放会**静默走偏**。
5. **重放到底**：把 T1 的记录档案喂进去，反复 `submit(s, next()!)` 到 `done` ⇒ 最终指纹 == 原局；`cursor().position === file.actions.length`；`next()` 在 `done` 后返回 `null`。
6. **结束不崩**：`done` 后再 `submit` ⇒ `{ok:false, refusal:'exhausted'}`，**不抛**。
7. **档案被篡改**（某一步改 `cardUid`）⇒ 该步返回 `{ok:false, refusal:'engine-error'}`、`error` 是引擎抛出的原始 Error、`cursor().error` 非空；驱动**不崩**，后续 `submit` 仍可调用（但不再推进）。
8. ★**定时器与握手机制（假 ticker）**：`play()` 后**不立即** `schedule`（要等 `settle()`）；`settle()` 后**恰好** `schedule` 一次；`pause()` ⇒ `cancel` 被调用且不再 tick；`setRate(2)` 后下一次 `schedule` 的 ms 是 1× 的一半；`setRate(0)` 等价 `pause()`；**看门狗**：只给 `settleWatchdogMs` 而**从不** `settle()` ⇒ 到点仍会 tick 一次（防"永久卡死在一步上"）且 `cursor().error` 留下诊断文本；`dispose()` ⇒ `cancel` + `onTick` 退订 + 再 `submit` 不抛。
9. **`src/app` 不许有直呼定时器**：生成式扫 `src/app/**`，剥注释后按**调用形态**匹配 `setTimeout(` / `setInterval(` / `requestAnimationFrame(` ⇒ 零命中（`tests/app-purity.test.ts:109` 已禁 `requestAnimationFrame`；本腿补前两个 —— 它们今天**没有**被禁，是本任务补上的洞）。


**变异实测要求**：
- M1：`LocalDriver.submit` 里删掉 `recorder.record(...)` ⇒ 判据 2 必红。
- M2：`ReplayDriver.submit` 的闸门换成"什么都放行"（等价 `acceptsInput()===true`）⇒ 判据 3 **必红** —— **这是"重放只读 / 闸门"的全部价值**。
- M3：`submit` 应用**调用方**给的那条而不是记录里的那条 ⇒ 判据 4 必红。
- M4：握手写错（`settle()` 之前就 `schedule`，或把看门狗删掉）⇒ 判据 8 必红。

**文件边界**：**只能新建** `src/app/match-driver.ts` + `tests/app/match-driver.test.ts`。**依赖 T1**。**不许**碰 `src/main.ts`、`src/ui/**`、`src/core/**`。

**第 1 条：「不能区分世界」的探针不是判别器，只能配对使用。**
T3 用 `probe-f1-oldmodel.mjs` 证明"旧模型对 F1 变异是瞎的"。评审复核后指出：该探针**按设计只读 `styles.css`、从不读被变异的那张表** ⇒ 它在**变异体与纯净体上都 exit 0 并打印同一句"旧判据全绿"**，退出码**不区分世界**。
⇒ **正确用法**是"与 `probe-f1` **配对**成立"（一个证明旧公式的数据来源只有一张表，一个证明新公式双向可辨），**不能**单独写成"复现了缺陷"。
⇒ **通用规则**：任何探针在被当作"缺陷证据"之前，必须先在**纯净树**上跑一次，并**确认它报的是"缺陷不存在"**；若它与世界无关（恒绿/恒红），它就只能作为**差分对照的一半**。
⇒ 这与本仓已有的"`if (false)` 包裹也能骗过锚点唯一性 + 摘要变化"是**同一族**教训（机制满足了、语义没满足），**这是该族的第二次出现**。

**第 2 条：注释里宣称的"实测依据"必须与代码逐字相符 —— 归因错了比没有注释更坏。**
T1 的头注（`match-replay.ts:49-55`）与 `match-recorder.test.ts:224-231` 都写着"若只对 compile/refresh 还原…指纹仍不等（**实测 turn 9/10/15**）"。一审的 **M5** 把它证伪了：只留 `rearrange-protocols` 那一半 ⇒ **41 项全绿、0 红**。真相是 `rearrangeProtocolSlots` 不碰 control，所以**只有它**需要助手提前插入归还；compile/refresh 的"归还 log 在动作 log 之前"**引擎自己就保证了**（`game.ts:143/156`）⇒ 那半是空转的，而注释把 `rearrange` 那一半的**实测数字记到了 compile/refresh 头上**。
⇒ **规则**：引用"实测"时**必须能指出是哪条腿、哪个构造、删掉哪一行会红**；写不出这个链条的"实测"一律降级为"推断"。**计划自己也在 §3.1 犯了同一个错**（第一版写"重放不需要额外模拟"），已回填纠正 —— 规划者的注释同样受这条约束。

**第 3 条：探针自身也会带 bug，且它的 bug 方向恰好是"说没缺陷"。**
T3 为 F6 扩写 `probe-f5.mjs` 时，第一版报内联上限 **601 而不是 620**（在 F6 变异体上也会说"缺陷没有复现"）。原因：它按"函数体里出现过 `${param}`"反推 helper 的形参位置，而 `layer(cls, z)` 体里还有 `` `${cls} g3fx-layer` `` ⇒ 取到了 `cls`，**620 从未进候选面**。改为从 `z-index:${...}` 那一句直接取形参名后，探针报 `92 条 ⇒ 620`（变异体 20000）。
⇒ **规则**：探针报"没缺陷"时，先怀疑探针 —— 至少要用一个**已知会红的变异体**验证它确实会红（即 `probe-f5 full` 那种双向可辨性）。这是第 1 条的正向用法：**能区分世界**是探针上岗的最低要求。

**第 4 条：「0 个测试看起来是绿的」这一族有三个**不同**的入口，必须能指到具体命令才叫"实测"。**
T1 在上报时写"镜像里 `--reporter=basic` 在 vitest 4 不存在 ⇒ 整轮跑 **0 个测试却可能退 0**"。复验**实测否证了机制**：`npx vitest run --reporter=basic <file>` ⇒ `⎯ Startup Error ⎯ Failed to load custom Reporter from basic` + `ERR_LOAD_URL`，**exit=1**（启动期硬错，不是假绿）；`--help` 的合法列表里确实没有 `basic`（真、但无害）。
⇒ **真正的形态是这三个**（三个都要背下来）：
1. `npx vitest run -t "<不存在的腿名>"` ⇒ `Test Files … skipped` / `Tests … skipped`、**exit=0** —— **千万别用 `-t <中文腿名>` 判绿**（本仓 G3 已栽过一次，这次是**误把账记到 `--reporter` 头上**）。
2. **镜像不被 `include` 收编**（`vite.config.ts:5` 是 `tests/**/*.test.ts`）⇒ 裸 `npx vitest run` 从仓库根跑镜像会**一条都不跑**；必须 `--config <镜像>/vitest.config.ts` 或 `--root <镜像>`。

**第 5 条：边界纪律在"临时"两个字上最容易破。**
T6 在 `tests/` 下建了一个自述"跑完即删，绝不提交"的脚手架，被 vitest 收编（144→145），于是**另一个子代理的复验报告把 145/1818 当成了"当前树"**记下来。
⇒ **规则**：临时物一律 `.superpowers/<任务>/`（已 gitignore）；`tests/**` 与仓库根都**不是**临时区。**"我跑完会删"不是理由** —— 在你删之前，别人的门禁读数已经被你改过了。

**第 6 条：退出码必须避开管道测量（Windows/PowerShell 实测）。**
T1 为了订正第 4 条，第一次用 `npx vitest run --reporter=basic <f> | Select-String …` 量退出码，得到 **exit=0**；重定向到文件再读 `$LASTEXITCODE` 才拿到真值 **exit=1**。
原因：**管道之后 `$LASTEXITCODE` 是管道末端 cmdlet（`Select-String`）的退出码，不是 `npx` 的**。
⇒ **规则**：任何"退出码"证据都必须**不经管道**测量（`cmd > file 2>&1` 再读 `$LASTEXITCODE`，或直接 `; Write-Output "exit=$LASTEXITCODE"` 紧跟命令）。
⇒ 这条与第 4 条是**同一族**：**测量的对象被测量方式掉了包**。它也正是 T1 最初把"`--reporter` 不存在"与"0 测试退 0"两件事混成一件的**直接原因** —— 一个假的 `exit=0` 让它以为那个 reporter 是"静默假绿"。

**第 7 条：层叠问题只能问**浏览器谁在最上面**（hit test），不能读 CSS 属性 —— `getComputedStyle` 会对"被忽略的 `z-index`"照样回话。**
T6 做 M2 时，规格给的最简形态（**只**写 `shield.style.zIndex = '0'`）实测**全绿**。原因：`.board` 在热座页是 **`position: static`**（`styles.css:20` 只写 `display:flex;flex-direction:column`）⇒ **内联 `z-index` 对非定位元素被浏览器完全忽略**；而 `getComputedStyle(el).zIndex` **照样把设进去的值原样读回来** —— 于是任何"读属性"的判据都会说"压下去了、设上了"，**而浏览器根本不这么算**。修法：注入时同时给 `.board` 加 `position:relative`（只改定位方式、**几何零位移**）⇒ 三条判据全红（`overCenter`/`overCard` true→false、`blocksBoard` 9→3，命中链变成 `div.player-strip → div.board-grid → div.board`）。
⇒ **规则**：凡"谁盖住谁 / 能不能点到"的问题，**判据必须落在 `elementFromPoint`（或 `getBoundingClientRect` 的几何关系）**上，**不许**落在 `getComputedStyle` 读到的 `z-index`/`position` 上。这是"行为腿 > 文本腿"在 CSS 上的那一面：**`getComputedStyle` 读的是"作者写了什么"，`elementFromPoint` 问的是"浏览器算了什么"。**

**第 8 条：取证工具本身会给出**结构性假信号**，第五条门禁的两个实测坑。**
1. **`TIME_WAIT` ≠ 正在监听**：裸 `netstat -ano | Select-String ':5199'` 会打出**满屏 `TIME_WAIT`**（历史探测留下的**已关闭客户端 socket**、PID=0）⇒ 看起来像"端口还被占着"，或反过来让人忽略真正的 `LISTENING` 行。**必须**只判 `LISTENING` 行，或直接做连通性测试（`Test-NetConnection 127.0.0.1 -Port 5199`）。
