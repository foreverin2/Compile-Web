| 目录 | 文件数 | 体积 |

| `cardmaker/LICENSE-COMPILER-Card-Builder.txt` | 1 | 1,091 B |
| **合计** | **48 个文件** | **16,443,129 B（15.68 MB）** |

### 体积提示（用户要求：超过 ~15MB 要回报并给建议）

15.68 MB **超过**了用户给的 15 MB 线，超出约 0.68 MB。构成一目了然：
**15 套全分辨率背景 JPG 自己就占 14.70 MB**（单张 0.62–1.69 MB），其余四项加起来 1.03 MB。

三条可选处置（**本次都没做**，等用户点名）：

1. **丢掉 `card-backgrounds/thumbs/`（15 张缩略图，141 KB）** —— 收益极小，
   而且用户明确要求"含 thumbs"照搬 ⇒ 不建议；
2. **丢掉 `card-back/`（0.60 MB）** —— 它只被打印 PDF 那条路用（本项目**没做** PDF），
   当前确实是零引用素材。这是**性价比最高**的一刀（省 0.6 MB，功能零损失）；
3. **预设背景转 WebP / 降质量**（14.70 MB → 估计 6–8 MB） —— 收益最大，但要动素材字节，
   与"原样拷进来"的要求冲突，且会改变预设背景的观感 ⇒ 需要用户点头。

本次的实际影响：**不进预缓存**（`SHELL_EXT` 只放行 html/js/mjs/css/json/webmanifest）
⇒ `dist/sw-manifest.json` 仍是 12 个文件、app shell 体积不变（JS 869.95 kB / gzip 240.40 kB）。
它们只在用户真去看卡面时按需加载。仓库体积变大是唯一代价。

字体：用户 2026-10-01 明确要求"连字体一起搬"，**TT-Supermolot 的授权风险由用户承担**，
本文件如实登记这一点。

## 5. 本机存储与「本地数据与隐私」屏

制作器的牌组存在**独立的 IndexedDB 库** `compile-cardmaker`（store `decks`，键 `deck`）。
理由见 `src/ui/cardmaker/store-idb.ts` 的文件头注：自定背景 base64 内嵌之后一个牌组就会
超过 localStorage 的 ~5MB 配额（参考项目 `src/storage/idb.js` 的头注给的是同一条理由）。

授权门控沿用本仓**那一份**状态机（`src/app/local-store.ts`）：

- 用户点过「允许」且后端真写得进去 ⇒ 真写盘；
- 游客模式（「不允许」）或没有 IndexedDB ⇒ 整个存储退化成内存，屏上如实说
  "改动只存在内存里，刷新或关闭页面就会丢"。

「本地数据与隐私」屏上多了**一块**（`[data-role="cardmaker"]`）：
一条读数 + 一个清除按钮（`[data-role="clear-cardmaker"]`）。
它**不在** `clearAllLocalData` 的键表里（那是 L1 的两个 localStorage 键 + 授权标记），
所以走的是两个新接缝：`LocalDataNav.readCardmaker` / `LocalDataNav.clearCardmaker`。

### 那条读数的**三态**（2026-10-01 线上验收 D1 的修法）

`readCardmaker` 给的 `count` 有三档，屏上必须说**三句不同的话**：

| `count` | 含义 | 屏上那句 |
|---|---|---|
| `0` | 库开得了、**只是没有记录**（全新访客 / 刚点完清除） | 「卡牌制作器：本机还没有保存过牌组。」 |
| `> 0` | 有 n 张卡 | 「卡牌制作器：本机保存了 n 张卡（…）。」 |
| `null` | **真读不出来**（没有 IndexedDB / `open()` 抛错 / 记录不是对象） | 「卡牌制作器：读不到本机的数据（…）。」 |
| （host 抛错） | 另一个通道 | 「读取卡牌制作器的本机数据失败：<真因>」 |

⚠️ **第一版把前两档折叠成一句**（"读不到本机的数据…"）⇒ 全新访客与**刚点完清除**的用户
都以为"清除把东西弄坏了"。修法落两处：`src/ui/cardmaker/store-idb.ts` 的
`readCardmakerDeckInfo`（只在真失败时回 `null`）与 `src/ui/local-data.ts` 的
`refreshCardmaker`（三态三句）。连带修了 `src/main.ts` 的 `clearCardmaker`：
`removed` 的判据从"读得出来吗"改成"删之前**有没有东西**"（`cards > 0`），
否则全新访客点清除会被报成"已清除…牌组"（假成功）。

### 测试为什么第一版没拦住（同一条缺陷的第二半）

屏上的腿注入的是**桩**（`{ count: 0 }`），而**真宿主**那时把空态翻成 `null` ——
夹具口径与实现口径分叉 ⇒ 屏上的断言在桩上**恒真**（变异实测：只把上游改回 `null`，
`local-data-screen.test.ts` 整套 49 条**全绿**）。现在补了一条**不用桩**的贯通腿
（真 `readCardmakerDeckInfo` + 假 IndexedDB + 真 `renderLocalData`），
只改上游也会当场红。
