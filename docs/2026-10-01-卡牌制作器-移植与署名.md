## 5. 本机存储与「本地数据与隐私」屏

制作器的牌组存在**独立的 IndexedDB 库** `compile-cardmaker`（store `decks`，键 `deck`）。
理由见 `src/ui/cardmaker/store-idb.ts` 的文件头注：自定背景 base64 内嵌之后一个牌组就会
超过 localStorage 的 ~5MB 配额（参考项目 `src/storage/idb.js` 的头注给的是同一条理由）。

授权门控沿用本仓**那一份**状态机（`src/app/local-store.ts`）：

- 用户点过「允许」且后端真写得进去 ⇒ 真写盘；
- 游客模式（「不允许」）或没有 IndexedDB ⇒ 整个存储退化成内存，屏上如实说
  "改动只存在内存里，刷新或关闭页面就会丢"。

「本地数据与隐私」屏上多了**一块**（`[data-role="cardmaker"]`）：
一条读数 + 一个清除按钮（`[data-role="clear-cardmaker"]`）。
它**不在** `clearAllLocalData` 的键表里（那是 L1 的两个 localStorage 键 + 授权标记），
所以走的是两个新接缝：`LocalDataNav.readCardmaker` / `LocalDataNav.clearCardmaker`。

### 那条读数的**三态**（2026-10-01 线上验收 D1 的修法）

`readCardmaker` 给的 `count` 有三档，屏上必须说**三句不同的话**：

| `count` | 含义 | 屏上那句 |
|---|---|---|
| `0` | 库开得了、**只是没有记录**（全新访客 / 刚点完清除） | 「卡牌制作器：本机还没有保存过牌组。」 |
| `> 0` | 有 n 张卡 | 「卡牌制作器：本机保存了 n 张卡（…）。」 |
| `null` | **真读不出来**（没有 IndexedDB / `open()` 抛错 / 记录不是对象） | 「卡牌制作器：读不到本机的数据（…）。」 |
| （host 抛错） | 另一个通道 | 「读取卡牌制作器的本机数据失败：<真因>」 |

⚠️ **第一版把前两档折叠成一句**（"读不到本机的数据…"）⇒ 全新访客与**刚点完清除**的用户
都以为"清除把东西弄坏了"。修法落两处：`src/ui/cardmaker/store-idb.ts` 的
`readCardmakerDeckInfo`（只在真失败时回 `null`）与 `src/ui/local-data.ts` 的
`refreshCardmaker`（三态三句）。连带修了 `src/main.ts` 的 `clearCardmaker`：
`removed` 的判据从"读得出来吗"改成"删之前**有没有东西**"（`cards > 0`），
否则全新访客点清除会被报成"已清除…牌组"（假成功）。

### 测试为什么第一版没拦住（同一条缺陷的第二半）

屏上的腿注入的是**桩**（`{ count: 0 }`），而**真宿主**那时把空态翻成 `null` ——
夹具口径与实现口径分叉 ⇒ 屏上的断言在桩上**恒真**（变异实测：只把上游改回 `null`，
`local-data-screen.test.ts` 整套 49 条**全绿**）。现在补了一条**不用桩**的贯通腿
（真 `readCardmakerDeckInfo` + 假 IndexedDB + 真 `renderLocalData`），
只改上游也会当场红。

## 7. ★ 2026-10-01 用户看页面后的两条 UI 改动

### 7.1 左选项 / 右预览两栏，预览栏常驻

用户原话：「我希望将自定义协议页面内的预览展示框移至右边保持常驻，其他的选项移到左边」。

  `[data-role="preview-col"]`（右）。右栏里是 `[data-role="preview"]`（画布 + 读数）与
  `[data-role="adjust"]`（背景缩放滑杆）；其余每一块（牌组名 / 卡清单 / 表单 / 背景 /
  logo / 导出导入）都在左栏。

  align-self: start; max-height: calc(100vh - 24px); overflow: auto`。

### 7.2 补上显式的双模式切换（协议卡 / 卡牌）

**先核对（用户问"这个切换在哪"）**：`协议卡自定义` 与 `卡牌自定义` 两个词在**全仓**
（`src/**` + `public/**`）**零命中**，页面 DOM 里没有 `role="tab"`、没有任何
`cardmaker-mode*` 选择器，也没有第二个能表达"我在编辑哪一种卡"的控件 —— 当时只有
「点卡清单里那一行」这一条隐式路径（`[data-role^="card-open-"]`）。**结论：这个切换原本
不存在，是这一轮补上的。**

- 顶上两个 tab（`role="tablist"` + 两个 `role="tab"`）：
  `[data-role="mode-protocol"]`「协议卡（横版 · 正/背两面）」·
  `[data-role="mode-compile"]`「卡牌（竖版编译卡）」。
- 语义：切到协议卡 ⇒ 编辑横版双面协议卡（整副只许一张这条规则不变）；切到卡牌 ⇒
  编辑竖版编译卡（整副没有就按现有加卡逻辑建一张，结论码 `mode-created-card`）。
- **两个模式各自记住上次看的那一张**（`lastSeenId: Record<CardKind, string>`，按**卡 id**
  记而不是按索引 —— 删卡会让索引左移，按索引记会悄悄换卡）。切换**不丢**任何编辑内容
  （内容一直在 `deck` 里，这里只切"在看哪一张"）。
- 切完 `refreshAll()`：预览尺寸（744×1039 ↔ 1039×744）、预览读数、**字段集合**、卡清单、
  导出按钮文案**全都**跟着切。

## 8. ★ 2026-10-01 用户报缺陷：协议卡默认版图（根因 + 修法）

**现象**（用户截图）：切到协议卡模式，预览是一个黑底、两侧有白色怪形状、中间写着
"LOADING..." 的矩形。

**根因两条，逐条有证据：**

1. **帧素材没旋转**：`card-frame/` 里 12 张 PNG **全是竖版 744×1039**（`protocol-front.png`
   / `protocol-back.png` 的自然尺寸就是 744×1039；像素统计里内容纵向占 99.3%）。
   参考项目在**加载时**就转（`app.js:3035-3036` 的 `rotate90ccw(cFront)` / `(cBack)`），
   再按 1039×744 画（`drawImage(frame, 0, 0, LAND_W, LAND_H)`）。
   我们第一版**漏了那一步**，直接把竖版帧 `drawImage` 进 1039×744 ⇒ cover 成 744×744
   贴中间、**两侧各留约 147.5px 黑带**（横向空列 295）—— 截图里那条"黑底 + 两侧怪形状"
   就是这个。修正后横向空列只剩描边外侧的 7 列。
2. **"LOADING..." 是我们代码画上去的，不是素材自带的**：12 张 PNG 里没有任何字形

   `defaultCompileText()` ⇒ 新建协议卡卡面正中就印着它。现在四段卡文本默认全空，
   `src/ui/cardmaker/**` 的**代码位**里 "LOADING"/"COMPILED" 零出现（有腿钉住）。

**没有改的东西**（逐项核对过，本来就一致）：`card-frame/` 12 张 PNG 与参考项目**逐字节相同**
（844 字节到 243,654 字节那一批，`protocol-front.png` 两边都是 43,989 B）；协议卡的三张分区表

与参考项目 `renderCompileLandscape` 的两个分支一致。

没有它）。它只服务"打印 PDF"那条路（本项目不做 PDF），协议卡的正/背版图用的是
`card-frame/protocol-front.png` / `protocol-back.png`，**不依赖它** ⇒ 本轮**没有**补拷。

若哪天要做 PDF，再补拷它即可。

## 9. ★★ 2026-10-01 线上验收第二轮：`hidden` 被 CSS 压掉（真 bug）+ 三条用户要求

### 9.1 真 bug：`.cardmaker-field { display: flex }` 压掉了 `[hidden]`

**现象**：用户在协议卡模式下仍然看到"数值 / 上方面板 / 中部面板 / 下方面板"。
**根因**（真 Chrome 实测，`.superpowers/cardmaker/probe-struct.mjs`）：行的 `hidden === true`
**确实写上了**，但 `getComputedStyle(row).display === 'flex'`、行高仍是 54/122 ⇒ 照样可见。
作者样式的 `display: flex` 压过了浏览器 UA 的 `[hidden] { display: none }`。
**本仓同族先例**：`styles.css:1825`「display:flex 会覆盖 hidden 属性，需显式声明 [hidden] 恢复隐藏」
（`.dev-results` 当年栽在同一件事上）。

**修法三件一起上**：① `hidden` 属性（语义/可测）；②
`styles-local.css` 的 `.cardmaker-field[hidden] { display: none }`（类+属性，特异性够）；
③ 行内 `style.display` 兜底。**只做①不生效**（这就是那个 bug），所以缺任何一件都可能复发。
配套腿：`.cardmaker-field[hidden]` 规则存在（删掉就红）、桩上内联 `display: none` 双向复原
（删掉就红）、真浏览器读数（`panel-top` 行 `display: none / h: 0`）。

### 9.2 协议卡的正 / 背切换

用户原话：「协议卡自定义选项里没有协议卡背的设计切换按钮，请调整」。
新增 `[data-role="faces"]`（`role=tablist`）+ `[data-role="face-front"|"face-back"]`（`role=tab`），
**只在协议卡模式下出现**。切面会影响：预览画哪一面（`paint` 的 `side`）、字段按面显隐

两面都想要就切一次面各导一次。

### 9.3 协议卡不携带竖版字段（数据模型 + 导出）

`hydrateCard()` 对协议卡把 `value` / `panelTop` / `panelMid` / `panelBot` 一律清空；
`packCard()` 再把这四个**键**从导出的 JSON 里剔掉（内存清空 + 文件剔键，两处都要）。

### 9.4 logo 只留形状（抠背景）

用户传不透明方图 ⇒ 卡面一片白（因为 logo 会被整体染白）。原作者的答复（用户转述）：
logo 只需保留形状、背景透明，因为应用会叠加一层白色。

- `images.ts` 新增 `cutoutBackground()`（纯函数，吃 `ImageData` 吐 `ImageData`）：
  **从四条边漫水填充**，只吃掉与外界连通的背景 ⇒ 形状内部的同色区域**不被**挖掉
  （这是它与"全局颜色替换"的关键差别）；背景色取四角众数；`tol..tol*2.5` 之间给
  **半透明**过渡（抗锯齿边缘不出现白边）。
- `removeLogoBackground()` 在**原分辨率**上先抠、再 `normalizeLogo` 缩到 320px（顺序不能反）。
- 界面：`[data-role="logo-cutout"]`「去掉 logo 背景（推荐）」默认开，配一句人话说明；
  关掉 = 保留原图。真浏览器读数：同一张不透明方图，**不去背景时六边形里 13,296 个白色像素，
  去背景后 2,818（减少 79%）**。

⚠️ 这一节的**语义在下一轮被用户改掉了**：关掉勾选框不再是"保留原图但照样染白"，而是
**原图直上**（不抠、不染白、一个像素都不动）；抠图本身也加了"细笔画保护"。**当前状态以 §10 为准。**

### 10.2 改法

**logo（语义按用户说的"改死"）**

- `drawLogoHex()` 分两条路：`logo.whiten !== false` ⇒ 抠背景 + 白色着色（原来的做法）；
  `whiten === false` ⇒ **原图直上**：直接 `drawImage` 那张原图，不建离屏画布、不设

### 10.4 已知取舍（如实记下）

- 抠图被"细笔画保护"挡下来的那一圈背景色像素是**原样保留**（不是半透明），所以形状外沿
  可能留一圈 ≤ `GUARD`（3px）宽的**原背景色**。这是有意的：白化之后它本来就是白的，
  而"抠过界、把笔画啃掉"不可逆。
- `REJECT_RATIO = 0.9` 的代价：一张"小图形 + 一大片背景"的 logo（背景占比 > 90%）会被判为
  可疑而**不抠**，卡面上看到的是原图（带背景色）。这是"宁可不动"的取舍，界面文案说明了
  原因，用户可以取消勾选或换一张裁紧一点的图。
- 勾选框只在**上传时**生效（文案里写了"上传时生效"）；改勾选不会重处理已上传的 logo。
