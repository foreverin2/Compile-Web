## 0. 一句话结论

HTTPS 对本站不只是"更安全"：**它解锁三类现在根本不生效的能力**（Service Worker / PWA、
Web Crypto、带凭据接口的合规要求），而"缓存与加载"的优化里**一半是 HTTPS 之后顺手做**的
（HTTP/2、Brotli、CDN、预缓存清单扩大），另一半**现在就能做、与 HTTPS 无关**（`index.html` 的
缓存头、卡图体积、首屏包体）。

## 1. HTTPS 解锁的三件事（现在线上**没有**）

| # | 现在（http://8.130.97.243） | 上了 HTTPS 之后 | 证据 |
|---|---|---|---|
| 1 | **Service Worker 不注册** ⇒ PWA 的"装到桌面 / 断网打开 / 更新提示"三件都不生效（代码在，浏览器层面直接被安全上下文挡掉） | 三件真的可用：预缓存 12 个文件（1.26 MiB）装完即可离线打开，发新版会提示并可一键更新 | `src/ui/pwa-update.ts:340` 注册 `/sw.js`（`scope: '/'`）；该文件头注写明了"真实浏览器里 SW 到底注册成功没有…那要 https/127.0.0.1"；`README.md` §PWA（第 52-58 行）写了它**应当**有的效果 |
| 2 | `crypto.subtle` 不可用（安全上下文限定）⇒ 用到 `digest` 的路径只能走降级分支 | 原生加密/摘要可用（联机的指纹与凭据交换） | `public/probe.html:104-107` 就是设备体检页读的 `crypto.subtle` / `serviceWorker` / `isSecureContext` 三项 —— 现在这三项在线上是 false |
| 3 | 带凭据的接口只能跑明文；反馈服务的会话 Cookie **没有 `Secure`** | `/turn-cred` 按 RUNBOOK 的口径"只允许 HTTPS"；反馈服务给 Cookie 加 `Secure` | `server/turn-cred/RUNBOOK.md:130`（"这个接口带凭据：只允许 HTTPS（前置条件：域名备案 + 证书就绪）"）；`server/feedback/RUNBOOK.md:538`（"等上了 https 要在 `lib/auth.mjs` 的 `sessionCookie` 里加上"） |

⚠️ 第 3 条里的 `/turn-cred` 与反馈服务**不在本站的静态产物里**，属于服务器侧那一摊
（`server/**`）；本站前端不需要改代码，HTTPS 一生效它们就跟着可用。

## 2. 缓存与加载：现在就能做（与 HTTPS 无关）

线上 nginx 的实际配置在 `.superpowers/g5-server/compile.nginx.conf`（一次部署一份，内容如下要点）：

```nginx
location /assets/ { expires 30d; add_header Cache-Control "public, max-age=2592000, immutable"; }
location = /sw.js { add_header Cache-Control "no-cache"; }
gzip on; gzip_types text/css application/javascript application/json …
```

| # | 现状 | 建议 | 依据 / 代价 |
|---|---|---|---|
| a | `index.html` **没有显式缓存头**（只有 `sw.js` 有 `no-cache`） | 给 `location = /index.html` 加 `Cache-Control: no-cache`（或 `max-age=0, must-revalidate`） | 站点用**带哈希的文件名**，HTML 一旦被浏览器缓存住，就会去要已经删掉的旧 assets（更新后白屏/旧版混搭）。这是**现在**就可能踩的坑 |
| b | 主包 1.20 MB（gzip 328 KB）、CSS 378 KB（gzip 74 KB） | ① 代码分割（把图鉴/卡牌制作器那两块拆出去）；② 长期看可以给这两块做 `modulepreload` | 构建输出的实测数字（2026-10-07 的 `npm run build`）；本仓零运行时依赖，拆包不需要引入库 |
| c | 卡图每张 **~0.9 MB**，270 张（图鉴已 `loading="lazy"`，实测 0 加载失败） | ① 转 WebP/AVIF（体积通常降 50-70%）；② 或走 CDN | `README.md` 的图鉴懒加载读数；转格式要重跑 `texts:check` 与卡图哈希那一族腿（`src/data/**` 红线） |
| d | SW 预缓存只有程序外壳 12 个文件 1.26 MiB | 上了 HTTPS 后可以按需把"首屏必需的几张图"也纳入预缓存 | 代价：安装时多下载；预缓存清单由构建生成（`sw-manifest.json`） |

## 3. 缓存与加载：HTTPS 之后才做得了

| # | 手段 | 为什么卡在 HTTPS | 备注 |
|---|---|---|---|
| a | **HTTP/2（或 HTTP/3）** | 浏览器只在 TLS 上启用 h2（明文 h2c 基本没人支持）；HTTP/1.1 下并发连接数受限，对"1 个 JS + 1 个 CSS + 若干图"的首屏影响明显 | `listen 443 ssl http2;` 一行；HTTP/3 要 nginx 1.25+ 且开 `quic`（本机 nginx 是 1.18，见 `docs/2026-09-17-G5-进度与上下文.md:609`） |
| b | **Brotli（`br`）** | 与 HTTPS 无必然关系，但**国内 CDN 普遍只对 https 站点开放压缩/加速**；自建也行（需要 `ngx_brotli` 模块，发行版包通常不带 ⇒ 要自己编） | 收益：JS/CSS 再降 ~15-20%（对比现有 gzip） |
| c | **CDN 加速**（国内 CDN 要求域名备案） | 备案是前提；CDN 回源也要求 https | 设计稿里就写了"国内静态托管/下载慢 ⇒ 国内镜像 + 备案 CDN"（`docs/2026-09-13-联机与多端-设计稿.md:692` 与 `:810` 的 R8） |
| d | **域名 + 证书本身**（Let's Encrypt） | 证书必须绑域名（IP 证书基本拿不到）；大陆服务器上未备案域名走 80/443 会被拦 ⇒ **顺序是：备案 → DNS → 签发证书** | 签发用 HTTP-01 时要 80 端口可达（恰恰要等备案）；也可用 DNS-01 绕过 80 |

## 4. 升级顺序（清单，等域名与备案到位后照这个走）

1. 备案通过 → 域名解析 A 记录指向 `8.130.97.243`；
2. `certbot --nginx -d <域名>` 拿证书（自动续期）；
3. nginx：`listen 443 ssl http2;` + 80 → 443 跳转；顺手把第 2 节 (a) 的 `index.html` 缓存头补上；
4. `server/turn-cred` 与 `server/feedback` 按各自 RUNBOOK 切到 HTTPS（含会话 Cookie 的 `Secure`）；
5. 打开 `https://<域名>/probe.html`，确认设备体检页上 **`secureContext=true`**、
   `serviceWorker=true`、`crypto.subtle=true`，再看"装到桌面 / 断网打开"是否真的可用；
6. 之后再谈 CDN、Brotli、卡图转格式（第 2/3 节）—— 那些是"更快"，不是"能不能用"。
