## 0. 你不需要做的事（先说清，免得白折腾）

- **不需要服务器**：两台设备之间是直连（`src/app/privacy.ts:102` 那句是唯一出处）。
- **不需要填 TURN**：只在两端不在同一个局域网、直连打不通时才需要（见 §6）。
- **不需要输 6 位房间码**：短码要信令服务器，今天这里没有（见 §6 第 1 条）。
- **不要刷新页面**：刷新只是把手里这份会话丢掉，对局不会回来（`src/ui/net-lobby.ts:547-554` 那三句就是这件事）。

## 1. 起环境

**这一步做什么**：把页面跑起来，开两个窗口。

1. 在仓库根跑 `npm run dev`（Vite 默认端口 **5173**；这是你自己的 dev server，本清单一律不去碰它）。
2. 开**两个**普通窗口（不是无痕也行，但要两个独立窗口，别用同一个窗口的两个标签页 —— 焦点与 ICE 行为容易互相干扰）。
3. 两个窗口都打开 **`http://127.0.0.1:5173/#g5probe=1`**。
   - `#g5probe=1` 那段是**只读的排查读取口**（`src/main.ts:858-867` 的 `exposeMatchProbe()`）；不带它也能打，只是出错时看不到读数。

**什么算通过**：两个窗口都出现授权屏或主页。
**什么算失败**：窗口一片空白 / 控制台有异常 —— 先看第一个 `[X]` 那行报错，别继续往下走。

## 2. 走到"两个人都进同一局"（握手）

每一步都**只点自己那一页**，别猜对方在点哪里。

1. 两页都点「开始游戏」→ 模式选择里点「**联机对战（两台设备）**」。两页都出现大厅。
2. **窗口 A（当房主）**：点「**建房**」→ 再点「**生成邀请码**」。
   - 看：屏上出现一串码（实测：2026-09-18 大厅门三次是 **740 / 740 / 738** 字符；本清单撰写当天的一次性场景是 **737** 字符）。
   - **通过**：码非空、形状是 `<数字>.<base64url>`。
   - **失败**：点了没反应 / 屏上没有长度读数。
3. **窗口 B（当加入方）**：点「**加入**」→ 把 A 那串码**整段**粘进粘贴框（整段，别手打）→ 点「**出示回示码**」。
   - **通过**：B 出一串回示码（大厅门实测 654 / 658 字符；当天那次是 **653**）。
   - **失败**：可读失败句（例如"压缩段解不开（内容被改动或截断过）"）⇒ 码没粘全，重粘。
4. **窗口 A**：把 B 的回示码**整段**粘进「粘贴对方的回示码」那个框。
   - **通过**：A 的相位离开"握手中"，两端都出现**硬币屏**。
   - 注意：A 那行结论**可能要等几秒**才出现（本机 ICE 收集实测 4.8-5.2 秒）。
5. **窗口 B**：硬币屏上点**任意一枚**面（这一页是"叫面"的一方；标题会写清"由加入方选面"）。
   - **通过**：两端都从硬币屏进**草稿屏**（`.draft-screen`）。
   - **失败**：点下去没反应（历史上这是"新链路要面被旧闩吞掉"那个形态，T13-C 已修，见 `tests/ui/net-link-recovery.test.ts`）。

**这一段的硬判据**：两端屏上都出现草稿屏，且**两端盘面逐字相同**（见 §3 的读数法）。

## 3. 草稿：把六次选牌走完

规则：草稿是 **1-2-2-1 共 6 次**（`src/core/state/create.ts:38` 的 `DRAFT_PICK_COUNT`）。**每次只有一个人选**，另一页只等。

1. 看屏上那条醒目横幅（`src/ui/render.ts:4925-4936`）写的是「**玩家 N**」——那是**座位号**。
   - 同一屏上还有一行**人话**：`.net-turn-line`，写「轮到**你**选协议（第 X 步，共 6 步）」或「现在轮到**对方**选协议 …… 等他选」。
   - 这一行是本轮（T14）加的，取值与驱动同一个读数（`src/main.ts` 的 `appendTurnLine()`）。
2. **只在写"轮到你"的那一页**动手：从中间协议池**拖一张卡**到**它自己那一侧的「已选」框**（`.draft-picks.p1` / `.p2`，横幅说轮到谁就拖到谁那一框）。
3. 松手之后：**那一页**的横幅与"第 X 步"要往前走一格；**另一页**的同一读数也要跟着走（它是从线上收到的那一帧）。
4. 重复到**第 6 次**选完（两端 `draftRound` 都到 6）。

**通过**：六次都由"轮到的那一页"拖，另一页一次不点，最后两端都进牌桌（草稿屏消失）。
**失败**：

- 拖了没反应（卡回原位）⇒ 你多半在**不是自己回合**的那一页拖的，看 `.net-turn-line`；
- 一端进了牌桌、另一端还在草稿 ⇒ 记下两页 `.net-turn-line` 的原文，这是缺陷。

## 4. 对局：真打几步

     只有"给一张"要你来选。node 面这条链已验（`tests/net/net-cross-side-choice.test.ts`），真机待你试。

4. 每次动手之后，**两页都要看一眼**：

**通过**（每一步都要同时满足）：

- 动手那一页的盘面变了（`state()` 的指纹变了）；
- 另一页的 `state()` **与它逐字相同**；
- 另一页**没人点过**；
- `drive().applied` 涨了、`drive().pending` 是 0、`drive().failure` 是 `null`。

**失败**：

- 两端规范串不同 ⇒ 分叉，**不能修**（D1 的代价），停手并记录；
- `pending` 一直不为 0 ⇒ 帧到了没落地；
- `failure` 有值 ⇒ 那是驱动留下的真因，原样抄下来。

## 5. 故意做一次"不是自己回合"的输入（负控）

1. 等到**不是**你回合的时候（`.net-turn-line` 说"轮到对方"），在**你那一页**试着把手牌拖到链路槽。
2. **通过**：
   - 落点**一个都不亮**（拖拽期间没有 `.drag-target`）；
   - 松手之后**两页盘面一字不动**（规范串指纹不变）；
   - 屏上不出现任何"成功"字样、不出现新的回示码/相位行。
3. **失败**：本端状态变了 / 对端跟着变了 / 出现"假成功" —— 这是缺陷，把两页指纹抄下来。

## 5.5 重点试这些卡（T23 之后：哪些卡最可能撞上同一族 bug）

## 6. 已知会遇到的（照实写，别当成缺陷来报）

1. **6 位房间码今天用不了**：那条路要信令服务器，端点为空时屏上只给一句可读提示且**一个请求都不发**（`src/net/invite.ts` 的 `NO_ENDPOINT_MESSAGE`，`src/ui/net-lobby.ts` 只渲染）。今天照做只能走邀请码。
2. **草稿期没有计时**：回合计时属 G6，本阶段不做；草稿与对局都不会因为"等太久"自动推进。
3. **掉线超过宽限只能重开**：对局中掉线超过约 **4 秒**宽限（`src/main.ts` 的 `RECONNECT_GRACE_MS`）会被**带回"建房 / 加入房"那一屏**（`linkRecoveryNeeded`）。在那里重新生成邀请码 / 重新加入，接上之后走 `resuming` 追平。
   - **5 分钟窗口今天判不了**：生产没有给大厅注入时钟 ⇒ 屏上是"判不了"那一格（计划 §9 第 30 条）。
4. **跨机 / 跨网络未验证**：本机两个 Chrome 进程验过；NAT 打洞、跨机 mDNS 解析、丢包、手机切后台都**未验证**（计划 §9 第 1、2 条）。
5. **刷新页面不能让对局回来**：刷新等于把本地那份会话丢掉。
6. **不要用本清单去验观战 / 投降 / 计时**：都不在 G5 范围内（计划 §1.2）。
