## 3. 效果引擎能力清单（开发新卡前必读）

- **Op**（`Op` 联合）：`discard/delete/return/flip/shift/playTopDeck/playFromHand/reveal/draw`。shift/delete/return/flip 支持 `allowCovered`；`cardPointValue` 单卡分值（正面=def.value；反面=2，暗2顶命令线上=4；牌库=2）。
- **选择类型**（`ChoiceRequest.kind`）：`select`（候选卡）、`select-line`（应答 `'line:N'`，可 optional 跳过）、`select-action`（应答 `'action:X'`，可 optional「跳过」）。`chooser` 字段指定应答玩家（缺省=效果属主）。
- **fizzle 规则（用户拍板）**：任何选择步骤候选为空 → `runStack` 以 `{selected:[]}` 续接生成器，**生成器必须守卫 `ans.selected.length === 0` 后自行结束**（不得死锁）。
- **触发器**：`before-covered`（被盖住前，fire-0 用）、`end`/`start`（只收当前回合玩家场地侧）。触发器效果必须等其完整结算后落地卡（sourceValid 机制）。
- **valueModifier**：`CardEffects.valueModifier { target: 'own-stack' | 'opponent-line' | 'line'; apply(s, owner, line, total) }`，`stackValue` 集成（line 目标=线上任一方正面卡即对双方估值生效）。暗2 用它：线上反面牌分值 4。
- **覆盖卡**：`CandidateFilter.covered`（列出非顶卡）+ op `allowCovered`。
- **幽灵牌（揭示）**：`reveal` op 复制卡面为幽灵（`revealedGhosts`），两种情形：**A 揭示己方卡→幽灵给对方**（对手回合结束消失）；**B 揭示对方卡→幽灵给自己**（自己下一回合结束消失）——按被揭示卡归属 vs 效果属主判定，`expiresAtTurn = turnCount + 2/3`。`lightFx` 标志给光系揭示幽灵加十字星+边框光晕。
- **易主安全**：效果逻辑**不得假设效果卡协议属于持有者**（isPlayableFaceUp 已双线匹配；light-2 的翻/移/跳过选择权=打出者）。

## 4. 开发新协议（水/生命）的标准步骤

1. **读卡面文本**：`src/data/cards.ts` 中 `water-0..5` / `life-0..5` 的 middle/top/bottom 文本（权威在 `compile1文本.txt`）；规则疑问查 `rules文本.txt`（第 77/78/79 行定义顶/中/底指令；第 58 行：背面无协议属性无指令、分值固定 2；第 87-90 行覆盖规则；第 123 行：平移=同一玩家场地内换线，不换归属）。
2. **对照模板**：`src/core/effects/cards/light.ts`（抽/翻/平移/揭示/弃）与 `darkness.ts`（抽/平移对手/覆盖目标/playTopDeck/playFromHand/valueModifier）——新协议照此写生成器。
3. **注册**：`registerCardEffects('water-0', { middle: ... })`；`src/core/effects/resolve.ts` 顶部补 `import './cards/water';`。
4. **测试**：`tests/effects/water.test.ts` / `life.test.ts`，TDD（先 RED 后 GREEN）；helpers 有 `draftFireP1/draftLightP1/draftDarknessP1` 模板，可加 `draftWaterP1`（P1 第 1 选 `water`）。
5. **特效**（如需专属）：`src/ui/effects/index.ts` 的 triggerProtocol 额外分支 + `styles.css`；已编译特效在 `appendCompiledRing`（render.ts）按 defId 分支 + `.compiled-ring-<defId>`/`.compiled-fx-<defId>`。
6. **流程**：沿用 SDD 子代理驱动（见 §7）——每任务 implementer 实施 + reviewer 评审（spec+quality 双裁决），全绿后合并 main，**推送等用户指示**。

## 5. 已实现的游戏规则要点（用户逐条拍板）

- fizzle 防死锁（见 §3）。幽灵牌 15 张手牌上限。牌库区/弃牌堆/挡板布局、抽牌特效起点=牌库区。
- 暗2 顶命令：**线级**（对手相对线路也生效），线上反面牌分值 4；正面上线时双方该线边框持续冒黑烟（12 团、常驻不重启）。
- 暗0/暗1/暗4 平移有"黑烟桥"动画（起点终点标记→浓烟桥渐现→卡飞过→桥渐消，桥厚=一张牌长 178.8px）。
- 光2：先抽 2 再揭示 1 张反面牌（可被盖的、可对手的）；**翻/移/跳过由打出光2 的玩家决定**；揭示后翻转/平移可用 allowCovered。
- 光3：平移**本线双方**全部反面牌到所选线。光4：揭示对手手牌（幽灵依次飞入自己手牌）。
- 光0：**先翻面后按翻转后分值抽牌**；翻后被移出游戏仍生效（弃牌堆公开→抽牌面分值；牌库秘密→抽 2）。
- 暗3：**先选手牌**（要反面打出的那张）**再选线**（playFromHand op）。暗1 可选平移目标线**包含暗1 所在行**（只排除被翻卡当前行）。
- 揭示幽灵两种情形消失时机（§3）。卡牌易主规则（§3）。
- 效果选择按钮全部固定在**视口底部操作台**（fixed bottom-center，滚动不消失）；导出日志按钮放大固定在右下角。
- 编译特效：火=慢速岩浆+大石头+熔岩背光+石头浮动；光=黄白呼吸+四角护边；暗=深灰↔纯黑+波浪尺扇贝光晕+不规则黑雾+圆形黑烟；**全部常驻（跨渲染不重启）**。
