## 四、怎么自己复核（三步，五分钟）

### 第 1 步：把界面切成英文

方式 A（真浏览器）：打开游戏 → **设置 → 语言 → English**（这一行是双语的 `语言 / Language`，
只认得英文的人也能找到）。

方式 B（直接写存储，与门禁脚本用的是同一条路）：

```js
// 在页面控制台里跑，然后刷新
localStorage.setItem('compile-settings', JSON.stringify({ nick: 'x', lang: 'en', onboardingSeen: true, fx: {} }));
localStorage.setItem('compile-consent', 'allowed');
location.reload();
```

### 第 2 步：一眼看还剩哪些中文

- **看屏**：按主路径走一遍（首页 → 模式选择 → 掷硬币 → 草稿 → 牌桌 → 胜负 → 本地数据与隐私 → 图鉴 → 规则 → 卡牌制作器 → 联机大厅 → 反馈）。
  按第二节的清单对照：看到中文时先判"是不是数据（卡面/协议名）"、再判"是不是引擎给的标题/日志"，都不是的话就是 B/C 两节的缺口。
- **看机器**（在仓库根目录）：

```bash
node .superpowers/i18n-scan/scan.mjs              # src/ui/** 每个文件还剩多少中文字面量（逐条打印）
node .superpowers/i18n-turn-cred/scan-non-ui.mjs  # src/main.ts / src/net/** / src/app/** 还剩多少（本轮新加的）
npx vitest run tests/i18n                         # 两张表 + 清单 + 每条"英文帧"腿
```

### 第 3 步：要动某一屏时，按这套规矩来

1. 中文值**逐字守恒**：用 `.superpowers/*/check-verbatim.mjs` 那套（从 `git show HEAD:` 抓原文逐条比对）；
2. `t()` 的键必须是**字面量**，**不许在模块顶层调 `t()`**（`tests/i18n/module-scope-t.test.ts` 盯着）；
3. 值里的 `{xxx}` 占位符在**每一处**调用点都要给全（`tests/i18n/tables.test.ts` §8 盯着）；
4. `en` 表里**不许有汉字**，例外必须逐条登记进 `EN_CJK_ALLOW` 并写明理由；
5. **只换字符串来源，不改行为**；抽完把台账 A 表那一行删掉，并在“已抽取”一节留一条记录。

## 五、这份清单本身的口径边界（如实声明）

- 计数口径与 `tests/i18n/unextracted-manifest.test.ts` 的 `scanUiLiterals()` **同源**：
  `src/ui/**/*.ts` 的代码位、**去重**、只数含汉字的字符串/模板串 ⇒ 它**偏大**
  （类名、`data-*` 取值、给开发者看的串都会算进去），用途是**估工作量与防漏登记**，不是"待翻译句数"。
- 第二节 C 那一族的计数来自 `.superpowers/i18n-turn-cred/scan-non-ui.mjs`（**不在仓库门禁里**，
  是本轮为了这张清单临时写的扫描器，口径与上面同一个）。
- "已全覆盖"= **代码位零中文 + 至少一条腿**。它证明的是"这一屏的文案都从表里取"，
  **不**证明英文翻得好不好（那是人读的事）。
