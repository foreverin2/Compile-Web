# G3 档案格式 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让"本地优先"落地 —— 首次进入给出**授权弹窗**（允许 → 本机可存；拒绝 → 游客模式零写入），把昵称/设置/卡组这类轻量偏好在**允许之后**可持久化（L1），把 `MatchFile` 做成**可导入可导出、可校验、可迁移**的单一档案格式（L2），并让网页端可作为 PWA 安装、离线打开、可提示更新。**本阶段不实现重放**（`ReplayDriver` 属 G4）。

**Architecture:**
- 新增 `src/app/` 作为**新的分层**（设计稿 §1.1：`ui → app → core`）：本阶段它只放**纯数据与纯函数** —— `MatchFile` 的规范化/校验/迁移、卡牌数据指纹、`ActionRecord` 规范化、已执行操作的记录器。**无 DOM、无浏览器 API、可在 node 下直接单测**。
- 浏览器能力（`localStorage`/`indexedDB`/File System Access/`crypto.subtle`/Service Worker）一律**先定义可注入接口，再给浏览器实现**：`src/app/` 里只有接口与纯逻辑，`src/ui/` 里才是真实现。这样"游客模式零写入""档案往返""版本迁移""指纹不匹配"全部有**行为腿**，不依赖 jsdom（本仓测试环境是 `node`，见 `vite.config.ts:6`）。
- UI 侧新增三个屏（授权弹窗 / 本地数据屏 / PWA 更新条件）挂在**既有屏幕系统**上（`src/ui/home.ts` 的 `clearRoot`+`el`+`button` 惯例），不改导航架构。

**Tech Stack:** TypeScript 5（strict）/ Vite / vitest（node 环境、`pool: 'threads'`、**无 jsdom**）。**零运行时依赖**。

**依据文档：** `docs/2026-09-13-联机与多端-设计稿.md` §3（档案格式 MatchFile，全节）、§0.4（三条红线）、§5.9（隐私边界，**文案必须与它一致**）、§8.1（PWA）、§8.4（更新机制）、§10（测试策略）、§11（阶段路线）、§16（未决问题）；`docs/2026-09-13-G0-确定性内核-实现计划.md`（已完成的 G0 产出，本阶段直接复用）。

**前置（已在源码核对）：** G0 已完成（`src/core/rng.ts`、`src/core/fingerprint.ts`、`src/ui/match-seed.ts` 均在树上；`npx vitest run` **1298 项全绿**；`npx tsc --noEmit` 0 错；`npm run texts:check` 差异 0）。G2 已完成（`src/ui/render-net.ts`、`src/ui/styles-net.css`、`renderMode`/`netViewSeat` 路由均在树上）。

## Global Constraints

> 每条都是**硬约束**；任一任务违反即视为未完成。

- **零运行时依赖**：不得新增任何 npm 包；`package.json` 的 `dependencies` 必须保持**不存在**。**禁止 `npm install`**（含 `npm i -D`）。devDeps 只允许 `typescript` / `vite` / `vitest`（现状见 `package.json:11-15`）。
- **"需要新依赖"时必须给零依赖替代方案**：本计划中所有看似需要依赖的需求，替代方案已写死在任务里，**不得**改用依赖实现：
  - PWA（manifest / service worker / 预缓存 / 更新提示）→ **手写** `public/manifest.webmanifest` + `public/sw.js` + `src/ui/pwa-update.ts`，**不用** `vite-plugin-pwa`（Task 8）。
  - 稳定哈希 → 复用既有 `src/core/rng.ts:26` 的 `hash32` 与 `src/core/fingerprint.ts:43` 的 `hash64`。
  - 加密（若用户裁决要做）→ 浏览器/Node 内置 `crypto.subtle`（AES-GCM + PBKDF2），**不引** `crypto-js`/`libsodium`。
  - 文件读写 → `<a download>` + `<input type="file">`（**全平台可用**的降级路径），File System Access 只在能力探测通过时**附加**（§3.7）。
- **无后端、不存储任何数据**：本阶段**不写任何网络请求代码**（`fetch`/`XMLHttpRequest`/`WebSocket`/`RTCPeerConnection` 在 `src/app` 与 `src/ui/local-*.ts` 内零命中，Task 9 有守卫）。
- **只在用户同意的前提下把数据留在本地**：
  - 首次进入必须先给授权弹窗；**用户未点"允许"之前，磁盘上零写入**。
  - 游客模式（拒绝）＝ **L1 与 L2 都不写**，所有数据只在内存，刷新或关闭即全丢（设计稿 §0.4 红线 3、§3.6）。
  - "拒绝"的会话内标记**只能放内存变量**，**不得**用 `sessionStorage`/`localStorage` 承载（否则违反红线 3 的"零写入"）。设计稿 §3.6 留了"会话内标记"与"每次都问"两条路，本计划选**内存标记**（见"待用户裁决 #5"）。
- **测试环境是 `node`，没有 jsdom**（`vite.config.ts:4-8`）：
  - 不得引入 jsdom / happy-dom / playwright / puppeteer；不得给 `vite.config.ts` 加 DOM 环境。
  - UI 行为靠 `tests/ui/net-dom-stub.ts` 那类**手写桩**（该文件已实现后代选择器、`dataset` 映射、`parentElement` 维护、可配置 `getBoundingClientRect`）；纯文本判据靠 `tests/ui/source-text.ts` 的 `stripComments`/`codePositions`/`functionBody`/`stripArrayDecl`。
- **浏览器专属能力一律要有可注入抽象**（否则无法机检）：`localStorage`/`indexedDB`、File API（`showOpenFilePicker`/`showSaveFilePicker`/`<input type=file>`）、Service Worker（`navigator.serviceWorker`）、`crypto.subtle`。抽象**放在 `src/app/` 的接口**里，**在 `src/ui/` 里实现**，测试注入内存假件。
- **`src/core` 本阶段零改动**：G3 不碰 `src/core/**`（设计稿 §1.1 的"core 唯一例外"是 §14.7 的 `forfeit`，属 G6）。`src/app/` 也**不得**出现 `document`/`window`/`localStorage`/`indexedDB`/`navigator`/`fetch`（Task 9 守卫）。
- **四道门禁（每个任务收尾都要全绿）**：
  - `npx tsc --noEmit` → **0 错**
  - `npx vitest run` → **全绿**，且测试总数**不得少于 1298 项**（2026-09-16 基线：125 文件 / 1298 项，本计划每个任务都会**只增不减**）
  - `npx vite build` → **成功**
  - `npm run texts:check` → **卡牌文本差异 0 处；协议元数据差异 0 处**（该脚本读 `E:\studyE\compile\正版compile` 下的权威 txt；不写文件）
- **⚠️ 工具链险情（G2 评审查出的真实事故，务必遵守）**：文件 mtime 与 vitest 启动落在**同一秒**时，Vite 的转换缓存会让 vitest 使用**旧编译产物**（测试文件是新的，但它 `import` 的模块改动未生效；`--no-cache` 无效）。
  → **每次「改文件 → 跑测试」之间先 `Start-Sleep -Seconds 2`**，否则拿到的是假红/假绿，据此下的结论全是错的。
- **守卫哲学**：
  - **行为腿 > 文本腿**。能用"跑一次拿返回值"证明的，不许用"读源码找字符串"证明。
  - **生成式清单 > 手写清单**。凡"必须齐全"的集合（A 类钩子、卡面数量、导出点、`RENDERERS`）一律**从磁盘/源码派生**，不得在测试里手写一份副本（本仓已因手写副本栽过两次，见 `tests/ui/source-text.ts:1-12`）。
  - **每条新守卫都要变异实测**：注入缺陷 ⇒ 变红 ⇒ 还原。计划里每个任务都写明了"怎么注入变异"。
  - **不许为了让门禁变绿而放宽/删除判据**。判据红了就改实现，不改判据。
- **既有红线文件的改动必须单独说明理由**：`src/ui/styles.css`（382 KB）、`src/ui/render.ts`（327 KB）、`src/ui/effects/index.ts`（157 KB）、`src/ui/styles-net.css` 在 G3 **一行都不改**（G3 只需一个新 CSS 文件 `src/ui/styles-local.css`）。**若某任务认为非改不可，先停下来报告**，不要在任务内偷偷改。
- **无头浏览器（用户已授权）**：
  - 只用于"静态解算看不见浏览器"的那类自查（Service Worker 注册、`localStorage` 真的写了/真的没写、`<a download>` 真的产生了文件）。
  - **只在备用端口起临时服务**（例如 `npx vite preview --port 4173` / `npx vite --port 5199`）；**绝不碰用户的 5173、也绝不碰 DSH 的 3080**。
  - **收工杀干净**（`job_kill` / 显式 `Stop-Process`，确认端口已释放）。
  - 探针与截图一律放 `.superpowers/` 下（`.gitignore:3` 已忽略），**不得**产生仓库内的临时文件。
  - 无头浏览器**不得**作为门禁的一部分（不得进 vitest）；它只是人（或代理）的一次性自查手段。
- **提交规范**：`git add src tests docs public`（**不要** `git add -A`，不要提交 `dist/`、不要提交 `.superpowers/`）；中文提交信息、多个 `-m`；**不推送**，**不 `git commit` 由规划者执行**（本文件作者未提交任何东西）。

**设计要点（务必理解，不要改动）**
1. **`setup` 比设计稿 §3.1 多两个字段**：`draftPicks: string[]` 与 `bannedProtocols: string[]`。理由（**可验证**）：设计稿的 `setup.draftPool: string[]` 是"本局可选协议池"，它是**集合**不是序列；而 `GameState.draftPicks` 是**按选择顺序**的数组（`types.ts:334`），`bannedProtocols` 也是**按禁用顺序**（`types.ts:344`）。少了这两个快照，**ban 模式的档案无法完整重放**（分不清谁能选什么、哪几张是禁的）。这是"补齐 §3.1 的缺口"，不是"改需求"——见"待用户裁决 #1"。
2. **`args` 的校验按 kind 收窄**：`play` 必须有 `cardUid`/`faceUp`；`compile` 必须有 `line`；`effect-choice` 必须有 `promptId`/`choice`；`resolve-trigger` 必须有 `cardUid`；`rearrange-protocols` 必须有 `target`/`a`/`b`；`refresh`/`advance`/`clear-cache` **不得**带 args。
3. **`createdAt` 只展示、不进指纹**：`matchFileFingerprint` 先把 `createdAt` 置为固定串（`''`）再算 —— 否则"同一局导出两次"指纹会不同，G4 的"重放后指纹 == 原局指纹"就没法比。设计稿 §3.1 的注释（`createdAt: string; // 仅展示用，**不进指纹**`）就是这个意思。
4. **`via` 不进引擎状态**：`normalizeAction` **只**保留 `via` 字段、**不**把它塞进 `args`；`matchFileToCreateOptions` 完全不看它。设计稿 §3.1 注释与 §14.2 都明写"档案层元数据，不进引擎状态"。
5. **迁移链骨架**：`version === 1` 直接过；`version > 1` → 报 `too-new`（**不猜测**，§3.3 第 2 条）；`version < 1` → 报 `bad-version-type`（v1 是首版，没有更早的版本）。**`MIGRATIONS` 是一张空表 + 一条"表必须在 version 升版时同步增长"的行为腿**，而不是等将来再补。

```ts
/**
 * 档案格式 MatchFile（G3；见 docs/2026-09-13-联机与多端-设计稿.md §3，全节）。
 *
 * 一份数据，五处复用（§3.2）：存档 / 录像 / 断线重连凭据 / 联机传输内容 / 观战中途加入。
 * 因此这里**只有纯数据与纯函数**：无 DOM、无存储、无网络 —— 联机与浏览器能力都不该渗进来。
 *
 * 与设计稿 §3.1 的**唯一差异**：`setup` 多了 `draftPicks` / `bannedProtocols` 两个**顺序快照**。
 * 理由见 setup 字段的注释（缺它 ban 模式无法完整重放）。
 */
import type { CreateGameOptions } from '../core/state/create';
import type { ActionKind } from '../core/game';
import type { PlayerId } from '../core/models/types';
import { hash64, stableStringify } from '../core/fingerprint';
import { getProtocolDef } from '../data/demo';

export const MATCH_FILE_FORMAT = 'compile-match';
export const MATCH_FILE_VERSION = 1;

/** §3.1：`via` 是**档案层元数据，不进引擎状态**（§3.1 注释、§14.2） */
export interface ActionRecord {
  /** 单调递增，从 0 开始 */
  seq: number;
  /** 执行者座位 */
  player: PlayerId;
  kind: ActionKind;
  /** 随 kind 收窄 */
  args?: unknown;
  /** user = 玩家操作；timeout = 决策窗口超时自动合成；ai = 本地 AI 产生 */
  via?: 'user' | 'timeout' | 'ai';
}

export interface MatchClock {
  decisionSec: number;
  draftSec: number;
  /** 免罚跳过额度，默认 2（§14.3） */
  maxSkips: number;
}

export interface MatchFileSetup {
  draftMode: 'normal' | 'ban';
  draftStarter: PlayerId;
  firstToPlay: PlayerId;
  /** 开局可选协议池（defId 列表） */
  draftPool: string[];
  /**
   * **顺序快照**（相对 §3.1 的补齐）：草稿实际选出的协议，按选择顺序。
   * `draftPool` 是集合、`draftPicks` 是序列 —— 少了序列，ban 模式（选/禁交错）无法重放。
   */
  draftPicks: string[];
  /** **顺序快照**：被禁用的协议 defId，按禁用顺序（§3.1 的 setup 未含此字段） */
  bannedProtocols: string[];
  /** 回合计时配置（§14.5）；缺省 = 不启用计时。**G6 才用**，G3 只透传 */
  clock?: MatchClock;
}

export interface MatchFile {
  format: typeof MATCH_FILE_FORMAT;
  version: typeof MATCH_FILE_VERSION;
  /** 卡牌数据指纹（§3.4） */
  cardDataHash: string;
  seed: string;
  setup: MatchFileSetup;
  players: [{ nick: string }, { nick: string }];
  actions: ActionRecord[];
  result?: { winner: PlayerId | null; reason: string };
  /** 仅展示用，**不进指纹**（§3.1） */
  createdAt: string;
}

/** 档案指纹里 `createdAt` 的占位：算指纹前把它替换成这个常量 */
const CREATED_AT_OMITTED = '';

/* ------------------------------------------------------------------ *
 * 校验错误
 * ------------------------------------------------------------------ */

export type MatchFileErrorCode =
  | 'not-json'
  | 'not-a-match-file'
  | 'bad-version-type'
  | 'too-new'
  | 'bad-shape'
  | 'bad-action'
  | 'hash-mismatch-unknown';

export interface MatchFileParseError {
  code: MatchFileErrorCode;
  message: string;
}

/* ------------------------------------------------------------------ *
 * 规范化
 * ------------------------------------------------------------------ */

const VIA_VALUES: readonly ActionRecord['via'][] = ['user', 'timeout', 'ai'];

/**
 * 单条操作规范化：写进档案的形态只有一种。
 * - `via` 只保留三个已知值（未知值丢弃，而不是原样写进档案）；
 * - `args` 为 undefined 时**删掉该键**（与 JSON.stringify 语义一致，也让指纹稳定）。
 */
export function normalizeAction(a: ActionRecord): ActionRecord {
  const out: ActionRecord = { seq: a.seq, player: a.player, kind: a.kind };
  if (a.args !== undefined) out.args = a.args;
  if (a.via !== undefined && VIA_VALUES.includes(a.via)) out.via = a.via;
  return out;
}

/** 档案规范化：actions 逐条规范化（顺序不动 —— **顺序就是语义**） */
export function canonicalMatchFile(f: MatchFile): MatchFile {
  const out: MatchFile = {
    format: MATCH_FILE_FORMAT,
    version: MATCH_FILE_VERSION,
    cardDataHash: f.cardDataHash,
    seed: f.seed,
    setup: {
      draftMode: f.setup.draftMode,
      draftStarter: f.setup.draftStarter,
      firstToPlay: f.setup.firstToPlay,
      draftPool: [...f.setup.draftPool],
      draftPicks: [...f.setup.draftPicks],
      bannedProtocols: [...f.setup.bannedProtocols],
      ...(f.setup.clock ? { clock: { ...f.setup.clock } } : {}),
    },
    players: [{ nick: f.players[0].nick }, { nick: f.players[1].nick }],
    actions: f.actions.map(normalizeAction),
    ...(f.result ? { result: { winner: f.result.winner, reason: f.result.reason } } : {}),
    createdAt: f.createdAt,
  };
  return out;
}

/** 落盘/传输用：稳定序列化（键排序）→ 同一份数据字节相同 */
export function stringifyMatchFile(f: MatchFile): string {
  return JSON.stringify(canonicalMatchFile(f));
}

/** 档案指纹：不含 createdAt（同一局导出两次必须同指纹） */
export function matchFileFingerprint(f: MatchFile): string {
  const c = canonicalMatchFile(f);
  return hash64(stableStringify({ ...c, createdAt: CREATED_AT_OMITTED }));
}

/* ------------------------------------------------------------------ *
 * 校验
 * ------------------------------------------------------------------ */

const KINDS: readonly ActionKind[] = [
  'play', 'refresh', 'compile', 'advance', 'effect-choice', 'resolve-trigger', 'clear-cache', 'rearrange-protocols',
];

/** 该 kind 的 args 必须含有的键；空数组 = 必须**不带** args */
const ARGS_REQUIRED: Record<ActionKind, readonly string[]> = {
  play: ['cardUid', 'faceUp'],
  compile: ['line'],
  'effect-choice': ['promptId', 'choice'],
  'resolve-trigger': ['cardUid'],
  'rearrange-protocols': ['target', 'a', 'b'],
  refresh: [],
  advance: [],
  'clear-cache': [],
};

function isPlayerId(v: unknown): v is PlayerId {
  return v === 0 || v === 1;
}

function isObj(v: unknown): v is Record<string, unknown> {
  return typeof v === 'object' && v !== null && !Array.isArray(v);
}

function isStrArray(v: unknown): v is string[] {
  return Array.isArray(v) && v.every((x) => typeof x === 'string');
}

function checkAction(a: unknown, i: number): MatchFileParseError | null {
  if (!isObj(a)) return { code: 'bad-action', message: `第 ${i} 条操作不是对象` };
  if (typeof a.seq !== 'number' || !Number.isInteger(a.seq) || a.seq < 0) {
    return { code: 'bad-action', message: `第 ${i} 条操作的 seq 不是非负整数` };
  }
  if (!isPlayerId(a.player)) return { code: 'bad-action', message: `第 ${i} 条操作的 player 不是 0/1` };
  if (typeof a.kind !== 'string' || !KINDS.includes(a.kind as ActionKind)) {
    return { code: 'bad-action', message: `第 ${i} 条操作的 kind 未知：${String(a.kind)}` };
  }
  const need = ARGS_REQUIRED[a.kind as ActionKind];
  const args = a.args;
  if (need.length === 0) {
    if (args !== undefined) return { code: 'bad-action', message: `第 ${i} 条 ${a.kind} 不该带 args` };
    return null;
  }
  if (!isObj(args)) return { code: 'bad-action', message: `第 ${i} 条 ${a.kind} 缺 args` };
  for (const k of need) {
    if (args[k] === undefined) return { code: 'bad-action', message: `第 ${i} 条 ${a.kind} 的 args 缺 ${k}` };
  }
  return null;
}

function checkSetup(v: unknown): MatchFileParseError | null {
  if (!isObj(v)) return { code: 'bad-shape', message: 'setup 不是对象' };
  if (v.draftMode !== 'normal' && v.draftMode !== 'ban') return { code: 'bad-shape', message: 'setup.draftMode 非法' };
  if (!isPlayerId(v.draftStarter)) return { code: 'bad-shape', message: 'setup.draftStarter 非法' };
  if (!isPlayerId(v.firstToPlay)) return { code: 'bad-shape', message: 'setup.firstToPlay 非法' };
  if (!isStrArray(v.draftPool)) return { code: 'bad-shape', message: 'setup.draftPool 非法' };
  if (!isStrArray(v.draftPicks)) return { code: 'bad-shape', message: 'setup.draftPicks 非法' };
  if (!isStrArray(v.bannedProtocols)) return { code: 'bad-shape', message: 'setup.bannedProtocols 非法' };
  if (v.clock !== undefined) {
    if (!isObj(v.clock)) return { code: 'bad-shape', message: 'setup.clock 非法' };
    for (const k of ['decisionSec', 'draftSec', 'maxSkips'] as const) {
      if (typeof v.clock[k] !== 'number') return { code: 'bad-shape', message: `setup.clock.${k} 非法` };
    }
  }
  return null;
}

function checkPlayers(v: unknown): MatchFileParseError | null {
  if (!Array.isArray(v) || v.length !== 2) return { code: 'bad-shape', message: 'players 必须是长度 2 的数组' };
  for (let i = 0; i < 2; i += 1) {
    const p = v[i];
    if (!isObj(p) || typeof p.nick !== 'string') return { code: 'bad-shape', message: `players[${i}].nick 非法` };
  }
  return null;
}

/* ------------------------------------------------------------------ *
 * 版本迁移链（§3.3）
 * ------------------------------------------------------------------ */

/**
 * 迁移链：`MIGRATIONS[n]` 把 v(n) 升到 v(n+1)。**v1 是首版，故为空表。**
 *
 * 行为腿（见 Step 5）：当 `MATCH_FILE_VERSION` 增长而本表没有对应项时，
 * `parseMatchFile` 必须**报 too-new 而不是静默吞掉**。这条腿的作用是：
 * 谁把版本号从 1 改成 2 而忘了写迁移，测试当场红。
 */
const MIGRATIONS: Record<number, (raw: Record<string, unknown>) => Record<string, unknown>> = {};

function migrate(raw: Record<string, unknown>): Record<string, unknown> | { error: MatchFileParseError } {
  let v = raw.version as number;
  if (!Number.isInteger(v) || v < 1) {
    return { error: { code: 'bad-version-type', message: `档案 version 非法：${String(raw.version)}` } };
  }
  if (v > MATCH_FILE_VERSION) {
    return {
      error: {
        code: 'too-new',
        message: `档案来自更新版本的游戏（档案 v${v}，当前支持 v${MATCH_FILE_VERSION}）。请更新游戏，本程序不会猜测如何读取它。`,
      },
    };
  }
  let cur = raw;
  while (v < MATCH_FILE_VERSION) {
    const step = MIGRATIONS[v];
    if (!step) {
      // 到不了（v < 当前且无迁移项 = 版本表与迁移链不同步）
      return { error: { code: 'too-new', message: `缺少 v${v} → v${v + 1} 的迁移步骤` } };
    }
    cur = step(cur);
    v += 1;
  }
  return cur;
}

/* ------------------------------------------------------------------ *
 * 解析入口
 * ------------------------------------------------------------------ */

export type MatchFileParseResult =
  | { ok: true; file: MatchFile; warnings: string[] }
  | { ok: false; error: MatchFileParseError };

/**
 * 解析一份档案。
 * - `opts.currentHash` = 本机 `CARD_DATA_HASH`；不同则**仍成功**但带一条警告（§3.3 第 3 条：
 *   "警告并允许仍要打开"，联机时的**拒绝**在 G5 的握手里做）。
 */
export function parseMatchFile(text: string, opts: { currentHash: string }): MatchFileParseResult {
  let raw: unknown;
  try {
    raw = JSON.parse(text);
  } catch {
    return { ok: false, error: { code: 'not-json', message: '档案不是合法 JSON（文件可能已损坏）' } };
  }
  if (!isObj(raw)) return { ok: false, error: { code: 'not-a-match-file', message: '档案顶层不是对象' } };
  if (raw.format !== MATCH_FILE_FORMAT) {
    return { ok: false, error: { code: 'not-a-match-file', message: `不是 Compile 对局档案（format=${String(raw.format)}）` } };
  }
  const migrated = migrate(raw);
  if ('error' in migrated) return { ok: false, error: migrated.error };
  const m = migrated;

  if (typeof m.seed !== 'string' || m.seed.length === 0) {
    return { ok: false, error: { code: 'bad-shape', message: 'seed 非法' } };
  }
  if (typeof m.cardDataHash !== 'string') {
    return { ok: false, error: { code: 'bad-shape', message: 'cardDataHash 非法' } };
  }
  const setupErr = checkSetup(m.setup);
  if (setupErr) return { ok: false, error: setupErr };
  const playersErr = checkPlayers(m.players);
  if (playersErr) return { ok: false, error: playersErr };
  if (!Array.isArray(m.actions)) return { ok: false, error: { code: 'bad-shape', message: 'actions 不是数组' } };
  for (let i = 0; i < m.actions.length; i += 1) {
    const err = checkAction(m.actions[i], i);
    if (err) return { ok: false, error: err };
  }

  const warnings: string[] = [];
  if (m.cardDataHash !== opts.currentHash) {
    warnings.push(
      `卡牌数据与本机不同（档案 ${m.cardDataHash}，本机 ${opts.currentHash}）：同一串操作可能得到不同结果。可以继续打开，但联机时会被拒绝。`,
    );
  }

  const file = canonicalMatchFile(m as unknown as MatchFile);
  return { ok: true, file, warnings };
}

/* ------------------------------------------------------------------ *
 * 档案 → 开局
 * ------------------------------------------------------------------ */

/**
 * 把档案的 setup 映射成 `createGame` 的入参。
 *
 * **这是 G4 的 `ReplayDriver` 的唯一开局入口**（本阶段不实现重放）：
 * 五个确定性输入（seed / draftStarter / firstToPlay / draftMode / draftPool）一个不少 —— §2.5。
 * 未知 defId **抛错**而不是跳过：静默跳过会让重放从第一步就与档案错位。
 */
export function matchFileToCreateOptions(f: MatchFile): CreateGameOptions {
  const draftPool = f.setup.draftPool.map((defId) => {
    try {
      return getProtocolDef(defId);
    } catch {
      throw new Error(`档案里的协议 defId 在本机不存在：${defId}（卡牌数据版本不一致？）`);
    }
  });
  return {
    seed: f.seed,
    draftStarter: f.setup.draftStarter,
    firstToPlay: f.setup.firstToPlay,
    draftMode: f.setup.draftMode,
    draftPool,
  };
}

/** 从 `GameState` 抽取 setup（顺序快照逐项照录） */
export function setupFromState(s: {
  draftMode: 'normal' | 'ban';
  draftStarter: PlayerId;
  firstToPlay: PlayerId;
  draftPool: { defId: string }[];
  draftPicks: { defId: string }[];
  bannedProtocols: string[];
}): MatchFileSetup {
  return {
    draftMode: s.draftMode,
    draftStarter: s.draftStarter,
    firstToPlay: s.firstToPlay,
    draftPool: s.draftPool.map((p) => p.defId),
    draftPicks: s.draftPicks.map((p) => p.defId),
    bannedProtocols: [...s.bannedProtocols],
  };
}

/* ------------------------------------------------------------------ *
 * 记录器（内存；G4 接进 driver 后即成为"联机传输内容/重连凭据"）
 * ------------------------------------------------------------------ */

export interface MatchFileMeta {
  seed: string;
  setup: MatchFileSetup;
  players: [{ nick: string }, { nick: string }];
  cardDataHash: string;
  createdAt: string;
  result?: { winner: PlayerId | null; reason: string };
}

export interface MatchFileRecorder {
  /** 下一个可用 seq（**只读**：不推进） */
  nextSeq(): number;
  /** 记录一条"正经产生"的操作（玩家点出来的 / 会话层合成的） */
  record(a: Omit<ActionRecord, 'seq'>): void;
  /**
   * 记录一条**旁路**操作（诊断/开发者模式）。它**不进 actions** —— 进了会让重放出来的
   * 对局与真实对局不同（`main.ts` 有直呼 `executeAction` 的旁路：devmode 加牌、效果内重排
   * 提交等）。但**必须留痕**（`noted()`），否则"档案为什么复现不出来"会变成无法调试的问题。
   */
  note(a: Omit<ActionRecord, 'seq'>): void;
  noted(): readonly ActionRecord[];
  actions(): readonly ActionRecord[];
  clear(): void;
  toMatchFile(meta: MatchFileMeta): MatchFile;
}

export function createMatchFileRecorder(): MatchFileRecorder {
  const list: ActionRecord[] = [];
  const notes: ActionRecord[] = [];
  return {
    nextSeq: () => list.length,
    record(a) {
      list.push(normalizeAction({ ...a, seq: list.length }));
    },
    note(a) {
      notes.push(normalizeAction({ ...a, seq: notes.length }));
    },
    noted: () => notes.slice(),
    actions: () => list.slice(),
    clear() {
      list.length = 0;
      notes.length = 0;
    },
    toMatchFile(meta) {
      return canonicalMatchFile({
        format: MATCH_FILE_FORMAT,
        version: MATCH_FILE_VERSION,
        cardDataHash: meta.cardDataHash,
        seed: meta.seed,
        setup: meta.setup,
        players: meta.players,
        actions: list.slice(),
        ...(meta.result ? { result: meta.result } : {}),
        createdAt: meta.createdAt,
      });
```

```ts
/**
 * 卡牌数据指纹（G3；见 docs/2026-09-13-联机与多端-设计稿.md §3.4）。
 *
 * 用途：防止两台设备卡牌数据版本不同导致**规则分歧** —— 设计稿称它是"联机最容易被忽略、
 * 后果最严重的一类 bug"。联机握手时用它做互斥校验（§5.2 第 2 条，G5 消费）。
 *
 * 为什么**不是**构建期生成的文件：本仓零运行时依赖、且 `vite.config.ts` 只有 `test` 段，
 * 加一个"构建期生成 TS 常量"的步骤要么改构建配置、要么多一个可能失败的构建阶段。
 * 运行期现算一遍（约 90KB 字符串的 FNV-1a）在模块首次求值时一次完成，**零漂移风险**。
 * `CARD_DATA_HASH` 一旦与现算值不符，`tests/app/card-data-hash.test.ts` 第 1 条当场红。
 */
import type { CardDef, ProtocolDef } from '../core/models/types';
import { hash32 } from '../core/rng';
import { DEMO_CARD_DEFS, DEMO_PROTOCOLS } from '../data/demo';

/** FNV-1a 32 位拼两段 → 16 位十六进制（与 core/fingerprint.ts 的 hash64 同规格） */
function pairHash(text: string): string {
  const a = hash32(text);
  const b = hash32(`${text}#${a}`);
  return a.toString(16).padStart(8, '0') + b.toString(16).padStart(8, '0');
}

/**
 * 卡牌数据指纹。
 *
 * **纳入**（影响规则/结算）：卡的 defId/protocol/value/top/middle/bottom；协议的 defId/commands。
 * **排除**（纯展示，纳入只会制造假不匹配）：name、loadingText、PROTOCOL_RATINGS、卡图路径。
 * **顺序无关**：先按 defId 排序再拼串（三代并池顺序会随数据文件增删变化）。
 */
export function cardDataHashOf(cards: readonly CardDef[], protocols: readonly ProtocolDef[]): string {
  const cardLines = [...cards]
    .sort((a, b) => (a.defId < b.defId ? -1 : a.defId > b.defId ? 1 : 0))
    .map((c) => ['C', c.defId, c.protocol, String(c.value), c.top ?? '', c.middle ?? '', c.bottom ?? ''].join('\u001f'));
  const protoLines = [...protocols]
    .sort((a, b) => (a.defId < b.defId ? -1 : a.defId > b.defId ? 1 : 0))
    .map((p) => ['P', p.defId, p.commands.join('/')].join('\u001f'));
  return pairHash(`compile-carddata-v1\n${[...protoLines, ...cardLines].join('\n')}`);
}

/** 本机卡牌数据指纹（模块顶层求值一次） */
export const CARD_DATA_HASH: string = cardDataHashOf(DEMO_CARD_DEFS, DEMO_PROTOCOLS);
```

**设计要点（务必理解，不要改动）**
1. **"零写入"必须是可证伪的行为**：`createLocalStore({ persistent: fakeKv })` 在 `deny()` 之后，`fakeKv` 的 `set` 调用次数必须**恒为 0**（游客模式走 `createMemoryStore()`，与 `fakeKv` 完全解耦）。这是 §0.4 红线 3 的机检形态。
2. **授权状态本身不能写盘**（否则违反红线 3）：`consent` 只存在闭包变量里。刷新后回到 `'unknown'` ⇒ `main.ts` 会**重新问**（§3.6 的"拒绝后本次会话内不再询问，下次进入重新问"）。
3. **`'ask'` 这个状态存在的原因是"弹窗已显示、等用户点"**：`main.ts` 的启动逻辑是 `unknown → ask（渲染弹窗）→ allowed/denied`。不要在 `unknown` 时就写任何东西。
4. **降级**：`set` 抛错（隐私模式 / 配额满）时 `writeJson` 返回 `{ ok: false, reason: 'write-failed' }` 并**不抛**；调用方（Task 7 的 UI）显示"本机保存失败，本次会话仍可正常游玩"。
5. **`indexedDB` 的角色**：设计稿 §3.7 说"句柄存 IndexedDB，需同一授权"指的是 **L2 的文件句柄**（浏览器 FSA 的 `FileSystemFileHandle` **只能**存 IndexedDB，不能存 localStorage）。本任务只给出 `AsyncKeyValueStore` 接口与 `indexedDB` 的能力探测骨架；**真正的句柄存取在 Task 7**（且**只在用户裁决要做"静默写回"时**才实现 —— 见"待用户裁决 #4"）。
6. **容量上限**：单个值 64 KiB（`L1_VALUE_MAX_BYTES`），写入前用 `value.length` 粗判（UTF-16 码元数 ≥ 字节数是保守安全方向：中文一个字 3 字节，按码元判会**低估** → 所以用 `new TextEncoder()` 算真实字节数；`TextEncoder` 在 node 与浏览器都有，**不需要**注入）。

```ts
/**
 * L1 轻量配置的**存储抽象**（G3；见 docs/2026-09-13-联机与多端-设计稿.md §3.5、§3.6）。
 *
 * 三层分工，别混：
 *  - 本文件：**接口 + 纯逻辑**（无浏览器 API）。因此可在 node 下直接单测（本仓无 jsdom）。
 *  - `src/ui/local-store-browser.ts`：浏览器实现（localStorage 主 + indexedDB 从 + 能力探测）。
 *  - `src/app/local-store.ts`：授权状态机与数据模型（也是纯逻辑）。
 *
 * 红线 3（§0.4）：游客模式下**零写入磁盘**。它的机检形态就是本文件里的
 * `createLocalStore({ persistent })` + `deny()` ⇒ `persistent.set` 调用次数恒 0。
 */

export interface KeyValueStore {
  get(key: string): string | null;
  set(key: string, value: string): void;
  remove(key: string): void;
  keys(): string[];
}

/** 异步 KV：IndexedDB 的形态（仅供 L2 的文件句柄等浏览器对象使用） */
export interface AsyncKeyValueStore {
  get(key: string): Promise<string | null>;
  set(key: string, value: string): Promise<void>;
  remove(key: string): Promise<void>;
  keys(): Promise<string[]>;
}

/** 带名字的存储后端（"indexeddb 优先，localStorage 兜底"的探测单位） */
export interface NamedStore {
  name: string;
  kv: KeyValueStore;
}

/** L1 的键（**键名一旦发布就不能改** —— 改了等于让所有老用户丢配置） */
export const L1_SETTINGS = 'compile-settings';
export const L1_DECKS = 'compile-decks';
/** 单值上限（64 KiB）：L1 是"轻量、随时可丢"的偏好层，不是档案层（§3.5） */
export const L1_VALUE_MAX_BYTES = 65536;

/** 内存 KV：游客模式与测试共用同一份实现（**一份实现，不是两份拷贝**） */
export function createMemoryStore(): KeyValueStore {
  const m = new Map<string, string>();
  return {
    get: (k) => (m.has(k) ? (m.get(k) as string) : null),
    set: (k, v) => { m.set(k, v); },
    remove: (k) => { m.delete(k); },
    keys: () => [...m.keys()],
  };
}

/**
 * 按优先级探测可用后端：`get`/`set` 各真跑一次探针（不能只看 `'indexedDB' in globalThis`
 * —— Safari 隐私模式下对象存在但一用就抛）。全部不可用 → **抛错**（调用方负责降级成 null）。
 */
export function pickNamedStore(stores: readonly NamedStore[]): NamedStore {
  const probeKey = '__compile_probe__';
  for (const s of stores) {
    try {
      s.kv.set(probeKey, '1');
      s.kv.get(probeKey);
      s.kv.remove(probeKey);
      return s;
    } catch {
      // 试下一个
    }
  }
  throw new Error('没有可用的本地存储后端');
}

function utf8Bytes(v: string): number {
  // TextEncoder 在 node(>=11) 与全部目标浏览器都有；不需要注入
  return new TextEncoder().encode(v).length;
}

export function readJson<T>(kv: KeyValueStore, key: string, fallback: T): T {
  const raw = kv.get(key);
  if (raw === null) return fallback;
  try {
    return JSON.parse(raw) as T;
  } catch {
    return fallback; // 坏数据不该让游戏打不开
  }
}

export type WriteResult = { ok: true } | { ok: false; reason: 'too-large' | 'write-failed'; detail: string };

export function writeJson(kv: KeyValueStore, key: string, value: unknown): WriteResult {
  let text: string;
  try {
    text = JSON.stringify(value);
  } catch (e) {
    return { ok: false, reason: 'write-failed', detail: `无法序列化：${String(e)}` };
  }
  const bytes = utf8Bytes(text);
  if (bytes > L1_VALUE_MAX_BYTES) {
    return { ok: false, reason: 'too-large', detail: `${bytes} 字节 > 上限 ${L1_VALUE_MAX_BYTES} 字节` };
  }
  try {
    kv.set(key, text);
  } catch (e) {
    return { ok: false, reason: 'write-failed', detail: `写入本机存储失败（隐私模式或配额已满）：${String(e)}` };
  }
  return { ok: true };
}

/** 清掉 L1 自己的全部键（不动别人的键）；返回清掉的个数 */
export function clearAllLocalData(kv: KeyValueStore): number {
  const mine = [L1_SETTINGS, L1_DECKS];
  let n = 0;
  for (const k of mine) {
    if (kv.get(k) !== null) { kv.remove(k); n += 1; }
  }
  return n;
}
```

```ts
/**
 * L1 数据模型与**授权状态机**（G3；见 §3.5、§3.6）。
 *
 * 关键不变式（红线的机检形态）：
 *  1. `consent === 'denied'`（游客模式）⇒ 任何写入都不碰 persistent（走内存 KV）；
 *  2. **授权状态本身从不落盘** —— 它只活在闭包里，刷新即回 'unknown'，于是"下次进入重新问"；
 *  3. persistent 不可用（null）时**功能仍可用**，只是全部退化到内存。
 */
import {
  L1_DECKS,
  L1_SETTINGS,
  createMemoryStore,
  readJson,
  writeJson,
  type KeyValueStore,
} from './storage';

export type ConsentState = 'unknown' | 'ask' | 'allowed' | 'denied';

export interface LocalStore {
  consent(): ConsentState;
  /** 弹窗已显示，等用户点（`unknown → ask`） */
  ask(): void;
  grant(): void;
  deny(): void;
  /** 回 unknown（"清除本机数据"后调用；授权状态不落盘，故只改内存） */
  reset(): void;
  /** 当前**实际**使用的 KV：游客模式 = 内存 KV，用户模式 = persistent */
  kv(): KeyValueStore;
  /** 是否有真正的持久化后端（游客模式恒 false） */
  isPersistent(): boolean;
}

export function createLocalStore(opts: { persistent: KeyValueStore | null }): LocalStore {
  const memory = createMemoryStore();
  let consent: ConsentState = 'unknown';
  const usingPersistent = (): boolean => consent === 'allowed' && opts.persistent !== null;
  return {
    consent: () => consent,
    ask: () => { if (consent === 'unknown') consent = 'ask'; },
    grant: () => { consent = 'allowed'; },
    deny: () => { consent = 'denied'; },
    reset: () => { consent = 'unknown'; },
    kv: () => (usingPersistent() ? (opts.persistent as KeyValueStore) : memory),
    isPersistent: usingPersistent,
  };
}

export interface DeckRecord {
  id: string;
  name: string;
  /** 卡组绑定的种子（同一卡组可复用于多局；重放时仍需整份 MatchFile） */
  seed: string;
  defIds: string[];
  updatedAt: string;
}

/* ---------------- L1 数据模型 ---------------- */

export interface L1Settings {
  nick: string;
}

export function readNickName(store: LocalStore): string {
  const s = readJson<Partial<L1Settings>>(store.kv(), L1_SETTINGS, {});
  return typeof s.nick === 'string' ? s.nick : '';
}

export function writeNickName(store: LocalStore, nick: string): boolean {
  const prev = readJson<Partial<L1Settings>>(store.kv(), L1_SETTINGS, {});
  return writeJson(store.kv(), L1_SETTINGS, { ...prev, nick }).ok;
}

function isDeckRecord(v: unknown): v is DeckRecord {
  if (typeof v !== 'object' || v === null) return false;
  const d = v as Record<string, unknown>;
  return typeof d.id === 'string'
    && typeof d.name === 'string'
    && typeof d.seed === 'string'
    && Array.isArray(d.defIds) && d.defIds.every((x) => typeof x === 'string')
    && typeof d.updatedAt === 'string';
}

export function readDecks(store: LocalStore): DeckRecord[] {
  const raw = readJson<unknown>(store.kv(), L1_DECKS, []);
  if (!Array.isArray(raw)) return [];
  return raw.filter(isDeckRecord);
}

export function writeDecks(store: LocalStore, decks: readonly DeckRecord[]): boolean {
  return writeJson(store.kv(), L1_DECKS, decks.filter(isDeckRecord)).ok;
}
```

```ts
/**
 * L1 存储的**浏览器实现**（G3）。放在 `src/ui/` 的原因：它是唯一允许碰 localStorage/IndexedDB
 * 的地方（`src/app/` 保持零浏览器 API，见 tests/app-purity.test.ts）。
 *
 * 探测顺序（§3.5）：IndexedDB 优先，localStorage 兜底。
 * ⚠️ 本文件里的探测**必须真存取一次**：Safari 隐私模式下 localStorage 对象存在但 setItem 抛错。
 */
import { createMemoryStore, pickNamedStore, type KeyValueStore, type NamedStore } from '../app/storage';

function localStorageBackend(): NamedStore | null {
  try {
    const ls = globalThis.localStorage;
    if (!ls) return null;
    const kv: KeyValueStore = {
      get: (k) => ls.getItem(k),
      set: (k, v) => { ls.setItem(k, v); },
      remove: (k) => { ls.removeItem(k); },
      keys: () => {
        const out: string[] = [];
        for (let i = 0; i < ls.length; i += 1) {
          const k = ls.key(i);
          if (k !== null) out.push(k);
        }
        return out;
      },
    };
    return { name: 'localstorage', kv };
  } catch {
    return null;
  }
}

/**
 * 取本机可用的 L1 后端。**任何异常都不外抛** —— 存储不可用不是致命错误，
 * 只是"本次会话不能保存"（设计稿 §9 的"存储授权被拒 → 游客模式，全部功能可用但刷新即丢"）。
 *
 * ⚠️ IndexedDB 后端留到 Task 7：它只在"用户裁决要做静默写回文件句柄"时才需要
 * （`FileSystemFileHandle` **只能**存 IndexedDB）。本任务只保证 localStorage 与内存两条路。
 */
export function openL1Store(): KeyValueStore | null {
  const candidates = [localStorageBackend()].filter((x): x is NamedStore => x !== null);
  if (candidates.length === 0) return null;
  try {
    return pickNamedStore(candidates).kv;
  } catch {
    return null;
  }
}

/** 显式的内存兜底（测试与无头浏览器自查用） */
```

```ts
/** 纯 reducer（与 main.ts 的 LocalStore 保持一致；放在这里是为了能被单测直接跑） */
export function nextConsentStep(s: ConsentState, action: 'show' | 'grant' | 'deny' | 'reset'): ConsentState {
  switch (action) {
    case 'show': return s === 'unknown' ? 'ask' : s;
    case 'grant': return 'allowed';
    case 'deny': return 'denied';
    case 'reset': return 'unknown';
  }

    p.textContent = line;
    body.appendChild(p);
  }

  hint.textContent = CONSENT_COPY.denyHint;
```

  - `interface FileSink { save(opts: { suggestedName: string; text: string }): Promise<{ ok: true; name: string; mode: 'fsa' | 'download' } | { ok: false; reason: 'cancelled' | 'unsupported' | 'failed'; detail: string }> }`

**设计要点（务必理解，不要改动）**
1. **导入的四个前置判据全部在纯逻辑里**（可机检）：空串 → `empty`；超过 `MAX_ARCHIVE_BYTES` → `too-large`；读文件失败 → `read-failed`；解析失败 → 透传 `parseMatchFile` 的 `code`（含 `too-new` 与 `bad-action`）。
2. **冲突策略默认 `keep-both`**（同名档案已存在时自动加 `-2`/`-3` 后缀）：**不覆盖**是安全默认（红线 1 的精神：用户的数据只增不减）。`overwrite` 必须由用户显式选择。
3. **`FileSink` 的降级顺序**（§3.7）：FSA 的 `showSaveFilePicker` 存在且可用 → `mode: 'fsa'`，否则 `<a download>` → `mode: 'download'`；**用户取消**必须返回 `cancelled` 而不是 `failed`（否则 UI 会弹"保存失败"，那是假警报）。
4. **`FilePicker` 的降级顺序**：`showOpenFilePicker` → `<input type="file">`；两者都不可用（例如某些 WebView）→ 返回 `null`（UI 显示"这台设备不支持导入档案"）。
5. **`size` 必须先判再读**：`text()` 之前用 `PickedFile.size` 挡掉超大文件（否则大文件会把内存打满）。

```ts
export const MAX_ARCHIVE_BYTES = 8 * 1024 * 1024;

export function archiveFileName(f: MatchFile): string {
  const stamp = f.createdAt.replace(/[-:]/g, '').replace(/\..*$/, '').replace('T', '-');
  return `compile-${f.seed.slice(0, 8)}-${stamp}.compile-match.json`;
}

export function exportArchive(f: MatchFile): { name: string; text: string } {
  return { name: archiveFileName(f), text: stringifyMatchFile(f) };
}

export function importArchive(text: string, opts: { currentHash: string }): ImportOutcome {
  if (text.trim().length === 0) return { ok: false, code: 'empty', message: '档案文件是空的' };
  // 字节数而非码元数：中文一个字 3 字节
  const bytes = new TextEncoder().encode(text).length;
  if (bytes > MAX_ARCHIVE_BYTES) {
    return { ok: false, code: 'too-large', message: `档案过大（${bytes} 字节 > ${MAX_ARCHIVE_BYTES} 字节）` };
  }
  const r = parseMatchFile(text, opts);
  if (!r.ok) return { ok: false, code: r.error.code, message: r.error.message };
  return { ok: true, file: r.file, warnings: r.warnings, raw: text };
}

export function nextArchiveName(existing: readonly string[], desired: string): string {
  if (!existing.includes(desired)) return desired;
  const dot = desired.lastIndexOf('.');
  const stem = dot > 0 ? desired.slice(0, dot) : desired;
  const ext = dot > 0 ? desired.slice(dot) : '';
  for (let i = 2; ; i += 1) {
    const cand = `${stem}-${i}${ext}`;
    if (!existing.includes(cand)) return cand;
  }
}

export function resolveConflict(existing: readonly string[], desired: string, strategy: ConflictStrategy) {
  if (!existing.includes(desired)) return { action: 'write' as const, name: desired };
  if (strategy === 'overwrite') return { action: 'write' as const, name: desired };
  if (strategy === 'skip') return { action: 'skip' as const, name: desired };
  return { action: 'write' as const, name: nextArchiveName(existing, desired) };
}
```

（`parseMatchFile` 的 `MatchFileErrorCode` 要 `import type`；`ImportOutcome` 的 `code` 联合里直接引用它。）

2. **预缓存清单必须构建期生成**：`scripts/gen-sw-manifest.mjs` 扫描 `dist/`（含 `assets/*.js|css`、`index.html`、图标），写 `dist/sw-manifest.json`（**不是** `public/`），内容形如 `{ "version": "<全部文件内容哈希>", "files": ["/index.html", "/assets/index-abc.js", ...] }`。
   - 版本键用**内容哈希**（对排序后的 `路径:sha256` 拼接再哈希）——文件名变了哈希就变，`sw.js` 的 `cacheName` 随之更新，**天然不会给用户旧代码**。
   - 脚本**只用 `node:` 内置**（`fs`/`path`/`crypto`），因为它是构建脚本（**不进浏览器产物**），不受"零运行时依赖"约束；**但仍不得新增任何 npm 包**。
3. **`sw.js` 的策略**（§8.1 + §8.4）：
   - `install`：`caches.open(version)` → `addAll(files)` → **不** `skipWaiting()`（等用户点"更新"）。
   - `activate`：删掉旧版本缓存 → `clients.claim()`。
   - `fetch`：**只**处理同源 GET；导航请求走"网络优先、失败回退 `/index.html`"；静态资源走"缓存优先"。
   - **绝不缓存任何用户数据**：`sw.js` 里不得出现 `localStorage`/`indexedDB`/`fetch` 到跨域（除同源静态资源）。这条有文本腿守卫。
   - 收到 `{ type: 'SKIP_WAITING' }` → `self.skipWaiting()`。
4. **⚠️ 无扩展名文件必须显式声明 MIME（本机已知陷阱）**：本仓存在名为 `public/assets/protocoects/` 的目录（注意拼写），且历史上出现过"无扩展名静态文件被 Vite 当源码处理"的问题。`manifest.webmanifest` **有**扩展名、`sw.js` **有**扩展名，两者都安全；但 `scripts/gen-sw-manifest.mjs` 生成的 `dist/sw-manifest.json` 是 `.json`，也安全。**唯一要当心的是别把清单文件命名为无扩展名**（例如 `sw-manifest`）。
5. **更新提示形态**：`initPwaUpdate` 检测到 `registration.waiting` 或 `updatefound → installed` 时调 `env.onUpdateAvailable()`；UI 侧（`main.ts`）显示一条**屏内条**（`document.body` 级 `position:fixed` **不要**再新增 —— 本仓已有 body 级残留的教训）。本计划选**往 `#app` 的第一层插一个 `.pwa-update-bar`**，且卸载函数负责移除它。
6. **生产闸门**：`initPwaUpdate` 默认行为里 `env.isProd` 为 false（`import.meta.env.DEV`）时**直接返回空卸载函数**，不注册 SW —— 避免开发时 SW 缓存把 `vite dev` 的模块热更新搞坏（这是"零依赖手写 SW"最容易踩的坑）。

```ts
/**
 * PWA 的注册与**自动提示 + 一键更新**（G3；§8.1、§8.4 的网页/PWA 行）。
 *
 * 零依赖：不装 vite-plugin-pwa、不改 vite.config.ts。SW 本体是 public/sw.js（手写），
 * 预缓存清单由构建脚本 scripts/gen-sw-manifest.mjs 生成到 dist/sw-manifest.json。
 *
 * 三条纪律：
 *  1. **dev 不注册**（`import.meta.env.DEV`）：否则开发时 SW 会缓存住入口，热更新失效；
 *  2. **不新增 body 级常驻层**：更新条插在 `#app` 第一层，卸载函数负责移除；
 *  3. 环境可注入（`PwaEnv`）：SW API 在 node 下不存在，行为腿靠注入假件。
 */
export interface SwRegistrationLike {
  waiting: unknown | null;
  installing: unknown | null;
  addEventListener(t: string, cb: () => void): void;
  update(): Promise<void>;
}
export interface SwContainerLike {
  register(url: string, opts?: { scope?: string }): Promise<SwRegistrationLike>;
  getRegistration(): Promise<SwRegistrationLike | undefined>;
  addEventListener(t: string, cb: () => void): void;
  readonly controller: unknown;
}
export interface PwaEnv {
  sw: SwContainerLike | null;
  reload(): void;
  isProd: boolean;
  onUpdateAvailable(): void;
}

/** 向等待中的 SW 发跳过等待指令（页面随后 reload 才会用上新的 controller） */
export function applyUpdate(reg: SwRegistrationLike): void {
  const w = reg.waiting as { postMessage?: (m: unknown) => void } | null;
  if (w && typeof w.postMessage === 'function') w.postMessage({ type: 'SKIP_WAITING' });
}

function realEnv(): PwaEnv {
  return {
    sw: (globalThis.navigator as { serviceWorker?: SwContainerLike } | undefined)?.serviceWorker ?? null,
    reload: () => globalThis.location?.reload(),
    isProd: !import.meta.env.DEV,
    onUpdateAvailable: () => {
      // 更新条：插在 #app 第一层（不是 body 级常驻层）
      const host = document.getElementById('app');
      if (!host || host.querySelector('.pwa-update-bar')) return;
      const bar = document.createElement('div');
      bar.className = 'pwa-update-bar';
      const text = document.createElement('span');
      text.textContent = '有新版本可用';
      const btn = document.createElement('button');
      btn.type = 'button';
      btn.className = 'btn';
      btn.textContent = '立即更新';
      btn.addEventListener('click', () => {
        void (globalThis.navigator as unknown as { serviceWorker: SwContainerLike }).serviceWorker
          .getRegistration()
          .then((r) => { if (r) applyUpdate(r); globalThis.location.reload(); });
      });
      bar.appendChild(text);
      bar.appendChild(btn);
      host.prepend(bar);
    },
  };
}

/**
 * 注册 SW 并挂更新提示。返回**卸载函数**（移除更新条 + 注销注册）。
 * 导入即用（`main.ts` 末尾调一次）；失败一律静默（PWA 不可用不该影响游戏）。
 */
export function initPwaUpdate(overrides: Partial<PwaEnv> = {}): () => void {
  const env: PwaEnv = { ...realEnv(), ...overrides };
  if (!env.isProd || env.sw === null) return () => {};
  let disposed = false;
  void env.sw.register('/sw.js', { scope: '/' }).then((reg) => {
    if (disposed) return;
    if (reg.waiting) { env.onUpdateAvailable(); return; }
    reg.addEventListener('updatefound', () => { env.onUpdateAvailable(); });
  }).catch(() => { /* PWA 不可用不影响游戏 */ });
  return () => {
    disposed = true;
    const host = document.getElementById('app');
    host?.querySelector('.pwa-update-bar')?.remove();
  };
}
```

关键结构（**必须**含 `SKIP_WAITING`/`skipWaiting`/`caches.delete`/`sw-manifest.json` 四个文本腿要求）：

```js
/* Service Worker（G3；§8.1、§8.4）。手写，无依赖。
 * 只缓存同源的程序文件；**绝不**触碰任何用户数据（不 import 任何存储 API）。 */
const MANIFEST_URL = '/sw-manifest.json';
let CURRENT = null;

self.addEventListener('install', (e) => {
  e.waitUntil((async () => {
    const res = await fetch(MANIFEST_URL, { cache: 'no-store' });
    const m = await res.json();
    CURRENT = m.version;
    const cache = await caches.open(`compile-${m.version}`);
    await cache.addAll(m.files);
    // 注意：这里**不**调 skipWaiting()，等用户在更新条上点"立即更新"
  })());
});

self.addEventListener('activate', (e) => {
  e.waitUntil((async () => {
    const names = await caches.keys();
    await Promise.all(names.filter((n) => n.startsWith('compile-') && n !== `compile-${CURRENT}`).map((n) => caches.delete(n)));
    await self.clients.claim();
  })());
});

self.addEventListener('message', (e) => {
  if (e.data && e.data.type === 'SKIP_WAITING') self.skipWaiting();
});

self.addEventListener('fetch', (e) => {
  const req = e.request;
  if (req.method !== 'GET') return;
  const url = new URL(req.url);
  if (url.origin !== self.location.origin) return;
  if (req.mode === 'navigate') {
    e.respondWith((async () => {
      try { return await fetch(req); } catch { return (await caches.match('/index.html')) || Response.error(); }
    })());
    return;
  }
  e.respondWith((async () => (await caches.match(req)) || fetch(req))());
});
```

```js
/**
 * 构建后生成 dist/sw-manifest.json（G3；§8.1）。
 * 版本键 = 全部被缓存文件的「路径:sha256」排序拼接后的 sha256 —— 任何一个文件变了，
 * 版本就变，sw.js 的 cacheName 随之更新，用户不会拿到旧代码。
 */
import { readdirSync, readFileSync, writeFileSync, statSync } from 'node:fs';
import { join, relative, sep } from 'node:path';
import { createHash } from 'node:crypto';

const DIST = 'dist';
const SKIP = new Set(['sw-manifest.json', 'sw.js']);        // sw.js 自身不必预缓存
const EXT_OK = /\.(html|js|css|json|png|jpg|jpeg|webp|svg|woff2|ttf|pdf|webmanifest)$/;

function walk(dir, out = []) {
  for (const name of readdirSync(dir)) {
    const p = join(dir, name);
    if (statSync(p).isDirectory()) walk(p, out);
    else out.push(p);
  }
  return out;
}

const files = walk(DIST)
  .map((p) => ({ abs: p, rel: '/' + relative(DIST, p).split(sep).join('/') }))
  .filter((f) => !SKIP.has(f.rel.slice(1)) && EXT_OK.test(f.rel))
  .sort((a, b) => (a.rel < b.rel ? -1 : 1));

const h = createHash('sha256');
for (const f of files) h.update(`${f.rel}:${createHash('sha256').update(readFileSync(f.abs)).digest('hex')}\n`);
const version = h.digest('hex').slice(0, 16);

writeFileSync(join(DIST, 'sw-manifest.json'), JSON.stringify({ version, files: files.map((f) => f.rel) }, null, 2));
console.log(`sw-manifest.json：${files.length} 个文件，version=${version}`);
```

> **注意本机陷阱**：`node scripts/gen-sw-manifest.mjs` 必须能在 **`dist/` 不存在**时给出**清晰的报错**（否则第一次 `npm run build` 之前跑它会得到 `ENOENT` 堆栈）。加一句 `if (!existsSync(DIST)) { console.error('先跑 vite build'); process.exit(1); }`。

```ts
import { describe, it, expect } from 'vitest';
import { readdirSync, readFileSync, statSync } from 'node:fs';
import { fileURLToPath } from 'node:url';
import { join } from 'node:path';
import { codePositions, stripComments } from './ui/source-text';

const appDir = fileURLToPath(new URL('../src/app', import.meta.url));

function walk(dir: string, out: string[] = []): string[] {
  for (const name of readdirSync(dir)) {
    const p = join(dir, name);
    if (statSync(p).isDirectory()) walk(p, out);
    else if (p.endsWith('.ts')) out.push(p);
  }
  return out;
}

const files = walk(appDir).sort();
const sources = files.map((p) => ({ path: p, code: stripComments(readFileSync(p).subarray(0, 4 * 1024 * 1024).toString('utf8')) }));

describe('src/app 的分层契约（ui → app → core；app 不碰浏览器/网络/UI）', () => {
  it('至少扫到了本阶段的全部 app 模块（生成式：文件数必须 >= 6，防"目录被清空后测试静默通过"）', () => {
    expect(files.length).toBeGreaterThanOrEqual(6);
  });

  it('浏览器 API 零命中（localStorage/indexedDB/document/window/navigator/fetch/serviceWorker）', () => {
    const banned: [string, RegExp][] = [
      ['localStorage', /\blocalStorage\b/],
      ['sessionStorage', /\bsessionStorage\b/],
      ['indexedDB', /\bindexedDB\b/],
      ['document', /\bdocument\s*\./],
      ['window', /\bwindow\s*\./],
      ['navigator', /\bnavigator\s*\./],
      ['fetch', /\bfetch\s*\(/],
      ['serviceWorker', /\bserviceWorker\b/],
      ['showOpenFilePicker', /\bshow(Open|Save)FilePicker\b/],
      ['crypto.getRandomValues', /\bgetRandomValues\b/],
    ];
    const hits: string[] = [];
    for (const { path, code } of sources) {
      for (const [label, re] of banned) if (re.test(code)) hits.push(`${path}: ${label}`);
    }
    expect(hits, `src/app 里出现浏览器 API（应挪到 src/ui）：\n${hits.join('\n')}`).toEqual([]);
  });

  it('不得 import src/ui（依赖方向严格单向）', () => {
    const hits: string[] = [];
    for (const { path, code } of sources) {
      if (/from\s+['"][^'"]*\/ui\//.test(code)) hits.push(path);
    }
    expect(hits).toEqual([]);
  });

  it('不得出现 Math.random / Date.now（随机源只能在 match-seed.ts；档案时间由调用方传入）', () => {
    const hits: string[] = [];
    for (const { path, code } of sources) {
      if (/\bMath\.random\s*\(/.test(code)) hits.push(`${path}: Math.random`);
      if (/\bDate\.now\s*\(/.test(code)) hits.push(`${path}: Date.now`);
    }
    expect(hits).toEqual([]);
  });

  it('纯逻辑模块不得带副作用式写盘（Node fs 零命中）', () => {
    const hits: string[] = [];
    for (const { path, code } of sources) if (/from\s+['"]node:/.test(code)) hits.push(path);
    expect(hits).toEqual([]);
  });
});

describe('codePositions 判据本身可用（防守卫假绿）', () => {

  });
```

### #1 【重要 · 影响档案能否完整重放】`setup` 要不要加"草稿顺序快照"？

- **背景事实**：设计稿 §3.1 的 `setup.draftPool: string[]` 是"开局可选协议池"（§3.1 注释：`defId 列表`），它是**集合**；而 `GameState.draftPicks` 是**按选择顺序**的数组（`types.ts:334`）、`bannedProtocols` 也是**按禁用顺序**（`types.ts:344`）。**ban 模式**下"选"与"禁"交错发生，只靠 `draftPool` 无法还原"谁在第几轮选/禁了什么"。
- **选项 A（推荐）**：`setup` 增加 `draftPicks: string[]` 与 `bannedProtocols: string[]`（本计划的 Task 1 就是这么写的）。
  - **代价**：档案比 §3.1 的 Schema 多两个字段；`version` 仍是 1（因为 v1 尚未发布，加字段不算破坏性变更）。
- **选项 B**：严格照 §3.1，不加。在 `MatchFile` 里只存 `draftPool`，把"草稿阶段"排除在重放之外（即 G4 的 `ReplayDriver` 从一个**已过草稿**的状态起跑）。
  - **代价**：档案不是"完整一局"，与 §3.2 的"录像/断线重连凭据"两个用途**直接冲突**（断线重连必须能回到草稿阶段的局面）。
- **我的推荐：A**。B 在 G4 会立刻撞墙，而且那时改档案格式要走迁移链。

### #2 【重要 · §16 第 5 条明确要求 G3 定】战绩的 L2 结构：单独文件还是并入"用户档案"？

- **选项 A（推荐）**：**完全不做战绩**（G3 不引入战绩概念；`MatchFile.result` 里已有的 `{ winner, reason }` 就是"这一局的战绩"，单局自带）。
  - **代价**：用户看不到"我赢了几局"。但 G3 的验收标准（§3.8）**没有**这一条。
- **选项 B**：**单独文件** `compile-profile.json`（一个"用户档案"，只有昵称 + 设置 + 卡组索引 + 战绩列表；`MatchFile` 作为独立文件被它引用，不内联）。
  - **代价**：多一个格式要维护、多一条版本迁移链；导入导出要处理"档案 vs 用户档案"两种文件（UI 上要区分，否则用户会导错）。
- **选项 C**：战绩**并入** `MatchFile`（每局档案自带一行统计），"战绩"= 扫描所有档案的聚合视图。
  - **代价**：用户删掉档案就丢战绩（数据生命周期耦合）；聚合要读全部文件（IO 成本随局数线性增长）。
- **我的推荐：A（G3 不做），把 B 推给 G4/G6 之后的独立阶段**。理由：§3.8 没有它，而 B/C 都会立刻引入新的格式与迁移链；G3 的目标是"把授权与档案这件事做对"，不是"把用户画像做全"。若你希望现在就做，请选 **B**（比 C 干净）。

### #3 【影响观感与可发现性】主页入口的文案与位置

- **选项 A（推荐）**：主页菜单加第 5 个按钮 **「本地数据与隐私」**（`home.ts:196-199` 那一串之后），点进独立屏。
  - **代价**：主页按钮从 4 个变 5 个（视觉上略微变长）；与"查看协议及其所属卡牌"并列，语义层不同但可接受。
- **选项 B**：放在**模式选择页**（`renderModeSelect`）里。
  - **代价**：用户必须先点"开始游戏"才能找到隐私设置 —— 而"拒绝授权后想改回来"恰恰发生在**主界面**。
- **选项 C**：只在授权弹窗里给一个"隐私说明"链接，不设常驻入口。
  - **代价**：用户**无法**事后改变授权（设计稿 §3.6 明写"用户随时可在设置里改授权"）。
- **我的推荐：A**。C 违反 §3.6。

### #4 【影响工作量】要不要现在做 FSA「静默写回同一文件」（句柄存 IndexedDB）？

- **选项 A（推荐）**：**不做**。导出走 `<a download>`（Chrome/Edge/Safari/Firefox 全平台可用），导入走 `showOpenFilePicker` 或 `<input type=file>`。
  - **代价**：Chrome/Edge 用户每局结束要"另存为"一次，而不是"静默写回"。设计稿 §3.7 称这只是"存档顺滑度"差异。
- **选项 B**：做（`showSaveFilePicker` 拿句柄 → `indexedDB` 存句柄 → 下次直接写回）。
  - **代价**：句柄是**浏览器对象**，`src/app` 的"纯逻辑"分层立刻被打破（要新增一个 `AsyncKeyValueStore` 的浏览器实现 + 授权绑定 + 句柄失效重授权流程）；而且 Safari/Firefox 上永远是死代码。
- **我的推荐：A**。B 的收益（少点一次"保存"）远小于它带来的分层复杂度与失败模式。

### #5 【影响红线 3 的严格程度】"拒绝后本次会话内不再问"的标记放哪？

设计稿 §3.6 给了两条路："要么每次进入都问，要么用一个不落盘的会话内标记"，并裁决"拒绝后本次会话内不再询问，下次进入重新问（真正做到零写入）"。

- **选项 A（推荐）**：**内存变量**（本计划 Task 3/4 的做法：`LocalStore.consent` 是闭包变量）。刷新即失效 → 每次都问。
  - **代价**：严格说"一次会话 = 一个页面实例"；在单页应用里用户从主界面反复进出不会重问（正确），但刷新/新标签页会重问（符合 §3.6 的"下次进入重新问"）。
- **选项 B**：用 `sessionStorage`（"同一标签页会话"内不重问，刷新也不问）。
  - **代价**：**`sessionStorage` 也是磁盘写入**（Chromium 会落盘），直接违反红线 3 的"零写入"。**不推荐**。
- **我的推荐：A**。B 是"看起来更聪明"的陷阱。

### #6 【影响聊天/观感】授权弹窗的措辞基调

- **选项 A（推荐）**：**中性陈述 + 明确后果**（本计划 Task 4 的 `CONSENT_COPY`）："允许后…保存在你自己的浏览器里"/"不允许也能正常游玩全部内容：刷新或关闭就全部丢掉"。
  - **代价**：文案略长（三行），首次进入要多读两秒。
- **选项 B**：极简（"是否允许本机保存设置？" + 允许/拒绝）。
  - **代价**：用户不知道"拒绝"意味着什么，容易误点；§3.6 要求"询问是否允许在本机保存**昵称、设置、卡组**"三项都要提到。
- **选项 C**：做成"推荐允许"的引导式（默认高亮允许、加一句"推荐"）。
  - **代价**：**暗黑模式**（dark pattern）。本项目面向熟人玩家，声誉成本大于收益。
- **我的推荐：A**。

### #7 【影响冲突行为】导入档案时若"同 id/同名已存在"怎么办？（本计划默认 `keep-both`）

- **选项 A（推荐）**：**保留两份**，自动加 `-2`/`-3` 后缀（`nextArchiveName`）。
  - **代价**：用户的档案目录会积累重复文件；需要 UI 上提示改名后的实际文件名。
- **选项 B**：**覆盖**（同名即替换）。
  - **代价**：**不可逆地丢用户数据**，而导入的往往正是"备份"—— 这是最坏的选择。
- **选项 C**：**跳过**（同名不导入，提示"已存在"）。
  - **代价**：用户想"用新档替换旧档"时会困惑（必须先去文件管理器删旧文件）。
- **我的推荐：A**，并把 `overwrite` 留作**显式按钮**（用户主动选"覆盖"时才做）。这已经写在 Task 6 的 `resolveConflict(strategy)` 里。

### #8 【影响工作量】档案加密（主密码 + AES-GCM + PBKDF2）现在做吗？

- **选项 A（推荐）**：**不做**。§3.7 提到它，但 §3.8 的 G3 验收标准**一条都没有**加密。
  - **代价**：用户把档案放在共享目录里会被别人读到（但档案里没有个人隐私数据 —— 只有昵称、种子与操作序列）。
- **选项 B**：做，作为**独立任务**（`src/app/archive-crypto.ts` + 注入式 `Cipher`，测试用假 cipher + 一条"真实 WebCrypto 在 node 下也能跑"的行为腿）。
  - **代价**：多一条 UI 分支（"加密导出/导入时需要输入主密码"）、多一类错误（密码错、迭代次数升级）；`crypto.subtle` 是**异步**的 ⇒ 现有"同步导出"的调用链全要改成异步。
- **我的推荐：A**。若要做，**必须**单独一个任务、单独一次用户验收（U 盘往返 + 错密码路径），不能塞进 Task 6。

### #9 【影响产品实体】"账号"要不要引入？

- **背景**：设计稿 §3.5 把"账号"列进 L2 内容（"账号、战绩、录像、`MatchFile`"），但 §0.4 红线 1 禁止任何服务器存账号，§3.8 验收标准也不含账号。
- **选项 A（推荐）**：**不引入"账号"实体**。L1 有昵称，L2 有档案文件与（若做）用户档案文件；"身份"就是"你手上那份文件"。
  - **代价**：换设备必须手动拷贝文件（这正是 §3.5 说的"可移植、换设备靠拷贝"）。
- **选项 B**：引入一个**本地账号**（昵称 + 一个本地生成的 id，存在 L2 用户档案文件里，用于把多份 `MatchFile` 归到一个人名下）。
  - **代价**：这个 id 一旦用于联机（G5 的 `sessionId`/昵称交换）就有"它是账号吗"的语义争议；且它**不能**做任何鉴权（无后端），容易让用户误以为"登录了"。
- **我的推荐：A**。B 只在"用户档案（#2 的选项 B）"确定要做时才有意义。

### #10 【与设计稿一句话不同】`cardDataHash` 是"构建期常量"还是"运行期计算"？

- **选项 A（推荐）**：**运行期计算 + 导出的常量**（本计划 Task 2），并加一条"常量 == 现算值"的行为腿防手改。
  - **代价**：与 §3.4 的"构建时生成的常量，不进运行时状态"**措辞不一致**（实际效果一致：它不进 `GameState`）；首次加载多算一次约 90KB 字符串的 FNV-1a（实测可忽略）。
- **选项 B**：**构建期生成** `src/app/card-data-hash.generated.ts`（用 `scripts/gen-card-hash.mjs` 在 `build` 里生成）。
  - **代价**：多一个构建步骤（更多失败点）、生成文件要么进仓库（会有"忘记重跑"的漂移）要么不进（`tsc` 在干净检出上会红）；且它违反"生成式清单 > 手写清单"的精神（多一份需要同步的产物）。
- **我的推荐：A**，并请在批复时确认这个措辞差异可以接受。

### #11 【门禁纪律】要不要加一条"测试总数不得低于 N"的自动守卫？

- **选项 A（推荐）**：**不加**。保持 G0/G1/G2 的惯例（**文字约定**写在 `## Global Constraints` 里，门禁里人工核对数字）。
  - **代价**：理论上有人可以把 100 个 `it` 合并成 1 个而门禁全绿（本仓历史上没发生过）。
- **选项 B**：加（把基线数字写进一个测试，例如 `expect(totalTests).toBeGreaterThanOrEqual(1298)`）。
  - **代价**：这个数字**只能靠 vitest 自己的报告**拿到，而测试内部拿不到"总项数"（要读 vitest 的 JSON reporter 输出 = 引入测试对测试运行器的依赖）；更糟的是任何合理的测试重构（合并/参数化）都会让它假红，而**假红的判据一定会被人放宽**（违反"不许放宽判据"）。
- **我的推荐：A**。

### #12 【观感取舍】授权弹窗是"整屏屏"还是"叠在主页上的卡片"？

- **选项 A（推荐）**：**整屏屏**（本计划 Task 4）。走 `root.textContent = ''`，**零 `document.body` 级残留风险**。
  - **代价**：视觉上"先过一道门再进主页"，不如"主页后面透出背景"精致。
- **选项 B**：`position:fixed` 覆盖层（保留主页背景透出）。
  - **代价**：本仓在 G2 已经因 `document.body` 级浮层残留栽过（多处遮挡点击、全量重渲染清不掉）；新增一个 body 级常驻层要额外写清理钩子挂进 `resetUiState`。
- **我的推荐：A**。

### #13 【诚实性】G3 的"离线可开"要不要现在就对玩家承诺？

- **选项 A（推荐）**：**承诺**，并在隐私说明里写明"缓存的不是用户数据"（Task 5 的 `offlineCacheNote`）。
  - **代价**：service worker 有缓存陈旧的风险 —— 靠 `sw-manifest.json` 的内容哈希版本键 + "一键更新"条兜住；但**首次部署到已访问过的用户**时，旧 SW 会先控制页面一次（这是 SW 的固有语义，无法完全消除）。
- **选项 B**：只做 manifest（可安装），**不做** service worker（不承诺离线）。
  - **代价**：§3.8 最后一条"断网可打开"直接不满足；PWA 只剩"能安装"。
- **我的推荐：A**。
