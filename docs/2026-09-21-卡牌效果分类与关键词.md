# 卡牌效果分类与关键词（第二版，2026-09-21）

这份文档给两件事用：**图鉴里那个筛选框**（每一类一条，勾了就筛卡），以及**"哪些卡会牵动别人那一屏"**的风险排查。
第二版按用户 2026-09-21 的要求补了三件事：**指令位置**（顶部 / 中部 / 底部）、**触发时机**（不止"打出"——
翻转、偏转、被揭开、被盖住、连锁都会触发）、**控制权相关**与**条件触发**。

## 0. 这份文档是怎么来的（数字都可复查）

数据来源是**两个**，一个工具一次跑出来（`tools/card-effect-index.mjs`，**开发工具，不是门禁**）：

| 来源 | 读到什么 | 为什么需要它 |
| --- | --- | --- |
| 卡面文本 `src/data/cards{,_2,_3}.ts` | 每张卡的 `top` / `middle` / `bottom` 三个**指令文本字段** | 这是玩家在图鉴里看到的东西，筛选框的说法要与它对齐 |
| 效果代码 `src/core/effects/cards/*.ts` | 每张卡登记的钩子、触发的 kind、`cond`（条件）、用到的 op、选择请求与 `chooser` | 文本说不清"什么时候触发""会不会换人应答"，代码才说得清 |

生成命令（仓库根）：

```
node tools/card-effect-index.mjs > .superpowers/g5-T23/effects-index.json
```

**实测规模**：卡牌数据 **270** 张（45 协议 × 6 档），其中 **266 张登记了效果代码**，另外 **4 张**
（`chaos-3` / `ice-4` / `ice-6` / `metal-2`）**只有文本、没有代码钩子** —— 它们是**持续型限制**
（"不可被翻转"/"如果你有手牌，不可以抽牌"/"可以无视协议限制打在任意堆叠"），由规则层实现。
**196 张会弹选择请求**，**70 张完全不产 prompt**，**82 张有 trigger**。

## 1. 五个维度总览

| 维度 | 回答的问题 | 关键词（代码层） | 图鉴筛选该不该用 |
| --- | --- | --- | --- |
| **A 指令位置** | 这条效果写在卡面哪一行 | `CardDef.top` / `.middle` / `.bottom`、`triggers.*.top === true` | 用（玩家就是这么认卡的） |
| **B 触发时机** | 什么事件让它跑起来 | `middle`、`triggers: { <kind>: … }`（25 种） | 用（"打出才触发"是常见误解，见 §3） |
| **C 效果动作** | 它到底干了什么 | `op: '<23 个动词>'` | 用（弃牌 / 删除 / 翻转 … 就是用户要的那些类） |
| **D 控制权相关** | 与"控制权 / 控制组件"有关 | `s.control`、`controlRearrangeFlow`、`holder`、`after-opponent-gain-control` | 用（单独一类，用户点名要） |
| **E 条件触发** | 需要满足条件才触发 | `triggers.*.cond !== undefined` | 用（可作"条件类"一个勾） |

## 2. 维度 A：指令位置（顶部 / 中部 / 底部）

**下面三个数是 266 张"已登记效果"的卡的口径**；那 4 张只有文本、没有代码钩子的持续型卡，另外还各有
顶部或底部文本（`ice-6` / `metal-2` 有顶部文本，`chaos-3` / `ice-4` 有底部文本）—— 把这 4 张算进去，
全 270 张的口径是：顶部 **49** / 中部 **222** / 底部 **66**。

| 类 | 关键词 | 张数 | 说明 |
| --- | --- | --- | --- |
| **顶部指令** | 卡面 `top:` 字段非空 | **47** | 写在卡面上方那一行 |
| **中部指令** | 卡面 `middle:` 字段非空 | **222** | 打出时结算的那一行 |
| **底部指令** | 卡面 `bottom:` 字段非空 | **64** | 写在卡面下方那一行（多是"结束/开始"触发） |
| **顶命令（被盖仍生效）** | 代码 `triggers.<kind>.top === true` | **31** | 与"顶部指令"**不是同一件事**：卡面 `top:` 是排版位置，`top: true` 是"这张牌被盖住了它的效果照样跑"。31 张的清单：`clarity-1, corruption-0, corruption-2, corruption-6, courage-0, death-1, diversity-6, flexibility-2, fulcrum-0, gluttony-0, gluttony-3, hate-3, ice-3, life-0, metal-6, momentum-1, momentum-6, nova-0, overwhelm-2, overwhelm-6, plague-1, pride-0, pride-6, rigidity-7, speed-1, speed-2, spirit-3, time-2, unity-1, unity-4, war-0` |
| **只有文本、无代码钩子** | 数据里有、`registerCardEffects` 里没有 | **4** | `chaos-3`、`ice-4`、`ice-6`、`metal-2` —— 持续型限制，判定在规则层 |

> 一张卡可以同时有顶部+中部+底部（例如 `momentum-1` 有 `top` 与 `bottom`，`momentum-6` 有 `top` 与 `middle`）。
> 上表三个数相加 **333 > 266** 就是这个原因，不是重复计数错误。

## 3. 维度 B：触发时机（**不止"打出"** —— 用户点名要的这一层）

### B1. 中部指令（`middle`）有**四个**触发点，不止"打出"

代码出处是 `pushMiddle(...)` 的 `reason`（`src/core/effects/resolve.ts`）：

| 触发点 | 关键词 | 出处 | 白话 |
| --- | --- | --- | --- |
| **打出** | `pushMiddle(…, '打出')` | `resolve.ts:1035` | 你把这张牌打到链路里 |
| **翻正** | `pushMiddle(…, '翻正')` | `:469` | 别人（或它自己的效果）把它**翻成正面**且它未被覆盖 |
| **被揭开** | `pushMiddle(…, '被揭开')` | `:1081`（`revealAfterRemoval`） | 它**上面那张被移走**，它成了正面顶卡 |
| **偏转暴露** | `pushMiddle(…, '偏转暴露')` | `:1069` | 它**被偏转到新线**后成了未被覆盖的正面顶卡（今天只对 `diversity-0` / `unity-1` 重新评估） |

**这四条都是"条件性"的**（用户 2026-09-21 第 2 点的意思就是这一类）：翻正要看它翻完是不是**正面且未被覆盖**；
被揭开要看它上面那张真的被移走、且它自己是正面（`revealAfterRemoval` 里那两个条件缺一不可）；
偏转暴露今天只对 `diversity-0` / `unity-1` 这两张重新评估。"打出"是唯一**无条件**的那一个。

**这条直接回答了用户第 1 点**：一张卡的中部指令**不一定在"打出"时触发**——翻转、移走压着它的牌、
把它偏转过去，都可能让它的中部指令再跑一次。图鉴筛选如果只按"打出"分类，就会漏掉这一类。

### B3. 明确写清"**没有**"的两件事（免得按直觉写文档）

- **没有 `after-flip`（翻转之后）**，也**没有 `after-shift`（偏转之后）**：`TriggerKind` 的 25 个值里
  只有 `before-flip`（翻转**前**）与 `before-covered`（被盖住**前**）。
  ⇒ **"一张牌被翻转/被偏转之后，它自己的效果再触发一次"这件事在当前引擎里不存在**；
  被翻转能触发的是**那张牌自己的保护类顶命令**（今天只有 `metal-6`），
  被偏转能触发的是**被它压住的那张牌的 `before-covered`**（9 张里任一在顶且正面时）。
- **中段不一定会结算**：`apathy-2`（"无效化此列所有牌的中部命令"）与 `fear-0`（"在你的回合内，对手无法
  触发中央效果"）会让 `pushMiddle` **直接返回**（`resolve.ts:110-120`）——"触发了但不算数"是一类真实状态，
  归 **限制 / 无效化** 类。

| **完全不产 prompt** | 没有选择请求 | **70** | （见 JSON 的 `noPromptCards`） |

> `light-2` 的 `chooser` 在源码里是一个**局部变量**（值 = 效果属主，源码写明"选择权不随卡牌易主转移"）

## 8. 为图鉴筛选预留的口径（第 2 步要用的东西，先写在这）

用户要的筛选：右下角一块，**所有分类各一个勾，默认全勾**；勾了的类里**只要命中一条**就把这张卡连同它的协议
显示出来；一条都没命中就不显示；某个协议**所有卡都被排除**时，连它的框一起隐藏。

按这份分类，勾选项建议**平铺**下面这些（每一条都对应一个可机械判定的关键词）：

| 勾选项 | 判定来源 | 关键词 |
| --- | --- | --- |
| 顶部指令 / 中部指令 / 底部指令 | 卡面文本 | `CardDef.top` / `.middle` / `.bottom` 非空 |
| 顶命令（被盖仍生效） | 效果代码 | `triggers.*.top === true` |
| 打出触发 / 翻正触发 / 被揭开触发 / 偏转暴露触发 | 效果代码（`pushMiddle` 的 reason） | 中段存在 + 该卡的触发点；"翻正/被揭开/偏转暴露"是**引擎侧**行为，按"这张卡有中段"即可勾"打出触发" |
| 回合开始 / 回合结束 / 被盖住前 / 被翻转前 / 被编译删除前 | 效果代码 | `triggers.start` / `end` / `before-covered` / `before-flip` / `before-compile` |
| 连锁反应（19 种 after-*） | 效果代码 | `triggers['after-…']`（可合成一个勾） |
| 弃牌 / 批量弃牌 / 弃牌库顶 / 弃整副 | 效果代码 | `op: discard / discardMany / discardDeckTop / discardWholeDeck` |
| 删除 / 翻转 / 偏转 / 揭示 / 回手 / 抽牌 / 给牌 / 拿牌 / 打出（牌库顶·手牌·弃牌堆）/ 重排协议 / 换堆叠 / 复制 / 牌库顶转移 / 回库底 | 效果代码 | §4 的 op 关键词 |
| 控制权相关 | 卡面文本（建议）或效果代码 | 文本含"控制权" / `s.control`·`controlRearrangeFlow`·`holder` |
| 条件触发 | 效果代码 | `triggers.*.cond` |
| 宣告 | 效果代码 | 选择请求标题含"宣告" |
| 数值修正 | 效果代码 | `valueModifier` |
| 限制 / 无效化 | 效果代码 + 数据 | §7 最后一行那几个关键词 |

**标签从哪来（两条路，建议第二条）**：

1. **纯文本关键词**（页面里现算）：只读 `src/data` 的卡面文本，按"弃/删除/翻转/偏转/揭示/控制权/宣告…"匹配。
   优点：零新增数据、零构建步骤；缺点：**文本里出现"弃牌堆"会被当成"弃牌"**，而"偏转/翻正触发"这种事
   文本根本不写 ⇒ 分类会偏。
2. **构建期生成一份标签数据**（推荐）：让 `tools/card-effect-index.mjs` 再输出一个"defId → 标签数组"的
   小 JSON（约 266 条、每条几个短字符串），由 `scripts/` 里现有那种生成器写进 `src/data/`。
   优点：标签来自**代码事实**（op / trigger / chooser），与这份文档同源；
   **注意**：`src/data` 里那份"自动生成的展示数据"有 `tests/app/card-data-hash.test.ts` 守着
   （改了要同步哈希），要么把新文件也纳入同样的守卫，要么把它放进一个**新的、明确的生成物**里并补一条
   "生成物与生成器一致"的腿 —— 这一步属于第 2 步的实现范围，动手前先定这一个选择。

### 8.1 已经做出来了（G5 T24，2026-09-21/22）—— 自己怎么试

## 9. 与"会不会出 bug"的关系 + 未验

| 分类 | 会牵动"别人那一屏"吗 | 现状 |
| --- | --- | --- |
| 应答权交给对方（21 张，含 9 张 trigger） | **会**：选择条要从操作方那屏换到对方那屏 | 座位规则已修（T23）；交叉应答链有 node 腿（`tests/net/net-cross-side-choice.test.ts`，用疫2 跑的）；**真浏览器没验** |
| body 级窗口（momentum-4） | **会** | 已加座位闸门；live 控制重排只有隐式隔离、**无腿** |
| 宣告（2 张） | **会**（骰子特效 + 选择条） | 座位闸门覆盖；真浏览器没验 |
| 揭示（9 张） | 会（观众是双方） | 未单独验 |
| 偏转暴露 / 翻正 / 被揭开这三条中段触发点 | 不换屏，但**会改变"这一刻谁在选"** | 引擎行为；本轮分类首次把它们写清，**没有专门的联机腿** |
| 其余（弃牌/删除/翻转/偏转，只要应答者是属主自己） | 不会 | 与 T23 那族无关 |

**未验 / 边界**（如实记）：

1. 真浏览器里两边真人各点一次（`effect-choice` 过网的完整回合）仍然没走过。
2. 本分类是**代码关键词**层面的事实；`chooser` 只认了字面量与一处局部变量（`light-2`）。
3. 工具的 title 抽取有窗口上限，个别多行 `yield` 的标题会读成空（不影响按 op / kind / chooser 的统计）。
4. 张数是"**用到**该效果的卡"，不是"实战里一定会触发"（很多卡有条件、有前置）。
5. `after-flip` / `after-shift` 这两类**不存在**是当前实现的**事实**，不是本文档的遗漏；若哪天规则要加
   "被翻转后触发"，`TriggerKind` 与这份分类都要同步改。
