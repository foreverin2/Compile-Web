# 卡牌效果分类与关键词（G5 T23 追加，2026-09-21）

这份文档回答两件事：**所有卡牌效果能按什么关键词分类**，以及**哪些类会牵动"别人那一屏"或弹出窗口**
（那正是用户 2026-09-21 报的那族缺陷所在）。

## 0. 这份文档是怎么来的（数字都可复查）

- 数据来源：`tools/card-effect-index.mjs`（**文本级**解析 `src/core/effects/cards/*.ts`，
  不做类型检查；解析不到的引用如实标 `unresolved`，不猜）。它**不是门禁**，不进任何流水线。
- 生成命令（仓库根）：
  `node tools/card-effect-index.mjs > .superpowers/g5-T23/effects-index.json`
  （JSON 留在 `.superpowers/`，是临时产物；要复现这张表跑这一条就行）
- 规模：卡牌数据里 **270** 张（45 协议 × 6 档），其中 **266 张登记了效果**。剩下 4 张
  （`chaos-3` / `ice-4` / `ice-6` / `metal-2`）是**持续型限制**（"不可被翻转"/"不可以抽牌"/"可以无视
  协议限制打在任意堆叠"），由规则层实现、**不产任何 prompt**，所以不在下面的分类里。
- 口径：分类按**代码关键词**，不按卡面措辞。同一张卡可以落在多个类里（例如 `fire-1` 同时是
  **弃牌**、**删除**、**翻转**）—— 这是**有意的**，卡面本来就是一句话叠几个动作。

## 1. 三层关键词（先看懂这三层，§2 的表才有意义）

| 层 | 关键词 | 白话 |
| --- | --- | --- |
| ① 钩子 | `middle:` | 这张牌**打出去结算时**跑的一段（"中指令"） |
| ① 钩子 | `triggers: { <kind>: { fn, top?, cond? } }` | **别人回合也可能跑**的一段（"顶/底命令"、反应型） |
| ① 钩子 | `valueModifier: { target, apply }` | **只改点数**，不弹任何东西 |
| ② 选择请求 | `kind: 'select'` / `'select-line'` / `'select-action'` | 让玩家选卡 / 选线 / 选动作（三个会弹 UI 的形状） |
| ② 选择请求 | `chooser: <谁>` | **应答权归谁**。缺省 = 效果属主；`foe`/`opp` = 对手；`holder` = 控制权持有者 |
| ② 选择请求 | `rearrangeSide` | 这个请求由**重排窗口**（body 级遮罩）承接，不是选择条 |
| ③ 效果步骤 | `op: '<动词>'` | 真正改状态的那一步（23 个动词，见 §2） |

**钩子的实际用量**（266 张登记卡）：只有 `middle` **173** 张、`middle+triggers` **26** 张、
只有 `triggers` **25** 张、`middle+triggers+top` **18** 张、`triggers+top` **13** 张、
只有 `valueModifier` **6** 张、`middle+valueModifier` **5** 张。合计**有 trigger 的 82 张**。

**trigger kind 一共 25 种**（出现次数）：`end`(31)、`start`(16)、`before-covered`(9)、`after-refresh`(4)，
以及各 1-2 张的：`after-any-compile`、`after-clear-cache`、`after-discard`、`after-opponent-draw`、
`after-opponent-gain-control`、`after-opponent-refresh`、`after-play`、`after-self-discard`、
`before-flip`、`before-compile`、`after-shuffle`、`after-self-rearrange`、`after-own-delete`、
`after-return`、`after-draw`、`after-delete`、`after-compile`、`after-any-rearrange`、
`after-any-clear-cache`、`after-self-compile`、`after-action-face-down-play`。

## 3. 交叉标签（不按 op 分，按"会不会换人 / 换窗口 / 换观众"分）

### A. 应答权交给**对方**（21 张；这是最该重点试的一族）

关键词：`chooser: foe` / `chooser: opp` / `chooser: holder`（前两个是显式写的，第三个是控制权持有者）。

`corruption-2, courage-0, fulcrum-0, greed-2, ice-1, inertia-1, inertia-3, lust-6, nova-0, nova-1,
plague-0, plague-1, plague-2, plague-4, psychic-0, psychic-2, psychic-3, rigidity-7, sloth-3,
war-4, wrath-4`

其中**由 trigger 触发**（也就是**在对方回合里**就可能弹选择）的 **9 张**：
`corruption-2`(after-self-discard)、`courage-0`(start,end)、`fulcrum-0`(start)、`greed-2`(start)、
`ice-1`(after-play)、`plague-1`(after-discard)、`plague-4`(end)、`rigidity-7`(end)、
`nova-0`(start,end)。

> 另外 `light-2` 的 `chooser` 是**局部变量**（`const chooser: PlayerId = ctx.player`），
> 值就是**效果属主**（源码里写明"选择权不随卡牌易主转移"）⇒ 它**不属于**这一族。

### B. 会弹 **body 级窗口**（不是选择条）

- `momentum-4`（`rearrangeSide`，唯一一张）—— 窗口只该开在操作方那一屏（T23 已修）；
- **live 控制组件重排**（不是卡效本身，是持控者的常规操作）：`controlRearrangeFlow` 出现在
  `love-2`、`fulcrum-3`、`spirit-4` 等走"刷新/控制权"的路径上；这条路的隔离是**隐式的**
  （按钮只画在"我是行动方"那一侧的信息块里），**没有腿**。

### C. 宣告（只有幸运协议才有的稀有效果，2 张）

关键词：选择请求标题以 `luck-0：宣告` / `luck-3：宣告` 开头，形状是 `select-action`，
并且会排一个**骰子特效**（`startLuckDiceFx`）。

- `luck-0：宣告1个数字（0-6）`（宣告后用阈值把牌库翻出来，还可能让你再打出）；
- `luck-3：宣告1个协议`（宣告后命中就删牌、弃牌库顶）。

### D. 揭示类（信息展示，9 张）

`clarity-1, light-2, light-4, love-4, luck-0, lust-3, lust-4, psychic-0, time-3`。
这一族走的不是"谁操作"，而是**揭示给谁看**（幽灵牌 `expiresAtTurn`）——与选择条那一族是不同的风险面。

### E. 纯数值修正（`valueModifier`，11 张，**不弹任何东西**）

`apathy-0, clarity-0, darkness-2, diversity-3, envy-0, lust-0, metal-0, mirror-0, sloth-0, smoke-2, wrath-0`

### F. 完全不产 prompt 的卡（70 张）

纯数值 / 纯改状态（抽牌、翻转、偏置、弃牌都自动做完）。它们**不可能**撞上"选择条画错屏"这一族。

## 4. 这份分类与"会不会出 bug"的对应关系

| 分类 | 会不会牵动"别人那一屏" | 现状 |
| --- | --- | --- |
| A（应答权给对方，21 张） | **会**：选择条要从操作方那屏换到对方那屏 | 座位规则已修（T23）；交叉应答链路已有一条 node 腿（`tests/net/net-cross-side-choice.test.ts`，用疫2 跑的）；**真浏览器没验** |
| B（body 级窗口） | **会**：窗口是 body 级，两个页面都读得到同一份状态 | `momentum-4` 已加座位闸门（T23 第二处）；live 控制重排只有隐式隔离，**无腿** |
| C（宣告，2 张） | **会**：骰子特效 + 宣告选择条 | 座位闸门覆盖（T23）；**真浏览器没验**（骰子落点也是未验项） |
| D（揭示，9 张） | 会：观众是"双方" | 未单独验过；揭示幽灵的可见性规则不在本次改动范围 |
| 其余（弃牌/删除/翻转/偏转/抽牌…，只要 chooser 是属主自己） | 不会：全程在操作方自己那屏 | 与 T23 那族无关 |

## 5. 未验 / 已知边界（如实写）

1. **真浏览器里两边真人各点一次**这条路（`effect-choice` 过网的完整回合）仍然没走过 —— A/B/C 三族的
   真机行为都归这一条。
2. 本分类是**代码关键词**层面的事实；`chooser` 只认了字面量（`foe`/`opp`/`holder`）与一处局部变量
   （`light-2`）。若以后有人把应答权算在别的表达式里（例如按控制权动态算），这张表**不会自动跟上**。
3. `extract-effects.mjs` 的 title 抽取有窗口上限，个别多行 `yield` 的标题会读成空（不影响 §2/§3 的
   分类与张数，那些是按 op 与 chooser 统计的）。
4. 这张表里的张数是"**用到**该效果的卡"，不是"该效果在实战里一定会触发"（很多卡有前置条件）。
