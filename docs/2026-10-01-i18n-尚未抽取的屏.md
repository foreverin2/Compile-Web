## 这份清单是**机检**的，不是给人读的备忘

`tests/i18n/unextracted-manifest.test.ts` 扫 `src/ui/**/*.ts` 的**代码位**（先剥注释，
只认字符串/模板串）里的中文字面量，并且：

1. **每一个含中文的 `src/ui/**` 文件都必须在这张表里**（新加一个屏而没登记 ⇒ 报红）；
2. 表里每一行指的文件**真的存在**（幽灵行 ⇒ 报红）；
3. "干净"的例外（目前只有 `src/ui/fx-settings.ts`）必须自证：它剩下的中文字面量
   逐条都来自 `src/i18n/zh.ts` 的**值**；
4. 表里不许留着"代码位里已经一个中文都没有"的文件（那种文件说明那一行忘了删）。

⇒ 新屏必须先登记；抽完才能划掉。

## 计数口径（**不要**当"精确待翻译句数"读）

下表"中文字面量"是 `tests/i18n/unextracted-manifest.test.ts` 的 `scanUiLiterals()`
**实测输出**（2026-10-01 的这次提交，`npx vitest run tests/i18n/unextracted-manifest.test.ts`
里那条打印腿的数）。口径：`src/ui/**/*.ts` 的代码位、**去重**、只数含汉字的字符串/模板串。

它偏大，原因写在扫描器自己的注释里：类名/`data-*` 取值/只给开发者看的字符串、
以及**卡牌文本**的显示层兜底串都会被算进去（例如 `src/ui/effects/index.ts` 那 3 条就是
卡面文案）。它的用途是**估工作量与防漏登记**，不是"待翻译 KPI"。

## D. 边界：**永远不在这张表里**（列在这里是为了说清边界）

- `src/data/cards.ts` / `cards2.ts` / `cards3.ts` / `demo.ts` / `cardEffectTags.ts` /
  `protocolRatings.ts`：中文是**数据**，被 `npm run texts:check` 与联机卡文哈希逐字钉住。
  **英文卡面走 P4 的显示层翻译表**（按 `defId` 映射，只在渲染时替换），数据一个字都不动。
- `src/core/**`：引擎的日志与提示（`log.ts` 等）。它们进日志与联机协议，翻译要同时改
  联机对端的一致性口径 ⇒ 排期在 UI 之后，且不在这条腿的判据面内。
- `src/app/privacy.ts` 的隐私说明全文：被 `tests/app/privacy.test.ts` 的整句哈希钉住。
  翻译它等于改那份哈希口径（**不是**翻译工作），要单独一轮裁决。
- `src/i18n/**`：两张表本身当然"含中文"，扫描器把这一层整层排除在外。
