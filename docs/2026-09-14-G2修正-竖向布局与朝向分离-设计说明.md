# G2 修正 · 竖向布局与朝向分离 · 设计说明（待用户确认后开工）

> 背景：G2 Task 3 我**理解错了布局**——按"3 条横带、带内上=对手/下=自己"做成了**三条横向的行**，
> 而用户要的是**三条纵向的列**。用户在验收时指出："六条链路、能量槽和协议方向都是和之前一样横着的"。
> 本文件是**重做前的规格确认稿**：先把布局与朝向逐条钉死，再动手。

---

## 1. 已确认的布局规格（用户逐条确认）

**三条线 = 三个纵向的列，并排。** 每一列从上到下依次是：

| 顺序 | 内容 | 朝向 / 生长 |
|---|---|---|
| 1 | **对手能量槽** | 在对手链路的外侧（最上） |
| 2 | **对手链路** | 竖向列；卡面 **180°**；越新的牌越**往上**长 |
| 3 | **对手协议** | 横置；原图**顺时针 90°** |
| 4 | **自己协议** | 横置；原图**逆时针 90°** |
| 5 | **自己链路** | 竖向列；卡面 **0°（原图）**；越新的牌越**往下**长 |
| 6 | **自己能量槽** | 在自己链路的外侧（最下） |

- **手牌区在页面底部水平中置**（左右留白对称）。
- **整体比现在窄、比现在高。**
- **`viewSeat = 1`（我是 P2）= 垂直镜像**：我的链路在下半部、对手在上半部，与 P1 视角完全对称。

> 推导依据（供复核）：这套规格**等价于把热座页的"每条线一行"整体旋转 −90°**。逐项对得上：
> 热座自己卡 +90° → 0°；对手卡 −90° → 180°；自己协议 0° → −90°；对手协议 180° → +90°；
> 能量槽在链路外侧端（左/右）→ 旋转后变成下/上；4 列的行 → 4 层的列，故更窄更高。

## 2. 已确认的朝向规格（用户确认）

| 对象 | 自己（在下） | 对手（在上） |
|---|---|---|
| 场上卡牌的**卡面** | 0°（原图方向） | 180° |
| **协议图** | −90°（逆时针） | +90°（顺时针） |
| **特效**（刀光/光束/粒子/边框光/飓风/闪电…） | −90° | +90° |
| **飞行中的幽灵卡** | 卡面 **0°**、附在它身上的**装饰层 −90°** | 卡面 **180°**、装饰层 **+90°** |

**用户原话**："打出的卡牌以及特效的方向都要遵守双方朝向的规则 —— 自己的卡牌原图方向就行，特效方向是逆时针 90°；对方的卡牌原图转 180 度可以，特效方向是顺时针 90°"；
关于幽灵卡："**分开：卡面跟卡牌，装饰跟特效**"。

## 3. 两处结构性后果（本次重做的核心）

### 3.1 朝向必须**分成两套**：卡面朝向 ≠ 特效朝向

现状（热座页）：**两者是同一套** —— `buildFxCard()` 直接读卡节点上的 `rot-cw`/`rot-ccw` 当作浮层卡朝向
（`effects/index.ts` 的 `buildFxCard` → `buildFxCardAt(rect, orientOf(node), …)`）。

按新规格：自己卡面 0° 而特效 −90°，对手卡面 180° 而特效 +90°。**所以 FX 层不能再"读卡牌朝向当特效朝向"**。

**建议机制**（待确认）：
1. 远程页给场上卡额外打一个**特效朝向标记**（例如 `data-fx-rot="ccw"` / `"cw"`，自己 ccw、对手 cw）。
   静态卡面仍由 CSS 决定（自己不加类、对手 `.rot-180`）—— **契约里 `.rot-cw`/`.rot-ccw` 仍然不产出**。
2. FX 层新增 `fxOrientOf(node)`：**优先读特效朝向标记**；读不到时**回退** `orientOf(node)`。
   → 热座页没有这个标记 ⇒ 回退到原逻辑 ⇒ **热座可证明零变化**。
3. 浮层卡（幽灵卡）按**特效朝向**（∓90°）构建根元素（沿用现有 `buildFxCardAt` 的"未旋转布局盒 + 中心旋转"逻辑，
   尺寸不变、footprint 仍等于 rect），**卡面图在根元素内部再本地旋转 +90°**，于是：
   - 自己的浮层卡：根 −90° × 卡面 +90° ⇒ **卡面 0°**（与场上卡一致）✓
   - 对手的浮层卡：根 +90° × 卡面 +90° ⇒ 卡面 **180°** ✓（`0 − (−90) = +90`、`180 − 90 = +90`，两处本地旋转**都是 +90°**，可复用同一段代码）
   - 而**装饰层不加任何额外旋转**，直接继承根元素的 ∓90° ⇒ **特效 ∓90°** ✓
   ⇒ 这一条的好处：**几十个特效函数一行都不用改**（它们只往克隆里 append 装饰节点）。

### 3.2 方向性从"按绝对玩家左右"改成"按座位上下"

现状：FX 的方向判断**全部按绝对玩家**，且"被盖住的卡露出的条带在**右侧**"是写死的：
- `effects/index.ts:191-193`（链端点 `owner === 0 ? right-90 : left+90`）、`fx-gen2.ts:779/878/957`、`gen3-control.ts:654`；
- `gen3-util.ts:51/66` 的 `visibleRectOf` / `clipInsetRightPct`（注释 `:5-6` 明写"覆盖者在右"）；
- 热座页的 `.stack.grow-left`（P0）/ `.grow-right`（P1）。

竖排之后：**自己向下长、对手向上长**，被盖住的卡露出的条带变成**上下横带**。
而"我是 P2 时垂直镜像"意味着方向取决于**座位**，座位↔绝对玩家的对应由 `viewSeat` 决定。

**建议机制**（待确认）：FX 层加一个**可选**的"当前视角座位"（`setFxViewSeat(seat: 0 | 1 | null)`）：
- `null`（热座默认）⇒ **走原来那套左右逻辑，一行不改** ⇒ 热座零变化是**构造性**的；
- 远程页渲染时设为 `viewSeat` ⇒ 方向判断改走"自己=下半、对手=上半"。

远程页必须**新增/替换**的类名（`grow-left/grow-right` → 竖向语义）也要一并定下来，
并把契约与 `fx-dom-contract.ts` 的 A 类清单同步（现在是 20 条）。

## 4. 明确**不变**的东西（红线）

1. **热座页观感零变化**：`styles.css` 不改；热座路径上的朝向/方向逻辑走"无视角座位"的旧分支。
2. **契约里 `.rot-cw`/`.rot-ccw` 在远程页仍不产出**（那是热座专属的横置方案）；新增的特效朝向标记是**新钩子**，要登记进契约。
3. **链路槽/协议格/能量槽/手牌区/弃牌堆/牌库这些 A 类钩子的**产出方拼写**不变**（`stack-slot p${n}`、`trash-pile p${n}`、`dataset.player/line`…），否则所有 FX 的 `querySelector` 会静默失配。
4. **`.hand` 的 DOM 顺序仍必须是绝对玩家顺序 `[P0, P1]`**（FX 按下标取手牌）。
5. **两张手牌节点仍都要产出**（对手那份是数量占位）。

## 6. 风险与已知代价

1. **改动面大**：R2/R3 触及 FX 层多处方向判断。缓解：`null` 分支保证热座走原路径，且用"热座回归"验收兜底。
2. **`viewSeat` 与 FX 的耦合**：远程页切换视角时必须同步 `setFxViewSeat`，否则幽灵卡/落点会按旧座位算。要有守卫钉住"每次渲染都同步"。
3. **覆盖条带方向**：`gen3-util.ts` 的假设从"右"改"下/上"后，被盖住卡的可见区计算要在**两种朝向**下都验证（自己侧与对手侧）。
4. **这套规则是"两套朝向并存"**，比热座的"一套"更复杂 —— 未来新增特效时必须知道"装饰层继承根元素（自动 ∓90°）、不要去动卡面"。
   必须写进契约文档与 `effects/index.ts` 的头部注释。

## 8. 用户裁决与命名（2026-09-14 确认，**开工依据**）

### 8.1 两处机制的裁决

1. **§3.1 特效朝向分离：✅ 接受**（按建议实现：远程页打标记 + `fxOrientOf` 回退 + 浮层卡根元素 ∓90° 而卡面本地 +90°）。
2. **§3.2 方向模型：✅ 接受**，但**用户明确补充**：
   > "**不需要特意去管切换玩家视角的这个功能，因为这个功能应该是放在开发者模式的功能里，用于测试用的**"

   **据此的落地口径**：
   - **切换视角 = 开发者/测试用的便利功能，不是产品功能**。因此**不为"运行时反复切换"造任何专门机制**
     （不做过渡、不做状态迁移、不做双向同步测试）。
   - 页面**每次渲染把当前座位设一次**（幂等）即可 —— 这就是全部要求。
   - 真实对局里座位由对局本身决定（我是 P0 还是 P1），页面**载入时固定**；工具条上的视角开关仍保留，
     但它属于"开发/验收用"，不追求切换过程的表现。
   - `setFxViewSeat(seat | null)` 仍然需要（`null` = 热座 ⇒ 走原逻辑，热座零变化是构造性的），
     但**它的调用点只有"渲染时设一次"这一处**，不需要任何切换专用逻辑。

### 8.2 命名（先钉死，避免实现者各自发明）

| 用途 | 名字 | 说明 |
|---|---|---|
| **特效朝向标记**（远程页场上卡） | `data-fx-rot="ccw"` / `"cw"` | **自己 = `ccw`（−90°）、对手 = `cw`（+90°）**。**新 A 类契约钩子** `[data-fx-rot]`，`requiredBy: ['fx-orient.ts']`；热座**不产出**它 ⇒ 在 `RENDERERS` 里给 `render.ts` 加 `exempt: ['[data-fx-rot]']`（正好用上已建好的 per-renderer `exempt` 机制） |
| **竖向生长** | `.stack.grow-down`（自己）/ `.stack.grow-up`（对手） | 替代热座的 `.grow-left`/`.grow-right`；**纯 CSS 语义**，契约不涉及（`.stack` 不是 A 类钩子） |
| **协议 ∓90° 视觉** | `.net-rot-ccw`（自己协议）/ `.net-rot-cw`（对手协议） | 规则写在 `styles-net.css`。**理由**：远程页仍**不产出** `.rot-cw`/`.rot-ccw`（那两个是热座专属的"卡牌横置"语义，且 `orientOf` 把它们当作**卡面**朝向读）；协议要用**自己的**类，避免和卡面朝向混淆 |
| **竖向覆盖条带** | `gen3-util.ts` 新增竖向变体（具体名字由 R3 定，须在契约文档记录） | 热座仍走原"覆盖者在右"；远程页走"覆盖者在下/上" |
| **视角座位** | `setFxViewSeat(seat: 0 | 1 | null)` | `null` = 热座（默认）；远程页渲染时设成本页 `viewSeat` |

### 8.3 由此修正 §4 红线里的两条

- `.rot-cw` / `.rot-ccw` 在远程页**仍不产出**（理由见上表第 3 行），`render-net.ts` 的 `exempt` **保留**。
- **新增一条**：`[data-fx-rot]` 只由远程页产出，热座 `exempt` —— 所以"每个渲染器必须提供全部 A 类钩子"
  这条断言要能表达"**某条钩子只属于某个渲染器**"（用 `exempt` 表达，而不是删钩子）。

### 8.4 §1 遗漏的两项布局（2026-09-14 追加确认）

§1 的规格只覆盖了链路/能量槽/协议/手牌，**漏掉了两件本来就存在于页面上的东西**。用户追加裁决：

1. **控制轨（控制权能量条）→ 改成竖向**：**自己那一端在下、对手那一端在上**，与"自己在下 / 对手在上"一致。
   - 影响：控制轨的 DOM 结构（横→竖）、`gen3-control.ts` 里按轨道实测矩形算的落点（`controlTrackSideX` 之类）、
     以及"哪一端属于哪个绝对玩家"的映射（现在要**按座位**，而不是按绝对玩家的左右）。
   - 热座**保持横向现状**（走"无视角座位"的原逻辑）。
2. **双方信息条（昵称 / 牌库数 / 弃牌堆数 / 手牌数）→ 与手牌区同一行、一左一右**（用户裁决）。
   - 即底部那一行是：**信息条 · 手牌区（居中）· 信息条**；**顶部信息条随之取消**（对手的牌库/弃牌堆计数改放在底部那一行里）。
   - **左右归属**：本设计说明**取"左 = 自己、右 = 对手"**（自左向右的自然读法）。用户未指定左右，若你要反过来，
     改一处常量即可 —— 请在上机验收时确认。
   - 归属：这是**布局**改动（R1 的范围），已安排为 R3 之后的**独立小任务**（见 §8.6）。
   - 注意红线：`.hand` 的 **DOM 顺序仍必须是绝对玩家顺序 `[P0, P1]`**（FX 按下标取手牌），
     而左右摆放是 CSS 的事 —— **不要让 DOM 顺序跟着视觉左右走**。
