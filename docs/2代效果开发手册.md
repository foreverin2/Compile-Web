## 1. 数据模型速查

全部类型定义在 `src/core/models/types.ts`。

### 1.1 基础标量（types.ts:1-3）

```ts
export type PlayerId = 0 | 1;          // 玩家座位
export type Line = 0 | 1 | 2;          // 线（列）编号，下标即线号
export type Zone = 'hand' | 'deck' | 'field' | 'trash' | 'float';
```

`float` = 浮空（pendingPlay/pendingShift 中的卡，未落场），`findCard` 会查到浮空卡。

### 1.2 卡牌实例 Card（types.ts:34-47）

```ts
export interface Card {
  uid: string;          // 实例唯一 id（nextUid() 生成 'c<n>'）
  defId: string;        // 卡定义 id（'ice-0'…，getCardDef(defId) 查面值）
  owner: PlayerId;      // 持有者
  faceUp: boolean;
  zone: Zone;
  line: Line | null;    // 在场/浮空时为所在线
  pos: number | null;   // 堆叠内位置：0=最底层，越大越靠上；null=不在场
  secret?: boolean;     // 牌堆来源的反面打出卡=非公开（playTopDeck 置 true；翻正/进手牌清 false）
}
```

静态卡定义 `CardDef`（types.ts:14-21）：`defId/protocol/value/top?/middle?/bottom?` —— 指令文本在数据层，效果注册按 defId。`getCardDef(defId)` 同时覆盖 1/2代 索引（data/demo.ts:24-28）。

### 1.3 玩家状态 PlayerState（types.ts:56-64）

```ts
export interface PlayerState {
  hand: Card[];                    // 手牌（公开，faceUp 恒 true）
  deck: Card[];                    // 牌库（末位=牌堆顶；faceUp 恒 false=秘密）
  trash: Card[];                   // 弃牌堆（公开，faceUp 恒 true）
  protocols: ProtocolState[];      // 长度固定 3，下标=线号；{ defId, compiled }
  stacks: Card[][];                // 长度固定 3；stacks[line][0]=底层
}
```

**堆叠/覆盖语义**：`stacks[line]` 末位（`stack[stack.length-1]`）= **顶卡 = 未被覆盖**；其余 = 被覆盖。新卡从牌堆顶弹出后 `stack.push`（pos = length-1）。判定顶卡用 helper：`isUncovered(s, card)`（effects/context.ts:29-33，要求 zone==='field' 且是所属堆叠末位）。

| 字段 | 类型 | 含义 |

## 2. 效果开发最小模板

### 2.1 注册 API（registry.ts:6-7）

```ts
export function registerCardEffects(defId: string, effects: CardEffects): void;
// CardEffects（types.ts:228-238）：{ middle?: EffectGen; triggers?: Partial<Record<TriggerKind, TriggerDef>>; valueModifier?: {...} }
```

### 2.2 新文件骨架（直接照抄改）

新建 `src/core/effects/cards/<协议>.ts`（例 `ice.ts`），模式与 1代 fire.ts 完全一致：

```ts
import type { EffectCtx, EffectStep, Line, PlayerId, StepResult } from '../../models/types';
import { registerCardEffects } from '../registry';
// 需要时：import { findCard, isUncovered, deckTopAvailable } from '../context';

/** <defId> <中文指令一句话>（照抄 cards2.ts 该卡注释/文本做行为说明） */
function* ice0Middle(ctx: EffectCtx): Generator<EffectStep, void, StepResult> {
  const targets = ctx.candidates({ zone: 'field' });          // 1. 取候选（见 §3）
  const ans = yield {                                          // 2. yield 选择请求 → 引擎挂起
    kind: 'select', title: 'ice-0：…', min: 1, max: 1,
    optional: false, candidates: targets,
  };
  if (ans.selected.length === 0) return;                       // 3. fizzle 守卫（见 §2.4）
  yield { op: 'shift', uid: ans.selected[0], targetLine: 1 as Line };  // 4. yield op（见 §4）
}

registerCardEffects('ice-0', { middle: ice0Middle });
```

**必做收尾**：在 `src/core/effects/resolve.ts` 顶部 import 区（resolve.ts:10-24，目前按序 import 1代 15 个 `./cards/*`）追加一行 `import './cards/ice';` —— EFFECTS 注册靠模块副作用，**漏加则引擎与测试里效果永远不生效**。

### 2.3 EffectGen 生成器语义（types.ts:218、resolve.ts:91-153）

```ts
export type EffectGen = (ctx: EffectCtx) => Generator<EffectStep, void, StepResult>;
export type EffectStep = ChoiceRequest | Op;          // yield 出去的值
export type StepResult = ChoiceAnswer | Record<string, never>;  // next() 的入参
```

- `ctx`：`{ s: GameState, player: PlayerId(效果属主), card: Card(源卡), candidates(filter) }`（types.ts:211-216；createCtx context.ts:79-81）。
- 生成器 **yield 选择请求** → 引擎把 `PendingEffect` 挂起（`pe.prompt` 置请求，resolve.ts:128-130），等玩家 `answerEffect` 后（resolve.ts:60-88），**yield 表达式求值为该请求的答案对象** `{ selected: string[] }`。
- 生成器 **yield Op** → `executeOp` 同步执行（resolve.ts:132-135），yield 表达式求值为 `{}`。
- 若执行 op 后产生浮空卡（shift/playTopDeck/playFromHand），runStack 会**先落地（含 before-covered 连锁）再恢复生成器**（resolve.ts:135、137-138），生成器感知不到中断。
- 生成器结束后按 id 移除（resolve.ts:102-112）——内部可能已 push 新效果（如 fireReactive），栈顶 ≠ 自己。

### 2.4 三个 ChoiceRequest kind 的完整对象形状（types.ts:98-111）与应答消费

```ts
export interface ChoiceRequest {
  kind: 'select' | 'select-line' | 'select-action';
  title: string;
  min: number; max: number; optional: boolean;
  candidates: ChoiceCard[];     // select：候选卡（必填）
  lines?: Line[];               // select-line：候选线，答案编码 'line:N'
  actions?: string[];           // select-action：可执行操作，答案编码 'action:<name>'
  chooser?: PlayerId;           // 选择权归属；缺省 = PendingEffect.player（效果属主）
}
```

| kind | 形状要点 | 消费（`pe.lastAnswer.selected`，即 yield 返回值） |
|---|---|---|
| `select` | `candidates: ChoiceCard[]`（空数组=无合法目标） | `ans.selected: string[]` = 选中卡 uid 数组；`findCard(s, uid)` 复查 |
| `select-line` | `lines: Line[]`；`candidates: []` | 每个元素是 `'line:N'` 字符串：`Number(ans.selected[0].replace('line:','')) as Line`（例 darkness.ts:15） |
| `select-action` | `actions: string[]`；`candidates: []` | 每个元素是 `'action:<name>'` 字符串，直接与动作名比较（例 death.ts:28-30） |

- `optional:true` + 空应答 `[]` = 玩家选择跳过；`optional:false` 时答案必须满足 `min ≤ len ≤ max`，否则 answerEffect 抛错（resolve.ts:65-66）；重复选择与越界 uid 也会抛错（resolve.ts:68-84）。
- **ChoiceCard 形状**（types.ts:86-95）：`{ uid, defId, faceUp, owner, zone, line, pos, label }`，`label = String(getCardDef(defId).value)`（context.ts:40-46）。生成器可直接 `ctx.candidates()` 得到它，也可自行构造（1代 有先例：speed.ts:104-113 手动 push ChoiceCard）。
- `chooser` 示例：让**被作用方**选自己的手牌/卡（psychic-0/plague-0 的「对手弃牌」用 `chooser: opp`，psychic.ts:17）；UI 经 `executeAction('effect-choice')` 校验 `prompt.chooser ?? top.player === 玩家`（game.ts:138-143）。

**最小生成器模板（带守卫）**：

```ts
function* xxx(ctx: EffectCtx): Generator<EffectStep, void, StepResult> {
  const hand = ctx.candidates({ zone: 'hand', owner: ctx.player });
  const ans = yield { kind: 'select', title: 'xxx：…', min: 1, max: 1, optional: false, candidates: hand };
  if (ans.selected.length === 0) return;   // 无牌可弃/无目标 → fizzle
  yield { op: 'discard', uid: ans.selected[0] };
}
```

### 2.5 「无合法目标自动 fizzle」语义与守卫写法惯例

- 实现点：resolve.ts runStack **115-131** 行 —— 生成器 yield 出选择请求时，若按 kind 判定「无合法目标」（select 看 `candidates.length===0`、select-line 看 `lines` 空、select-action 看 `actions` 空，resolve.ts:119-122），引擎**不挂起**，记录日志 `'无合法目标，该步骤跳过'` 并以空答案 `{ selected: [] }` 恢复生成器（resolve.ts:123-126）。**因此生成器必须能容忍空答案**。
- 1代 惯例（fire.ts:8、16 等全部文件）：yield 后立刻 `if (ans.selected.length === 0) return;` —— 这样：
  - 必选步骤无目标 → 跳过**该步**（若后续还有独立句子，则继续，如 fire-0 跳过 flip 仍 draw 2）；
  - 可选步骤 → 本就该跳过；
  - 多句效果（FAQ 39「每句独立」）→ 每句各自守卫，前句 fizzle 不影响后句（plague-4 注释 plague.ts:78-96）。
- **op 自身也会抛错兜底**（如 `draw` 两堆皆空、`shift` 目标=原线），所以生成器里能提前守卫就提前守卫（love.ts:9-12 双空提前 return）。

## 3. ctx.candidates()：候选过滤与「绑定规则」

### 3.1 签名与返回

```ts
// types.ts:204-208
export interface CandidateFilter { zone: 'hand' | 'field'; owner?: PlayerId; covered?: boolean; }
// context.ts:79-81：ctx.candidates(filter) => ChoiceCard[]
```

### 3.2 语义（context.ts:49-77 listCandidates，勿改）

- `{ zone: 'hand', owner }`：列某玩家全部手牌（不排除任何卡）。
- `{ zone: 'field' }`（无 owner）：列**双方每条非空堆叠的顶卡**（未覆盖卡），owner 限定则只列该玩家。
- `{ zone: 'field', covered: true }`：列堆叠中**被覆盖**的卡（`stack[0..len-2]`，排除顶卡）。
- **binding 排除规则**：`const resolving = new Set(s.pendingEffects.map(pe => pe.sourceUid))`（context.ts:50）——**所有结算中效果（含本次触发）的源卡 uid 一律排除**（幽灵状态防护：防效果结算中源卡被自己选中/被连锁中移动的卡污染）。即 `{zone:'field'}` 自动实现了「另1张」/「此卡之外」的排除；`covered:true` 也排除。**实现者勿自行把源卡塞回候选**——除文本明确含自己（如 hate-2「你分值最高的牌」可删自己、speed-3 end 可平移自己）时按 1代 先例手动补回（hate.ts:101-114、speed.ts:102-114）。
- 顶卡移除后被「揭开」的新顶卡由引擎自动 pushMiddle（revealAfterRemoval，resolve.ts:510-514），与候选无关。
- 反面牌/特定线/特定分值等**进一步过滤在生成器内做**（1代 惯例 filter 链）：
  - `filter(c => !c.faceUp)` 反面（light.ts:24-27、death.ts:67）；
  - `filter(c => c.owner !== ctx.player)` 对手的（darkness.ts:21）；
  - `filter(c => c.line === l1)` 指定线（death.ts:14、19）；
  - 面值过滤用 `getCardDef(c.defId).value` 或 `cardPointValue(s, c)`（见 §6.4），如 death-4（death.ts:75）、hate-2（hate.ts:51-60）。
- **「此列所有卡/双方堆叠」等批量遍历不走 candidates**，直接读 `s.players[owner].stacks[line]` 并快照 uid 数组后逐张 op（water.ts:44-54、death.ts:45-63、apathy.ts:28-41）。

## 4. Op 原语清单（resolve.ts:156-458 executeOp）

每个 op 的输入、执行语义、抛错条件、副作用（事件 / fireReactive / 揭开）。`allowCovered?: boolean` 语义统一：缺省 `false` 时 op 对**被覆盖**的目标抛错（`cannot ...: covered card`）；`true` 时允许操作被覆盖卡（删/回/翻/移自己或全场批量时的必备开关）。`pe` = 当前 PendingEffect；「效果属主」= `pe.player`。

| Op（types.ts:148-161） | 输入 | 执行语义 / 抛错 | 事件 | 即时连锁 / 其它副作用 |
|---|---|---|---|---|
| `discard` | `uid` | 卡必须在手牌（resolve.ts:160）；按**卡 owner** 弃入其 trash（正面） | `card:discarded`（带 triggerDefId/triggerProtocol，164-167） | `fireReactive('after-discard', card.owner)` —— 触发**弃牌者的对手**侧（170，见 §5.2） |
| `discardMany` | `uids: string[]` | 全部在手牌且**同一 owner**（409-411）；逐个弃（FAQ 94：批量=单次动作）；空数组 no-op | 每张各发一次 `card:discarded` | after-discard 只触发**一次**（420） |
| `delete` | `uid, allowCovered?` | 必须在场（229）；未允许时不能删被盖卡（230）；从堆叠任意位置移除（含中部，237）→ 持有者 trash 正面 | `card:deleted`（244-247） | `fireReactive('after-delete', owner)`（被删卡持有者侧，250）；`wasTop` 时 `revealAfterRemoval`（251）——**编译删除不经此路径、不触发任何文本** |
| `return` | `uid, allowCovered?` | 必须在场（256）；移除入**持有者手牌**（secret=false 解禁，265-271）；`wasTop` → 揭开 | `card:returned`（274-277） | 无 fireReactive（没有 after-return） |
| `flip` | `uid, allowCovered?` | 必须在场（204）；未允许不能翻被盖卡（205）；**若目标正面朝上且注册了 before-flip → 先结算该触发并中断本次 flip**（211-212，metal-6 先删自己）；反面翻正 = 公开 → `secret=false`（216）；翻正且未被覆盖 → pushMiddle 连锁中指令（224，FAQ 127：被盖卡翻正不连锁） | `card:flipped`（219-222） | 无 fireReactive |
| `draw` | `count, player?, fromOpponentDeck?` | `player` 缺省=效果属主；普通抽：`drawCards`（deck.ts:14-42，牌库空自动洗弃牌堆重组再抽，双空则抽 0 不抛错）；`fromOpponentDeck:true`：从对手牌库顶弹 1 张（对手库空先洗其 trash，两者皆空**抛错**，177-187），owner 变更给 `target`，进 target 手牌 | `card:drawn`（194/199） | 普通抽由 drawCards 内部 `fireReactive('after-draw', player)`（真抽到才触发，deck.ts:40）；fromOpponentDeck 分支在 executeOp 内 fireReactive（195） |
| `shift` | `uid, targetLine, allowCovered?` | 必须在场（283）；未允许不能移被盖卡（284）；**targetLine ≠ 卡当前线**（否则抛错，285）；从原堆叠移除 → `zone='float'`、`line=targetLine` → `pendingShift` 队列（293-296）；`wasTop` → 揭开（304） | `card:shifted`（带 fromLine，299-303） | 落地 completeShift：目标线顶卡先结算 before-covered（若正面注册），**落地不发中指令**（491-507，只发 `card:landed`） |
| `playTopDeck` | `line, faceUp, player?, belowUid?` | `player` 缺省=效果属主（gravity-6 传对手，309）；**从 target 牌库顶 pop，不洗弃牌堆**（FAQ 142，313；牌库空抛错——生成器应先用 `deckTopAvailable` 守卫）；`secret = !faceUp`（319）；入 pendingPlay | `card:deck-played`（325-329） | 落地 completePlay：目标顶卡 before-covered → `card:played` → 正面则 pushMiddle（463-488）。`belowUid`：插入源卡下方、源卡保持未被覆盖（gravity-0，见 gravity.ts:10-18） |
| `playFromHand` | `uid, line, faceUp` | 卡必须在手牌（334）；从**持有者**手牌移除 → 浮空 pendingPlay | `card:hand-played`（346） | 落地同 playTopDeck（card:played + 正面 pushMiddle）；**效果授予的打出不走 playCard → 不受 A2 限制**（speed.ts:9-10 注释，卡牌文本优先） |
| `rearrangeProtocols` | `a, b, player?` | `player` 缺省=效果属主（psychic-2 传对手）；`a≠b`（353）；交换 target 玩家两个协议槽位整体（defId 与 compiled 一起动，349-359），**场上卡与堆叠不动** | `protocols:rearranged`（gameBus，361） | 无 |
| `give` | `uid, to` | 卡必须在其持有者手牌（367）；移交 `to` 手牌并 owner=to（373-374） | `card:given`（带 to，377-381） | 无 |
| `takeRandom` | `from: PlayerId` | from 手牌非空（387，空抛错——生成器先守卫）；`Math.random` 取 1 张给效果属主（owner 更新，388-391） | `card:given`（to=效果属主，394-398） | 无 |
| `reveal` | `uid` | 任意 zone 卡可揭示（433-434）；**不改原卡**，生成幽灵牌 `RevealedGhost`：Case A（自己的卡给对手看）`shownTo=对手, expiresAtTurn=turnCount+2`；Case B（对手的卡给自己看，如 light-4/psychic-0）`shownTo=发起者, expiresAtTurn=turnCount+3`（436-442，过期在回合转换时清除，turn.ts:38-39）；`lightFx` 当源协议 === 'light'、`fx:'love'` 当源协议 === 'love'（444-446）——2代 若要专属幽灵特效需扩展 RevealedGhost 字段（引擎改动） | `card:revealed`（带 shownTo，450-454） | 无 |

**源卡有效性检查**（sourceValid，resolve.ts:32-38）——效果栈每次取栈顶时检查：源卡必须仍在场、正面、**未被覆盖**（`topCommand` 效果跳过未覆盖检查；`system` 效果恒有效）。不满足 → 该效果**整体终止**并记日志 `效果终止：…`（resolve.ts:96-98）。所以「删/回/移自己」的效果把删自己放最后（death-2 注释 death.ts:42-44），或利用此机制自然截断后续句子（hate-2 删到自己即终止，hate.ts:65）。

## 5. 触发系统

### 5.1 TriggerKind 全集（types.ts:73-83）

```ts
export type TriggerKind =
  | 'before-covered'   // 被盖住前（顶卡检查；fire-0/life-3/hate-4/apathy-2 底、metal-6 顶）
  | 'end'              // 结束阶段收集（fire-3/light-1/psychic-4…）
  | 'start'            // 开始阶段收集（death-1/spirit-1/psychic-1…）
  | 'after'            // 旧预留，未用
  | 'before-flip'      // 翻转前（flip op 前置；metal-6 顶）
  | 'before-compile'   // 通过编译删除前（executeCompileUnchecked 收集；speed-2 顶）
  | 'after-draw'       // 抽牌后（即时连锁）
  | 'after-discard'    // 弃牌后（即时连锁）
  | 'after-delete'     // 删除后（即时连锁）
  | 'after-clear-cache'; // 清理缓存后（即时连锁）
```

TriggerDef（types.ts:220-226）：`{ fn: EffectGen; optional: boolean; top?: boolean }`。
- `top: true` = **顶命令**（被覆盖仍生效）；缺省（底命令）= 仅未被覆盖生效。
- `optional: true` 的触发在 end/start 收集时**不阻止 advance**（game.ts:67-69、177-179），UI 可跳过。

### 5.2 start/end 收集 collectTriggers（triggers.ts:67-87）

- **只收集回合玩家**（`s.turnPlayer`）场地侧（triggers.ts:70）；`after` 等其它 kind 预留双方。
- 遍历该玩家三条线全部堆叠（triggers.ts:71-85）：只收 **faceUp** 卡中注册了该 kind 的卡；跳过 `resolvedTriggerUids`（本次 start/end 已结算的）。
- 顶卡（未覆盖）：top 与 bottom 都收；**被盖卡：仅收注册了 `top:true` 的顶命令**（triggers.ts:80-81，FAQ 98/99）。
- 返回 `TriggerEntry[]`（types.ts:194-201：`{ cardUid, defId, kind, optional, top? }`），UI 在 start/end 步骤逐个 `executeAction('resolve-trigger', { cardUid })` 出按钮（game.ts:60-70、145-157）。
- `resolvedTriggerUids` 进入 end/start 步骤时清空（turn.ts:24-26）；每次 `collectTriggers` 重新收集（结算中新暴露的触发会出现在后续收集）。

### 5.3 即时连锁 fireReactive（triggers.ts:14-35）——after-* 家族

```ts
export type ReactiveKind = 'after-draw' | 'after-discard' | 'after-delete' | 'after-clear-cache';
export function fireReactive(s: GameState, kind: ReactiveKind, actor: PlayerId): void;
```

- **只 push 不 runStack**——由外层 runStack 循环 LIFO 结算（triggers.ts:8-9 注释）。
- 收集范围按 kind 固定：
  - `after-discard`：遍历 **actor 的对手**（plague-1「对手弃牌后」）
  - 其余三种：遍历 **actor 自己**（spirit-3 抽牌后 / hate-3 删除后 / speed-1 清缓存后）
- 遍历该玩家**全部三条线堆叠的所有卡**（不只顶卡），faceUp 且注册了该 kind → push（推入的效果**恒带 `topCommand: true`**，被盖仍生效，triggers.ts:22-31）。
- 触发点（谁调用 fireReactive）：
  - after-draw：drawCards 真抽到牌时（deck.ts:40，覆盖所有抽牌路径）+ fromOpponentDeck 分支（resolve.ts:195）；
  - after-discard：discard（resolve.ts:170）/ discardMany（420）op；
  - after-delete：delete op（resolve.ts:250）；
  - after-clear-cache：系统清缓存生成器（game.ts:214）与 advance 防御路径（game.ts:183）。
- **引擎缺口（2代 需要）**：kind 是封闭联合，且方向硬编码（弃牌→对手侧、其余→自己侧）——mirror-4「对手抽牌时：你抽1张」、peace-4「在对手回合中你弃牌时：抽1张」、war-0/1/2、assimilation-1（刷新/编译反应）等无法用现成 fireReactive 表达，需扩展引擎（见 §12）。

### 5.4 单卡触发点（before-covered / before-flip / before-compile）

| kind | 触发点 | 语义 |
|---|---|---|
| `before-covered` | completePlay（resolve.ts:472-475）/ completeShift（497-500）：浮空卡落地/偏转落地前，若目标堆叠**顶卡**正面且注册了该 kind → 先结算它（每张目标顶卡只结算一次，PendingLanding.beforeCoveredDone） | 例：fire-0 被盖前先抽 1 翻 1（fire.ts:12-18）；apathy-2 被盖前先翻自己（apathy.ts:47-49）；hate-4 被盖前删本列最低分被盖卡（hate.ts:92-116）；metal-6 被盖前先删自己（metal.ts:85-87）。**注**：2代 unity-0 底「被此协议牌覆盖时」可在生成器内看 `ctx.s.pendingPlay[0].card.defId` 判断盖牌是否 unity 卡（before-covered 结算时盖牌仍在 pendingPlay 队首） |

## 6. valueModifier：改总值

### 6.1 注册形状（types.ts:233-237）

```ts
valueModifier?: {
  target: 'own-stack' | 'opponent-line' | 'line';
  apply(s: GameState, owner: PlayerId, line: Line, total: number): number;
};
```

### 6.2 三种 target 语义与 apply 的 owner 参数

在 `stackValue`（state/create.ts:249-273，单线总值入口）中遍历该线**双方堆叠所有 faceUp 卡**（背面无效果），按卡所属 owner 与估值方 player 决定：

| target | 作用对象 | apply 的 `owner` 实参 | 1代 实例 |
|---|---|---|---|
| `own-stack` | 只作用于**修正卡拥有者**自己该线的估值 | 修正卡持有者（循环 owner） | apathy-0「此列每张反面牌给你此列总分+1」（apathy.ts:19-21、80-82） |
| `opponent-line` | 只作用于**对手**同线总值 | 修正卡持有者 | metal-0「对手此列总分减2」（metal.ts:8-10、89-92） |
| `line` | 双方估值都生效（线上任一方有正面修正卡即激活，每估值只应用一次，lineMod 防多张叠加） | **估值方 player**（使修正按估值方堆叠计算） | darkness-2「此列反面牌分值4」（darkness.ts:45-49、83；apply 数 `s.players[owner].stacks[line]` 反面数，owner=估值方） |

修正是「顶命令按卡计」：own-stack/opponent-line 每张正面卡各自 apply（多张叠加）；`line` 每线至多应用一次。

### 6.3 总值计算入口（谁读 stackValue）

- `getLineValue(s, player, line)` = stackValue（create.ts:284-286）；
- 编译条件 `canCompileLine`：own ≥ 10 且 own > opp（rules/compile.ts:7-13）；
- 控制权 `checkControl`：统计 2+ 线领先（rules/control.ts:7-19）。
- 1代 其它改总值的卡：darkness-2（line）、metal-0（opponent-line）、apathy-0（own-stack）。**2代 同类**：smoke-2/ice-1?（ice 集无）——实际 2代 见 §9/§12 对应（mirror-0「对手每有1张牌你的总值+1」= own-stack 按对手该线张数；clarity-0、diversity-3、smoke-2 等均可用 valueModifier，按文本裁决 target 与分母）。

### 6.4 单卡分值 cardPointValue（与总值不同，按单卡查询）

`cardPointValue(s, card)`（create.ts:293-299）：牌库卡恒 2（秘密）；正面 = 牌面值；反面 = 2，但所在线有正面 darkness-2 顶命令 = 4。供 light-0 抽牌数（light.ts:14）、water-3/death-2/hate-2/plague 过滤用。**2代 文本中的「阈值」= 单卡分值**，实现时优先用 `cardPointValue`（对 darkness-2 修正一致）还是 `getCardDef(defId).value`（纯牌面值）需按句意裁决（1代 两口径都有先例：water-3 用 cardPointValue、death-4 用 getCardDef().value）。

## 7. 回合与动作流

### 7.1 Step 枚举与推进（types.ts:4-10、engine/turn.ts:3-10）

```ts
export type Step = 'start' | 'check-control' | 'check-compile' | 'action' | 'check-cache' | 'end';
export const STEP_ORDER: Step[] = ['start','check-control','check-compile','action','check-cache','end'];
```

`advanceStep(s)`（turn.ts:17-41）：STEP_ORDER 顺序推进，绕回 'start' 时换人（`turnPlayer` 翻转）、`compiledThisTurn=false`、清除 compileBlocked（若轮到被禁玩家结束）、`turnCount+1`、清除过期幽灵。`compiledThisTurn` 为真时跳过 'action' 直达 'check-cache'（turn.ts:20-22）。进入 'end' 或 'start' 时清空 `resolvedTriggerUids`（turn.ts:24-26）。

### 7.2 玩家动作入口（src/core/game.ts）

`ActionKind = 'play' | 'refresh' | 'compile' | 'advance' | 'effect-choice' | 'resolve-trigger' | 'clear-cache'`（game.ts:17）。UI 一律走 `executeAction(s, player, kind, args?)`（重载 game.ts:92-97；守卫 game.ts:98-104：非回合玩家只能 effect-choice、挂起中只能应答）。

- **play**（game.ts:107-117）→ `playCard(s, player, uid, faceUp, line)`（actions/base.ts:32-57）：先查手牌 → A2 限制守卫（§8）→ 从手牌移除、浮空 pendingPlay → **runStack 立即结算**（含 before-covered、落地、中指令）→ 栈空则 advanceStep，否则 `pendingStepAdvance = true` 由后续 runStack 消费。
- **refresh**（game.ts:118-126）→ `resetControlIfHeld`（控制回中立）+ `refreshHand`（base.ts:60-64：手牌 <5 抽至 5，≥5 抛错）。
- **compile**（game.ts:127-135）→ `resetControlIfHeld` + `executeCompile(s, player, line)`（rules/compile.ts:55-60：先 `canCompileLine` 校验）→ executeCompileUnchecked（compile.ts:31-52）：**收集该线双方正面 speed-2 → pendingCompile + resolveTrigger(before-compile) → runStack 结算**，全部完成后 runStack 消费 pendingCompile 执行 `executeCompileBody`（resolve.ts:140-145）。
- **compile-body**（rules/compile-body.ts:10-63）：双方该线堆叠整体入 trash → 协议未编译则置 compiled，已编译则抽对手牌库顶 1 张（owner 变更）→ `compiledThisTurn=true` → 三协议全编译 → winner。发 `line:compiled` 事件（compile-body.ts:28-37）。**编译不触发任何文本/连锁**。
- **effect-choice**（game.ts:136-144）：校验 `prompt.chooser ?? top.player === player` → `answerEffect`。
- **resolve-trigger**（game.ts:145-157）：step 必须在 end/start；`collectTriggers` 复查 → resolveTrigger(topCommand: t.top) → runStack → push resolvedTriggerUids。
- **clear-cache**（game.ts:158-164）：见 7.4。
- **advance**（game.ts:165-190）：强制项守卫（check-compile 必须编译、action 空手必须 refresh、check-cache 超 5 必须清缓存、end/start 有必选触发不得跳过）→ 防御路径清缓存弃牌后 fireReactive after-clear-cache（183）→ check-control 时执行 checkControl（186）→ advanceStep。
- 效果/触发结算期间 UI 只允许应答选择（game.ts:37、101-104）。

### 7.3 效果驱动的「伪动作」（生成器内直接做，1代 先例）

- **效果内刷新**：`resetControlIfHeld(ctx.s, ctx.player)` + 手算 `need = 5 - hand.length` 后 `yield {op:'draw', count: need}`（spirit.ts:9-14、love.ts:32-38；分两次 draw 各自触发 after-draw）。
- **效果内打出**：`yield {op:'playFromHand', …}` / `playTopDeck`，不走 playCard 因此**不受 A2 限制**（speed-0 注释 speed.ts:9-10）。
- **效果内改状态**：直接改字段合法（metal-1 设 `ctx.s.compileBlocked`，metal.ts:23-26）；需要洗牌等可 import `shuffleWith(s, arr)`（G0 起 `deck.ts` 不再导出 `shuffle`，该 API 已并入 `src/core/rng.ts`）。**2代 新机制大量依赖此模式**（见 §12）。

### 7.4 抽牌超 5 清缓存

- 抽牌只在 draw 完成时检查手牌上限？——不是 drawCards 内检查，而是回合步骤 `check-cache`：若手牌 >5 且无 spirit-0 底（shouldSkipCacheCheck，restrictions.ts:62-64），`getLegalActions` 只给 `clear-cache`（game.ts:71-78）。
- `clear-cache` → `beginCacheClear`（game.ts:219-233）：push 系统效果 `cacheClearGen`（game.ts:200-216，`system:true` 跳过源卡检查）→ 玩家自选弃 excess 张 → discardMany（单次动作）→ fireReactive after-clear-cache（speed-1 顶抽 1）。
- advance 的防御路径（玩家手牌>5 却 advance，正常被拦）也会 `clearCache`（deck.ts:59-74 弹出末尾几张）后 fireReactive（game.ts:181-184）。

### 7.5 compileBlocked（metal-1）

- 效果设 `s.compileBlocked = 对手`（metal.ts:25）；`canCompileLine` 开头检查（compile.ts:9）；被禁玩家回合结束（end→start 换人）时清除（turn.ts:31-32）。

## 11. FX/事件层影响点

### 11.1 事件总览

- `gameBus`（events/bus.ts:28）全局单例：`subscribe(fn: (e: GameEvent)=>void): ()=>void`；`GameEvent = { type: string; state: GameState; payload?: unknown }`（bus.ts:3-7）。UI 特效层订阅（ui/effects/index.ts:1700-1890）。
- `emitCardEvent(s, type, card, extra?)`（effects/context.ts:84-99）：自动把 payload 组装为 `{ uid, defId, protocol: defId.split('-')[0], owner, faceUp, zone, line, pos, ...extra }` —— **protocol = 卡协议名**，FX 层据此做协议命名空间分发（ui/effects/index.ts:1792-1809 例：按 `payload.triggerProtocol` 叠加 death/hate 特效）。2代 新协议特效只认 protocol 名即可，引擎侧无需新事件（**只要走现成 op**）。

### 11.2 事件名 ↔ 由谁发出（含 payload 要点）

| 事件 | 发出处 | payload 要点 |
