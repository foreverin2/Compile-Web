## 4. 跑门的纪律（都是踩过的坑）

- **串行跑 CDP 门**，不要两个门同时开（并发会让"真鼠标/等待"型判据相互造红）。
- **跑门期间不要改 `src/`**：会触发 Vite 全页重载，把正在跑的门打断（计划 §9 第 28 条那次 1 红就是这么来的）。
- **同一时刻只允许一个全量 `vitest`**：多个 agent 并行时，另一个只跑自己相关的文件；
  看到"跨任务"的红，先看那几个文件的 `mtime` 是不是还在动（计划 §9 第 73 条）。
- **门禁要留原文**：产物放 `.superpowers/g5-final/` 或该任务自己的目录；提交信息里写清那一刻的数字。
- 报数字之前先看**退出码**：\(exit \ne 0\) 且"失败 0 条"、或输出里有 `(0 test)`，都算硬错误，不许当成通过。

## 5. 提交与推送

- 提交只 `git add` **任务边界内**的路径（显式路径，别 `git add -A`）；越界要单独说明。
- 推送口径（用户 2026-09-21）：**不用每次问，也不要推得太勤**；一个阶段收口、门禁全绿就自己判断推。
- 推失败的第一条排查是**先试直连**（本机 `~/.gitconfig` 给 github 配了 `127.0.0.1:7890` 的代理，
  代理没开时会挡住本来能用的直连）：
  `git -c "http.https://github.com.proxy=" -c "https.https://github.com.proxy=" -c "http.proxy=" -c "https.proxy=" push origin main`
  直连被 reset 就回到默认代理配置。两条都失败 ⇒ 说一句"这次没推上去"，把提交留在本地，**不要反复变着法重试**。

## 6. 收工清理（别把一个阶段的临时件留给下一阶段）

- 临时件一律在 `.superpowers/<任务>/`（已 gitignore）。阶段性清理时**保留** `*REPORT*.md`、
  `*REVIEW*.md` 与门禁原文，删镜像与截图副本。
- **删 `.superpowers` 下的 `node_modules` 之前先认 junction**（`Get-Item <dir> | Select-Object LinkType,Target`），
  只能用 `cmd /c rmdir` —— 用 `Remove-Item -Recurse` 会递归删进真仓（2026-09-21 那次把真 `node_modules` 清空过）。
  **2026-09-23 实测又踩到同族的一个坑（这次没造成损失，但要记住）**：`cmd /c rmdir` 的路径**必须用反斜杠**
  —— 我写成 `.superpowers/g5-T20/mirror-cleanup/node_modules` 时 cmd 把 `/g5-T20` 当成开关，直接报
  `Invalid switch - "g5-T20"`；而脚本**没有检查就接着 `Remove-Item -Recurse -Force` 了**（等于走了那条禁路）。
  这次 PowerShell 7 没有跟着 junction 递归、真 `node_modules` 完好（随后 `tsc --noEmit` exit 0、
  `vitest` 20/20、`npm run build` exit 0 三条自证）。**正确顺序**：
  ① 反斜杠路径 `cmd /c rmdir "……\node_modules"`；② `Test-Path` 确认返回 false（junction 真的没了）；
  ③ 再 `Remove-Item -Recurse`；④ 清完立刻跑一次 `npx tsc --noEmit` 自证工具链还在。
- **镜像与快照垃圾要定期清**（2026-09-23 清了一次，读数供参考）：`.superpowers` 从 **1714.5 MB 降到 273.9 MB**

## 7. 变异纪律（2026-09-24 两条实测教训，都会把未提交的活弄丢或弄假）

- **变异前先备份到 `.superpowers/<任务>/`，绝对不要用 `git checkout -- <file>` 还原**：它回的是 **HEAD**，
  会把工作区里**未提交**的改动一起抹掉。T29 的评审就这么干过一次 —— 把实现者那 79 行未提交的追加块抹了；
  靠会话里留存的原始 diff 逐字重建、再用 sha256 对死（`26498` 字节 / `5B043A10…`）才救回来。
  还原口径永远是"回到变异前那一版"（备份文件或 diff），不是"回到 HEAD"。
- **"整段注释掉"这种变异手法在这张样式表上不可靠**：`src/ui/styles-library-filter.css` 文件头的大注释里
  本身嵌着**未闭合的注释起始符**，外面再包一层 `/* … */` 会被它提前结束 ⇒ 变异体看着像改了、浏览器里其实仍然生效
  （T29 评审实测：包注释后 1100 档仍单列、读数与还原态一模一样）。**要变异就物理删除**，
  并用 `git diff --numstat` 的增删数 + sha256 证明"落地了"与"还原了"。

## 8. 数字口径（引用任何自报数字之前，自己量一遍）

- **行数**：同一份文件用不同工具数出来**不一样**。2026-09-24 实测：`T31-REVIEW.md` 实现者/评审自报 **23 行**，
  实际 `wc -l` = **32**；`T29-REPORT.md` 自报 34 行、实际 **42**；`T27-REVIEW.md` 自报 37 行、实际 **52**；
  `T28-REPORT.md` 自报 78 行、实际 **80**（`T27-REPORT.md` 的 93、`T28-REVIEW.md` 的 46 是对得上的）。
  ⇒ **统一口径用 `wc -l`**（或 `node -e` 数 `\n`），**引用别人自报的行数前先自己数**。
- **长 Markdown 的行数不要用 PowerShell 的量法**：`(Get-Content <f>).Count` 与 `Measure-Object -Line`
  在 `docs/2026-09-17-G5-传输层联机-实现计划.md` 上给出 **1280**，而真实是 **1503 行**（`node` 数 `\n`：
  1502 个 LF、0 个 CR）⇒ 写进文档的"`文件:行号`"以 `Select-String` 报的行号为准，别用这两个 cmdlet 的数。
- **同一含义的数字只留一个口径**：条数（`vitest` 用 "文件数 / 条数"）、门禁判定（"判定 N 项 / 通过 M"）、
  指纹（前 8 位 + 字符数）—— 提交信息与文档里照这个写，别混用"用例/测试/条数"。
