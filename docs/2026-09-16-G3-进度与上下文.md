### 4.3 存储 / PWA / 发布

**⑦ 探针键在"set 成、remove 抛"的坏后端上会残留一条。**
事实：`src/app/storage.ts:181-185` 的 `probeWritable` 是 `set → get → remove`；`remove` 抛时探针键（`L1_PROBE_KEY` = `compile:l1-probe`，`:118`）留在磁盘上。
代价：磁盘上会多一条 `compile:l1-probe=1` 的垃圾键。**已用腿如实钉住，且刻意不清理**：清理要在授权前引入 `remove`，那正是红线 3 要避免的动作。

**⑩ 部署必须走 `npm run build`。**
事实：`package.json` 的 `build` = `tsc --noEmit && vite build && node scripts/gen-sw-manifest.mjs`；`npx vite build` 只把 `public/sw.js` 原样拷进 `dist/`（`public/sw.js:44` 的 `CURRENT_VERSION = '__SW_VERSION__'` 占位留在产物里，`:47` 的 `isRealVersion` 判否）。
代价：**若用 `npx vite build` 发布**，`dist/sw.js` 没有版本戳 ⇒ SW 只在 `sw.js` **字节**变化时重装 ⇒ 内容型发布既不提示更新、离线也永远停旧版（Task 8 修复轮的真 Chrome 三步实测）。**当前没有任何常驻判据保证"发布走了 `npm run build`"** —— 这条只能靠纪律。

**⑪ 版本键只覆盖 app shell。**
事实：`scripts/gen-sw-manifest.mjs` 扫的是 `dist/` 的清单文件（页面/脚本/样式/图标）。
代价：**只改卡图/PDF 的发布不换戳、不提示更新**；玩家可能长期看到旧图。缓解：那些资源本来就不在预缓存里（`privacy.ts` 的 `offlineCacheNote` 已如实说明）。

**⑫ `compile-` 前缀是 origin 级共享。**
事实：`public/sw.js:28` 的 `CACHE_PREFIX = 'compile-'`（缓存名 = `compile-<version>`）。
代价：同一 origin 下两份产物（例如把新版本放到 `/beta/`）的 SW 会**互删对方的 `compile-*` 缓存**（`activate` 按前缀清理）。**⚠️ 这条是推理，未实测** —— 如实标注，别当成已验证结论。

## 5. 三条事故与方法学教训（事实 / 代价 / 由此产生的硬性协议）

### 5.1 教训一：**文本腿会把实现带歪**（B-1）

- **事实**：`navigator.serviceWorker.register(...)` 被改成 `globalThis.serviceWorker.register(...)`，理由是"躲开一条**文本正则**"。
- **代价**：**真实浏览器里 PWA 从不注册** —— 437 项预缓存 / 离线可开 / 更新提示**全部未达成**，而 `tsc` / `vitest` / `vite build` / `texts:check` **四道门禁全绿**。修它的是 `7c1e3c3`。
- **硬性协议**：**行为腿 > 文本腿**。能用"跑一次拿返回值"或"真浏览器里看一眼"证明的，不许用"读源码找字符串"证明；当一条文本腿**逼着你把实现改成更差的写法**时，**改腿**，不是改实现（本节正是 `tests/app-purity.test.ts` 用**调用形态**而不是字面命中的原因）。

### 5.2 教训二：**就地变异造成交叉污染**（禁止在共享工作树里注入）

- **事实**：Task 4 的复验者对 `src/ui/local-consent.ts` **就地**注入变异，约 5 秒窗口内 Task 5 修复轮 3 重写了同一文件，并把当时磁盘上的**注入文本**读进去存了下来 ⇒ 一句假承诺（`'在你允许之前，磁盘上不会有任何写入。'`）被**固化进授权弹窗的 `body[0]`**。复验者因为"写回前哈希复核、发现不一致就**拒绝写回**"才没覆盖对方的成果。
- **代价**：如果没有那道"写回前复核"，两边都会丢工作；而**假承诺**会进真实产物 —— 那是对玩家的不实陈述。
- **硬性协议**：**禁止在共享工作树里做就地变异（in-place mutation）；所有变异一律在隔离镜像里跑**。做法：用 `execFileSync('git',['show','HEAD:<path>'])` 逐字节取纯净文件建树（`.superpowers/<dir>/mirror/`），在**镜像**上注入/还原；**共享工作树只许读**。附带教训：**提交要早** —— "已评审通过但未提交"的成果在工作树里是**可被静默改写**的（`148fae3` 那次能取回原文，正是因为它提交了）。
- **本任务的执行**：`.superpowers/g3-t9/mutate.mjs` 全程在 `.superpowers/g3-t9/mirror/` 里注入，并在开工时自证"镜像 == `git show HEAD:<path>`"（§8.2）。

### 5.3 教训三：**"变异其实没生效"已发生六次**

- **事实（六次明细，来自 `docs/3代特效-进度与上下文.md §0` 教训⑦）**：① PowerShell 吃掉引号；② 给本来没有 `args` 的 action 置 `undefined`（空操作）；③ harness 锚点多了一个逗号；④ 多 edit 变异每条都从快照重读、只写最后一条；⑤ 评审者把锚点缩进写成 4 空格而实际是 2 空格；⑥ **`if (false)` 包住原件**（同时满足"锚点命中 1 次"与"哈希变了"，语义却完全没变）。
- **代价**：每次都产出**方向完全相反**的结论（"判据没牙"或"已修好"），而报告读上去完全正常。
- **硬性协议（三条，缺一不可）**：
  1. 注入后必须**同时**断言「锚点恰好命中 1 次」**且**「注入前后 SHA256 不同」；
  2. ⚠️ **这两条仍不充分**（第 6 次事故同时满足了两条）⇒ 必须**另用独立探针复现"缺陷本身"**，再去看腿是否变红；**复现不出缺陷 ⇒ 变异无效、重写变异**，不许据此判"腿无牙"；
  3. 跑出"全绿"时**同源连跑第二次**再下结论；harness 覆写工作树前要校验「工作树 == 快照」。
- **本任务的执行**：三条都做了，且第 2 条做到了**运行期**级别 —— `document.createElement` 的变异用 `node --experimental-strip-types` 真去 `import` 那个模块并抓到 `ReferenceError: document is not defined`（原始文件则是 `PROBE-IMPORT-OK`）；`Math.random` 的变异把 `Math.random` 换成计数器**真执行**那个表达式（调用次数 1；原始文件 0）。§8.2 有逐条输出。

### 5.4 教训四（本任务新增）：**计划给的守卫骨架也要变异实测**
